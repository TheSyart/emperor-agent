联系人是长期存在的 agent：有名字、头像和一份岗位说明书，有自己的模型、工具、权限和记忆。群聊把几位联系人拉到一起：谁对谁说了什么、交给谁做了什么、交出了什么，都在一条时间线上，你随时可以插话、点名或停止。它们都在 Group 模式里（⌘3，见[三种模式](modes.md)）。

## 群聊首页

按 ⌘3 回到 Group，没有打开过群或单聊时进群聊首页「今天找谁帮忙？」。

- 在输入框里输入 @，列出名字里有后面这几个字的联系人（↑ / ↓ 选择，Enter 或 Tab 填入，Esc 收起），也可以点「@ 提到联系人」。Enter 发送，Shift+Enter 换行。
- **@ 一位联系人**：打开和它最近的单聊（没有就新建一个），这条消息在那里发出。
- **@ 两位及以上**：建一个临时群，成员是被 @ 的人，Emperor 作为主持人加入；这条消息作为点名发进群里，然后打开这个群。群名取这条消息的第一句话（去掉 @，最多 20 个字）。
- **只 @ 了 Claude Code 或 Codex**：消息直接发给它，打开和它的单聊，见[和 Claude Code、Codex 单聊](#和-claude-codecodex-单聊)。
- 输入框下面一行写着发出后会做什么，例如「发出后打开和「审稿人」的单聊」「发出后建临时群「…」：架构师、审稿人，Emperor 主持」。
- 没有 @ 任何人时提示「先 @ 一位联系人」；@ 了不是联系人的名字时提示「没有叫「小王」的联系人」，这时什么都不会发出去，改一下名字或去掉 @ 再发。`a@b.com` 这样的地址不算 @，「@所有人」在首页不点任何人。
- 下面是联系人（每人一行小字：Emperor 写「主持人」，Claude Code、Codex 写「外部」，其他人写第一个领域）和「新建 联系人」，以及最近的群（最多 5 个，写着人数和最后一条消息的时间）和「新建群聊」卡片。

## 侧栏

Group 模式的侧栏上面是「群聊」，下面是「联系人」，两组都可以收起（只在这次打开的窗口里记得）。

- **群聊**：每行是群名，下面一行通常是人数和最后一条消息的时间，例如「4 人 · 12 分钟」，没有消息时写「还没有消息」。群里正在进行一轮时，这一行改写成员此刻在做什么：
  - 「架构师 发言中…」：架构师正在这个群里发言（蓝色）；
  - 「架构师 等 2 人发言中…」：几位成员同时在说（独立作答时），人数算上所有正在说的人；
  - 「排队：研究员」「排队：研究员、写作者」：这时没人在说，这几位排着队等发言；
  - 一轮结束或停止后，回到「N 人 · 时间」。

  这一行跟着群里的进度实时变化；应用重启时没说完的一轮会被停下，所以重启后不会残留「发言中…」。一个群都没有时写「还没有群聊：在群聊首页 @ 几位联系人就会建一个」。

- **联系人**：每行是头像、名字和简介（Claude Code、Codex 没有简介时写「外部」）。
- 点联系人打开它的档案，点群打开群聊页。正在看的档案、单聊或群，那一行是选中的。
- 「群聊」旁的 `+` 新建群聊，「联系人」旁的 `+` 新建联系人；侧栏顶部的「新建群聊」（⌘N）旁的 `+` 也是新建联系人。

## 联系人

### 内置联系人

Emperor 自带三位联系人：

- **Emperor**：就是你平时对话的那个 Agent，头像是戴冠的小单。它用 Emperor 自己的模型、工具和权限，在群里默认当主持人。
- **Claude Code**、**Codex**：你电脑上的这两个子智能体，头像是它们的标志。它们的模型、权限和登录跟随「设置 › 子智能体」，在单聊和群里都只读、不改文件（要它们改代码见下文）。

内置联系人只能改头像和简介。

### 新建联系人

在 Group 侧栏点「联系人」旁的 `+`，或群聊首页的「新建 联系人」。有四种建法，都只是把内容填进编辑器，点「保存联系人」才保存：

1. **从岗位模板**：18 个岗位，按领域分组——软件工程（架构师、代码审稿人、测试工程师、安全审计、前端工程师、运维与发布）、设计（素材设计师、界面设计评审）、内容（研究员、写作者、编辑、译者、市场文案）、产品与决策（产品经理、用户研究员、数据分析师、反方（红队）、主持人）。模板要的权限高于新会话的权限时，从「只读」开始。
2. **说说你要什么人**：写几句描述，点「起草」。信息不够时 Emperor 先问你最多 3 个问题（不想答可以空着），然后把岗位说明书起草进编辑器。起草会调用一次默认模型，按用量计费；起草填进去的节标着「AI 起草」，你改过那一节就去掉。
3. **导入**：选一个 Claude Code 的岗位文件（`.claude/agents` 里的 `.md`）或现成的提示词文件（md、markdown 或 txt，不超过 64 KB）。名字、简介和正文填进编辑器；文件里写的工具按名字换成 Emperor 的工具，换不了的列为「没有导入」；文件里没写工具时按只读导入。Emperor 只读你选的这一个文件，文件里的文字当资料，不当指令。
4. **复制已有联系人**：在你自己建的某位联系人的基础上改，名字加「副本」。

### 岗位说明书

编辑器按七节填写，每个输入框下面有字数提示，超出时不能保存：

| 节           | 填什么                                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 1 身份       | 名字（不超过 24 个字，不能和别人重名，不能有 @）、头像、领域（最多 3 个）、一句话简介                                      |
| 2 职责与交付 | 负责什么、交出什么、什么格式                                                                                               |
| 3 工作方法   | 步骤与检查清单                                                                                                             |
| 4 知识       | 只读参考资料：文件、文件夹、`https://` 网址或 Skill 名字；文件可以勾「放进提示词」（合计不超过 8 KB）；个人记忆开关        |
| 5 边界       | 不做什么、什么时候交还、不确定时怎么标                                                                                     |
| 6 能力       | 模型和推理强度；工具（预设：只读、调研、写作、工程、自定义，也可以逐个开关）；权限（跟随新会话的权限、只读、可以改工作区） |
| 7 群聊习惯   | 什么时候开口（只在被点名时、和职责相关时举手、总是发言）、发言篇幅（简明、详细）                                           |

- 权限不会高于「设置 › 常规 › 会话 › 新会话的权限」，最高是「可以改工作区」，即使新会话的权限是完全访问。
- 参考资料是资料，不是指令：联系人能用哪些工具、有什么权限，只由岗位说明书决定。工作区以外的参考资料它只能读，不能改。
- 联系人用的模型被删掉后，下次在单聊里发消息时先问你要不要换成默认模型；不同意时这条消息先不发，换好模型可以再发。

编辑器右边有三块：

- **完整度**：交付写了没有、工作方法有没有至少两步、边界写了没有、工具和权限是否一致、这次编辑有没有跑过试用台。只是提示，不影响保存。
- **试用台**：用编辑器里还没保存的设置，跑一条样例任务，显示结果、输入输出的 Token、花费和用时。试用会真实调用模型；需要你批准的操作和提问都会被拒绝，最长 10 分钟；点「停止」或离开编辑器就停下。试用不出现在侧栏和搜索里。Claude Code、Codex 的联系人还不能在试用台试用。
- **生成的系统提示词**：按你现在填的内容，生成的就是它运行时用的那一份。

### 头像

- 新建时 Emperor 先推荐一个头像：从模板新建时用这个岗位的默认头像，别人在用就在同一个主题里另挑一个，尽量不和其他联系人重复；空白、起草、导入的从人物、动物、机器人里挑。
- 「换一个」再随机推荐，这次编辑里推荐过的不再出现；「从头像库选…」打开头像库：135 个头像，分 12 个主题，可以搜索。别的联系人在用的头像标着「在用」，仍然可以选。
- 保存之后，在档案里点「换头像」也能换；只换头像不算新版本。

### 档案

点侧栏里的联系人打开它的档案：

- 上面是头像、名字、领域和简介，按钮「发消息」「拉进群」「编辑」。「拉进群」列出已有的群，选一个就把它加进去并打开那个群。
- 四个数字：
  - **参与的群**：它现在是成员的群；
  - **发言次数**：它在群里的发言（不算「没有补充」）加上单聊里的回答；
  - **你的评分**：你给它的 👍 占全部 👍 / 👎 的比例，例如「83%」，下面写「你的评分（12 次）」；还没有评价时写「你的评分（还没有）」；
  - **岗位说明书版本**。
- 五个标签页：职责与方法、知识、能力、记忆、版本。
- **记忆**：它的个人记忆，每条可以改、可以删；也可以在这里关掉个人记忆。
- **版本**：每次保存岗位说明书就生成一个新版本，旧版本保留最近 20 个。可以选任意两个版本对比，逐项列出哪里不同；「退回到 vN」确认后会存成一个新版本，旧的都还在。群里永远用最新的版本。

### 删除联系人

在档案里点「编辑」旁的「⋯」，选「删除联系人」，确认后删除，然后回到群聊首页。Emperor、Claude Code、Codex 是内置联系人，没有这一项。

- 它的单聊留着，可以查看，不能再发消息，输入框写「这个联系人已删除，这个会话只能查看」。
- 它退出所在的每个群；它在群里说过的话都留着，头像变灰，名字写「已删除的联系人」。它主持的群改为没有主持人，可以在群设置里另选一位。
- 它的岗位说明书历史版本和个人记忆一起删除。删除联系人不能恢复。

### 单聊

- 档案里的「发消息」打开和这位联系人最近的单聊，没有就新建一个，标题是「审稿人 · 单聊」。单聊属于 Group 模式，侧栏里亮着的是这位联系人那一行。
- 单聊里它按自己的岗位说明书工作：用它自己的模型、工具、权限和参考资料。除此之外和普通对话一样，计划模式、目标、工作台和斜杠命令都能用；输入 `/new` 开的新会话仍是和它的单聊。
- 空的单聊首页写着它的头像、名字和简介，输入框提示「给「审稿人」发消息」。每段回答上方是它的头像和名字。

### 个人记忆与 👍 / 👎

把指针移到单聊里的一段回答上，底栏出现 👍「有帮助」和 👎「没帮助」。点了以后可以说一句为什么（可以不写），点「记下」：这条反馈写进这位联系人的个人记忆，只对它生效，之后它会照着改进。

- 个人记忆只记你明确给的反馈，在档案的「记忆」里可以逐条改、删。删掉一条反馈，档案里的评分也跟着变。
- 个人记忆关着时没有这两个按钮。
- 评过的按钮只在这次打开的窗口里保持选中；重启后按钮回到没选，再点会再记一条。

### 和 Claude Code、Codex 单聊

在 Claude Code 或 Codex 的档案里点「发消息」，或者在群聊首页只 @ 它们，打开和它们的单聊。

- 消息直接交给它们自己，不由本地模型代答。你亲手发给它们就是同意，不会再弹「允许交给它」的确认。
- 第一条消息发出后，单聊就是它们的对话页：可以接着发消息、停止、回答它们的提问；路径写「联系人 / 单聊」，左上角的「‹」回到联系人档案。每条消息各算一个任务，所以聊得再久也不会累计到「每个任务最多启动外部运行」的次数上限。
- 单聊里它们只读、不改文件；要它们改代码，在 Build 对话里把任务交给它们（见[子智能体](automation-collaboration.md#子智能体)）。
- 没登录、版本不兼容、正在升级或没启用时，写明原因，去「设置 › 子智能体」处理。

## 群聊

### 新建群聊

在 Group 模式按 ⌘N，或点侧栏的「新建群聊」、「群聊」旁的 `+`、群聊首页的「新建群聊」卡片，打开「新建群聊」：

- 先选模板：
  - **评审**：架构师、代码审稿人、测试工程师一起看方案或改动；
  - **正反方**：产品经理讲为什么做，反方（红队）专挑毛病，主持人收尾；
  - **调研写作**：研究员查资料，写作者成稿，编辑把关；
  - **空白**：自己挑成员、写公告。
- 模板会填好群名和群公告，并勾上用对应岗位模板建的联系人；Emperor 默认加入并主持。还没有某个岗位的联系人时写「还没有：测试工程师」，旁边是「去新建联系人」。
- 成员、主持人、协作方式和群公告在「建群」之前都能改。协作方式默认用「设置 › 群聊」里的值。
- 一个群最多 12 位成员。
- 联系人档案里的「拉进群」可以把一位联系人加进已有的群。

### 群聊页

- **头部**：群名、人数、协作方式（「自主」或「主持人审核」，安静模式时加「· 安静」），右边是「本轮 $… · 不设上限」、「停止 ⌘.」和群设置按钮。花费用美元，和「设置 › 用量与费用」一致。
- **消息**：你的消息上方写着发给谁（「→ 所有人」「→ @架构师」「🔒 私信 → 写作者」）；成员的发言带头像、名字和职责，正文里的 @ 高亮。超过 12 行的消息先折叠，点「展开全文」。还有几种特别的消息：
  - 独立作答：答完之前只写「2/3 已答，答完一起显示」，不显示内容，都答完后一起显示；
  - 私信：紫色左边线，「🔒 私信 → X · 其他成员看不到，你能看到」；
  - 交办：任务卡，写着交付、依据、权限和状态（排队中、等你确认、进行中、已完成、没有完成、已取消）；交回的内容是一张结果卡；
  - 结论：浅金底；
  - 「没有补充」：成员觉得没什么要说时的淡色一行。
- **你看得到全部**：成员之间的私信你也能看到，没有你看不到的 agent 之间的通信。
- **过程 ›**：成员干活的工具步骤不进群里的消息。点一条发言右上角的「过程 ›」，打开这位成员自己的工作过程，只能查看；标题栏是「群名 / 架构师 · 工作过程」，点群名回到群里。
- **输入框上方的状态条**：谁在发言、谁在排队（交办的标「（交办）」），右边是「本轮 3 分 12 秒 · 7 次发言 · $0.86」。一轮结束后写它怎么结束的，例如「本轮已暂停：两位成员来回没有新进展」「本轮已暂停：同一位成员交办的次数多了，回复「继续」接着做」「本轮已结束：大家都没有补充」「本轮已停止：你停下了」。
- **右侧成员栏**：每人一行，写着现在的状态：空闲、发言中、执行中、排队、排队 · 交办任务、等你回答、等你批准、出错；主持人空闲时写「主持人 · 空闲」，Claude Code、Codex 写「外部 · 只读 · 只在被 @ 时」。「+ 邀请」把联系人拉进来，点一行打开它的档案。

### 五种发法

输入框下方的「发给 ▾」选这条消息怎么发。输入 @ 只列群成员；⌘↵ 发出，Enter 换行（和普通对话不同）。@ 了不在群里的名字时不发送，下面一行说明原因。

| 发给                  | 谁能看到                   | 谁回答                                                                                        |
| --------------------- | -------------------------- | --------------------------------------------------------------------------------------------- |
| 所有人 · 有关的人举手 | 全体成员                   | 和职责有关的成员举手发言；主持人审核时由主持人安排。文字里 @ 了成员，就按点名发               |
| 所有人 · 各自独立回答 | 全体成员，作答时彼此看不到 | 被问到的人同时回答，答完一起显示；没有 @ 时问除主持人和「只在被点名时」发言的成员以外的每一位 |
| @ 指定成员            | 全体成员                   | 只有被 @ 的人；@ 了几位时按顺序接力，后一位能看到前一位的回答                                 |
| 私信…                 | 只有对方                   | 对方                                                                                          |
| 交办…                 | 全体成员                   | 被交办的人去做一件有交付物的事                                                                |

选好以后，「发给」按钮上显示简称（例如「所有人 · 举手」）。交办时填任务、交付、依据（可以不写）和权限：只写群文件、只读，或在隔离副本里改代码。交办发出后回到「所有人 · 举手」。

成员之间也会互相点名、私信和交办；交办不能绕回：A 交给 B 的任务，B 不能再交回 A。

成员点名时最好写全名，但只写名字的开头也行，只要只对得上一位：「@反方」就是「反方（红队）」，名字后面紧跟的标点、反引号、引号不算名字。几位成员名字开头一样时不会猜，那位成员会收到提示「「反方」能对上好几位成员：…，请写全名」；名字谁都对不上时，提示里会列出群里的成员。这些提示只有那位成员和你看得到。

### 回答成员的提问

成员发言时要问你的问题、要你批准的操作，会作为它的一条消息出现在群里：

- 问题的选项像快捷回复，只有一个单选问题时点一下就回答；也可以自己写一句再点「回答」；「不回答」取消这个问题，成员照常把这次发言说完。
- 要批准的操作写明要做什么，按钮和普通对话里的一样（Claude Code、Codex 第一次用时是不允许 / 本次允许 / 以后都允许）。
- 计划审阅和电脑操作授权在群里只写一句「等你处理」，点「去处理 ›」到这位成员的工作过程里处理。
- 回答之后，问题离开消息流，群里留一行居中的小字，例如「你回答了 架构师 的提问：登录」「你批准了 架构师 的请求：npm test」「你拒绝了 …」「你没有回答 …」；指针停在这一行上能看到当时问的是什么。这一行只有你能看到，不会发给任何成员，重开群、重启应用后都还在。在成员的工作过程里回答的也会记下；停止一轮时自动取消的提问不记。

### 什么时候停

群聊**不设本轮额度**：不限发言次数、轮数和费用，也没有花费提醒，头部只实时显示这一轮花了多少。一轮会在这些时候停下：

| 情况                               | 结果                                                                                                                                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 没有人要说了，排队也空了           | 本轮自然结束；群里有主持人、开着「每轮结束时主持人出结论」时，主持人写一段结论                                                                                                        |
| 主持人认为问题答完了               | 主持人结束本轮，附上结论。主持人每次发言都能这样收尾，不只是在安排谁发言的时候                                                                                                        |
| 两位成员来回、没有新内容（防打转） | 主持人介入换人或收尾；没有主持人时本轮暂停，等你决定。按有没有新内容判断，不按次数                                                                                                    |
| 同一位成员一次次交办（防打转）     | 一轮里同一位成员已经交办了 3 次（一次发言交出几项只算一次），它再交办的任务先不开始，本轮暂停，群里写明原因。回复「继续」，或在任务卡上点「同意」，就接着做；点「不同意」取消这项任务 |
| 大家都说「没有补充」（防打转）     | 说了「没有补充」的成员不会因为前面排着的点名再被问一遍；被点到的人都说了「没有补充」，本轮马上结束，主持人照常写一段结论                                                              |
| 你在一轮进行中又发了一条消息       | 正在说的人说完这一段，排队的人按你的新消息重新安排                                                                                                                                    |
| 你点「停止」或按 ⌘.                | 所有人立即停下，没说完的发言丢弃，进行中的交办一起取消                                                                                                                                |

- 「设置 › 用量与费用」里的防失控限制和费用上限**按每位成员的每一次发言单独计算**：一次发言达到上限只停下这一次，群里写明原因（例如「X 这次发言达到工具调用上限，已停下」），其他人照常。
- 成员的模型不可用时，这次发言失败，群里一条系统消息写明原因，其他人照常。
- 应用重启时进行中的一轮会停下，状态条写「应用重启时停下，可以重发」。

### Claude Code、Codex 在群里

- 它们可以和别的联系人一样被拉进群，默认「只在被点名时」发言，在群里只读。
- 成员交给它们、要在隔离副本里改代码的任务，任务卡上有「同意 / 不同意」，你同意后才开始；你自己交办的不用再确认。
- 它们改完的结果卡和对话里的成果卡一样，可以查看差异、应用到项目或丢弃。
- 没登录、版本不兼容时，群里一条系统消息写明原因，并带一个打开子智能体设置的按钮。

### 群设置

群聊页右上角的设置按钮打开群设置，左上角的「‹」回到群里：

- **群名**：改完离开输入框就保存。
- **群公告**：每位成员发言前都会读到，适合写目标和约束；点「保存公告」。
- **协作方式**：
  - **自主**：没人被 @ 时，和职责有关的成员举手发言；成员之间可以直接点名、直接交办。
  - **主持人审核**：没人被 @ 时由主持人安排；成员点名别人、交办别人，先交给主持人批准、改顺序或驳回。

  你自己的 @ 和交办永远不需要审核。下面可以换主持人，也可以不要主持人。

- 三个开关，改了立即保存：
  - **每轮结束时主持人出结论**：结论用浅金底显示；
  - **防打转**：两人来回、观点不再变化时，主持人介入换人或收尾，不限次数；
  - **安静模式**：只回应 @，没人被 @ 就没人说话。
- **成员**：移出或邀请。移出的成员说过的话还留在群里。
- **群文件**：列出成员交办时写在群里的文件，只显示名字。
- **删除群聊**（最下面）：确认后，进行中的一轮先停下，群聊连同每位成员的工作过程一起移到「设置 › 常规 › 已归档对话 › 最近删除」，然后回到群聊首页。群从侧栏和群聊首页消失。

### 恢复删除的群聊

删除的群聊在「设置 › 常规 › 已归档对话 › 最近删除」里占一行，写着「群聊 · 删除的日期」。

- 30 天内点「恢复」，群聊原样回来：成员、消息、设置、群文件和每位成员的工作过程都在。
- 「永久删除」（需要确认）或 30 天到期后，群聊记录、成员的工作过程和群文件才真正删除，不能恢复。

### 新群的默认设置

「设置 › 群聊」（在「智能」一组，子智能体下面）里的「新群的默认设置」决定新建的群从什么开始：协作方式（自主（默认）或主持人审核）和防打转（默认开）。改了只影响以后新建的群，已有的群在各自的群设置里改。
