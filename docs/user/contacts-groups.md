联系人是长期存在的 agent：有名字、头像和一份岗位说明书，有自己的模型、工具、权限和记忆。群聊把几位联系人拉到一起：谁对谁说了什么、交给谁做了什么、交出了什么，都在一条时间线上，你随时可以插话、点名或停止。它们都在 Group 模式里（⌘3，见[三种模式](modes.md)）。

## 群聊首页

按 ⌘3 回到 Group，没有打开过群或单聊时进群聊首页「今天找谁帮忙？」。

- 在输入框里输入 @，列出名字里有后面这几个字的联系人（↑ / ↓ 选择，Enter 或 Tab 填入，Esc 收起），也可以点「@ 提到联系人」。Enter 发送，Shift+Enter 换行。
- **@ 一位联系人**：打开和它最近的单聊（没有就新建一个），这条消息在那里发出。
- **@ 两位及以上**：建一个临时群，成员就是被 @ 的人；这条消息作为点名发进群里，然后打开这个群。群名取这条消息的第一句话（去掉 @，最多 20 个字）。Core 会自动补入固定的 Emperor，由它呈现内置协调，不需要你设置主持人。
- **只 @ 了 Claude Code 或 Codex**：消息直接发给它，打开和它的单聊，见[和 Claude Code、Codex 单聊](#和-claude-codecodex-单聊)。
- 输入框下面一行写着发出后会做什么，例如「发出后打开和「审稿人」的单聊」「发出后建临时群「…」：架构师、审稿人，由群聊内置协调」。
- 没有 @ 任何人时提示「先 @ 一位联系人」；@ 了不是联系人的名字时提示「没有叫「小王」的联系人」，这时什么都不会发出去，改一下名字或去掉 @ 再发。`a@b.com` 这样的地址不算 @，「@所有人」在首页不点任何人。
- 下面是联系人（每人一行小字：Emperor 写「通才」，Claude Code、Codex 写「外部」，其他人写第一个领域）和「新建 联系人」，以及最近的群（最多 5 个，写着人数和最后一条消息的时间）和「新建群聊」卡片。

## 侧栏

Group 模式的侧栏只有「群聊」一组；联系人在主区域的联系人页里（底栏明暗切换左边的「联系人」图标）。

- **群聊**：每行是群名，下面一行通常是人数和最后一条消息的时间，例如「4 人 · 12 分钟」，没有消息时写「还没有消息」。群里正在进行一轮时，这一行改写成员此刻在做什么：
  - 「架构师 发言中…」：架构师正在这个群里发言（蓝色）；
  - 「架构师 等 2 人发言中…」：几位成员同时在说（独立作答时），人数算上所有正在说的人；
  - 「排队：研究员」「排队：研究员、写作者」：这时没人在说，这几位排着队等发言；
  - 一轮结束或停止后，回到「N 人 · 时间」。

  这一行跟着群里的进度实时变化；应用重启时没说完的一轮会被停下，所以重启后不会残留「发言中…」。一个群都没有时写「还没有群聊：在群聊首页 @ 几位联系人就会建一个」。

- 点群打开群聊页；正在看的群那一行是选中的。
- 「群聊」旁的 `+` 新建群聊；侧栏顶部的「新建群聊」（⌘N）旁的 `+` 新建联系人。
- 联系人页：点底栏的联系人图标，主区域打开「联系人」（像「能力」页一样）。标题下按联系人的领域分页签（全部、产品、工程、内容、数据、决策、外部、其他），每个带数量；没有领域的联系人进「其他」，没有联系人的分类不显示。下面是平铺的联系人卡片，点一张进入档案，左上「‹ 所有联系人」回到原来的分类。侧栏仍然在，点侧栏里的群或再点图标就回到会话。

## 联系人

### 内置联系人

普通联系人列表里有三位内置联系人：

- **Emperor**：就是你平时对话的那个 Agent，头像是戴冠的小单。它用 Emperor 自己的模型、工具和权限；每个群默认都有且只有一位 Emperor，作为固定可见成员负责简短安排、提问和收尾，不需要也不能移除。
- **Claude Code**、**Codex**：你电脑上的这两个子智能体，头像是它们的标志。它们的模型、权限和登录跟随「设置 › 子智能体」，在单聊和群里都只读、不改文件（要它们改代码见下文）。

内置联系人只能改头像和简介。另有固定的「角色创建师」系统联系人，用于对话式创建和调整联系人；它不进普通专业工作群，也不是群协调器。

### 新建联系人

日常创建和调整都通过固定的「角色创建师」对话完成，不需要逐项填写七段表单：

1. 点联系人页右上角的「新建联系人」、侧栏「新建群聊」旁的 `+`，或群聊首页的「新建 联系人」，会打开角色创建师会话。
2. 直接说要什么岗位、负责什么、怎样交付。信息不足时创建师会追问；也可以从岗位模板、已有提示词文件或已有联系人复制开始。
3. 创建师把结果整理为岗位草稿。草稿里仍使用身份、职责与交付、工作方法、知识、边界、能力和群聊习惯这七节数据契约，可以查看生成的系统提示词并试用。
4. **只有你点确认保存后**，联系人才会真正创建或更新。取消不会落盘；编辑只修改你指定的联系人，不会顺带新建另一位。
5. 保存后可以马上发消息或拉进群。创建师不会自行扩大 Skill、MCP、工作区或外部执行权限；模型草稿也不能直接写入联系人数据。

高级七节编辑器保留为内部回退，不再出现在日常入口。下面仍按七节说明这份岗位数据，便于理解草稿和权限。

### 岗位说明书

岗位草稿和高级回退编辑器都按七节保存；超出各节限制时不能保存：

| 节           | 填什么                                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 1 身份       | 名字（不超过 24 个字，不能和别人重名，不能有 @）、头像、领域（最多 3 个）、一句话简介                                      |
| 2 职责与交付 | 负责什么、交出什么、什么格式                                                                                               |
| 3 工作方法   | 步骤与检查清单                                                                                                             |
| 4 知识       | 只读参考资料：文件、文件夹、`https://` 网址或 Skill 名字；文件可以勾「放进提示词」（合计不超过 8 KB）；个人记忆开关        |
| 5 边界       | 不做什么、什么时候交还、不确定时怎么标                                                                                     |
| 6 能力       | 模型和推理强度；工具（预设：只读、调研、写作、工程、自定义，也可以逐个开关）；权限（跟随新会话的权限、只读、可以改工作区） |
| 7 群聊习惯   | 什么时候开口（只在被点名时、和职责相关时举手、总是发言）、发言篇幅（简明、详细）                                           |

- 权限不会高于「设置 › 常规 › 会话 › 新会话的权限」，最高是「可以改工作区」，即使新会话的权限是完全访问。
- 参考资料是资料，不是指令：联系人能用哪些工具、有什么权限，只由岗位说明书决定。工作区以外的参考资料它只能读，不能改。
- 联系人用的模型被删掉后，下次在单聊里发消息时先问你要不要换成默认模型；不同意时这条消息先不发，换好模型可以再发。

角色草稿和高级回退编辑器提供三块核对能力：

- **完整度**：交付写了没有、工作方法有没有至少两步、边界写了没有、工具和权限是否一致、这次编辑有没有跑过试用台。只是提示，不影响保存。
- **试用台**：用编辑器里还没保存的设置，跑一条样例任务，显示结果、输入输出的 Token、花费和用时。试用会真实调用模型；需要你批准的操作和提问都会被拒绝，最长 10 分钟；点「停止」或离开编辑器就停下。试用不出现在侧栏和搜索里。Claude Code、Codex 的联系人还不能在试用台试用。
- **生成的系统提示词**：按你现在填的内容，生成的就是它运行时用的那一份。

### 头像

- 新建时 Emperor 先推荐一个头像：从模板新建时用这个岗位的默认头像，别人在用就在同一个主题里另挑一个，尽量不和其他联系人重复；空白、起草、导入的从人物、动物、机器人里挑。
- 「换一个」再随机推荐，这次编辑里推荐过的不再出现；「从头像库选…」打开头像库：135 个头像，分 12 个主题，可以搜索。别的联系人在用的头像标着「在用」，仍然可以选。
- 保存之后，在档案里点「换头像」也能换；只换头像不算新版本。

### 档案

点底栏的联系人图标，在联系人页点一张卡片，就是它的档案：

- 上面是头像、名字、领域和简介，按钮「发消息」「拉进群」「编辑」。「拉进群」列出已有的群，选一个就把它加进去并打开那个群。
- 四个数字：
  - **参与的群**：它现在是成员的群；
  - **发言次数**：它在群里的发言（不算「没有补充」）加上单聊里的回答；
  - **你的评分**：你给它的 👍 占全部 👍 / 👎 的比例，例如「83%」，下面写「你的评分（12 次）」；还没有评价时写「你的评分（还没有）」；
  - **岗位说明书版本**。
- 五个标签页：职责与方法、知识、能力、记忆、版本。
- **知识**：文件、文件夹、网址和笔记。标了「常驻上下文」的会放进每一次提示词，其余按需读取；常驻资料合计不超过 8 KB。在「编辑」里加。
- **能力**：Skill 从安装里可用的目录选，MCP 选到具体工具；每一项都标「可用 / 缺什么、没连上」。Claude Code、Codex 这类外部智能体在 Emperor 里暂不支持绑定 Skill 或 MCP。
- **记忆**：它自己的工作经验和你在单聊里给的 👍 / 👎。工作经验分有效、待验证、已停用、已删除；待验证的不会参与回答。每条可以改、停用、删除、恢复；旧反馈没有可追溯来源时列在「历史反馈（待确认）」，不会自动使用。
- **版本**：每次保存岗位说明书就生成一个新版本，旧版本保留最近 20 个。可以选任意两个版本对比，逐项列出哪里不同；「退回到 vN」确认后会存成一个新版本，旧的都还在。群里永远用最新的版本。

### 删除联系人

在档案里点「编辑」旁的「⋯」，选「删除联系人」，确认后删除，然后回到联系人页。Emperor、Claude Code、Codex 是内置联系人，没有这一项。

- 它的单聊留着，可以查看，不能再发消息，输入框写「这个联系人已删除，这个会话只能查看」。
- 它退出所在的每个群；它在群里说过的话都留着，头像变灰，名字写「已删除的联系人」。群的内置协调不受联系人删除影响。
- 它的岗位说明书历史版本和个人记忆一起删除。删除联系人不能恢复。

### 单聊

- 档案里的「发消息」打开和这位联系人最近的单聊，没有就新建一个，标题是「审稿人 · 单聊」。单聊属于 Group 模式；联系人页里能看到它所在的分类和卡片。
- 单聊里它按自己的岗位说明书工作：用它自己的模型、工具、权限、知识和能力（选中的 Skill / MCP）。除此之外和普通对话一样，计划模式、目标、工作台和斜杠命令都能用；输入 `/new` 开的新会话仍是和它的单聊。
- 空的单聊首页写着它的头像、名字和简介，输入框提示「给「审稿人」发消息」。每段回答上方是它的头像和名字。

### 工作经验与 👍 / 👎

一项工作结束后，如果宿主核对到工具结果、你的确认或纠正，Emperor 会后台用一次小模型把这次工作整理成最多 5 条经验（费用记在「用量与费用」）。有依据的自动生效，没依据的进「待验证」，不参与以后的回答。你也可以在单聊里给一段回答点 👍 / 👎 并写一句为什么，这条反馈也会记进它的记忆。

- 这些记录只在它自己的工作里用，不会读主对话的长期记忆；在档案的「记忆」里可以逐条改、删、停用或恢复。删掉一条反馈，档案里的评分也跟着变。
- 记忆关着时不再整理新经验、也不再召回已有的；已有条目仍可管理。
- 评过的按钮只在这次打开的窗口里保持选中；重启后按钮回到没选，再点会再记一条。

### 和 Claude Code、Codex 单聊

在 Claude Code 或 Codex 的档案里点「发消息」，或者在群聊首页只 @ 它们，打开和它们的单聊。

- 消息直接交给它们自己，不由本地模型代答。你亲手发给它们就是同意，不会再弹「允许交给它」的确认。
- 第一条消息发出后，单聊就是它们的对话页：可以接着发消息、停止、回答它们的提问；路径写「联系人 / 单聊」，左上角的「‹」回到联系人档案。每条消息各算一个任务，所以聊得再久也不会累计到「每个任务最多启动外部运行」的次数上限；「设置 › 用量与费用」的费用上限也只管单条消息，整段单聊的总花费不设上限。Emperor 重启后可以接着聊。
- 单聊里它们只读、不改文件；要它们改代码，在 Build 对话里把任务交给它们（见[子智能体](automation-collaboration.md#子智能体)）。
- 发不出去时写明原因和该怎么做：没登录、版本不兼容、正在升级或没启用，去「设置 › 子智能体」处理；它还在停下上一条、排队的消息太多，等一会儿再发；上次运行没有正常结束，在对话页点「标记为已结束」再发。一条消息最多 32 KB（大约一万个汉字）。
- 再次打开已经聊过的单聊，直接到它的对话页。没发出的字留在各自的单聊里，不会带到别的单聊。

## 群聊

### 新建群聊

在 Group 模式按 ⌘N，或点侧栏的「新建群聊」、「群聊」旁的 `+`、群聊首页的「新建群聊」卡片，打开「新建群聊」。新建只有三部分：**群名称 → 成员 → 可选群公告**，没有协作方式、项目或 Git 配置。

- 可选模板：
  - **评审**：架构师、代码审稿人、测试工程师一起看方案或改动；
  - **正反方**：产品经理和反方（红队）给出不同立场，群聊收尾；
  - **调研写作**：研究员查资料，写作者成稿，编辑把关；
  - **空白**：自己挑成员、写公告。
- 成员区先单独显示 Emperor 和「默认内置」，没有复选框；模板会填好群名和群公告，只勾选用对应岗位模板建的其他联系人。建群请求只提交其他成员，Core 自动补上且只保留一位 Emperor。空白群也可以不选其他成员，填写群名后直接建一个只含 Emperor 的群。缺少某个岗位时列出「还没有」，可从「去新建联系人」进入角色创建师。
- 一个群最多 12 位成员，包含固定的 Emperor。联系人档案里的「拉进群」也可以把一位联系人加进已有的群。
- 所有群都按职责自主协作。固定成员 Emperor 呈现内置协调的安排、简短状态和收尾；专业成员自主举手、点名和交办，不需要你选主持人。

### 群聊页

- **头部**：群名、人数、「自主 · 内置协调」，右边是本轮费用、「停止 ⌘.」和群设置。花费用美元，和「设置 › 用量与费用」一致。
- **主区域只显示对话**：采用接近 QQ 群聊的紧凑气泡，成员在左、你在右，32px 头像，连续发言缩小间距。你的交办、成员一次接单、最终交付、讨论和已揭晓的独立答案都是普通消息；Emperor 用一句话说明安排和失败原因，长过程只留在内部。没有任务卡、独立作答卡、公开成果卡或外部执行结果卡。
- **交办与交付**：明确交办被原子接单后，负责成员只说一次「收到，我来做…」；完成后在同一任务链给出简短交付。没有虚构百分比，也不需要你点「确认验收 / 确认完成」。成果具备真实、同 revision 的通过检查后自动完成。
- **文件和图片**：作为交付消息里的内联附件，复用 Chat / Build 的文件类型图标、名称、大小和查看 / 获取方式；图片使用同一个全屏查看器。读取的是群共享区里的公开版本，不是成员的私有源目录。
- **独立作答**：作答期间主区域不提前显示答案；右侧只显示「N/M 已答，答完一起显示」。全部答完后，各答案作为普通成员消息一起出现。
- **私信**：只有对方成员和你能看到；其他成员看不到。私信内容不会自动进入群共享区。
- **流式发言**：本地成员发言时，正文在消息流末尾逐字出现，写完由群日志中的最终消息接上；中间工具步骤不复制进群。独立作答在揭晓前不显示草稿。
- **输入框上方状态条**：显示谁在发言、谁排队、本轮时长、发言次数和费用，以及本轮自然结束、暂停或停止的原因。
- **右侧成员栏**：显示成员状态、任务进度和独立作答进度。点一位成员只切换到 TA **在这个群里的只读执行详情**，可核查真实工具和文件记录；不会打开私人单聊、联系人档案或其他群。再点返回箭头回到任务进度。窄窗口通过顶部成员按钮打开覆盖式抽屉，不会失去详情入口。

### 群工作区与公开成果

每个群都有独立工作区，每位成员都有自己的目录：

```text
群工作区/<groupId>/
  members/<contactId>/   # 仅这位成员读写，其他成员不可读
  shared/                # 全群只读；公开成果由宿主发布
```

成员依据指令决定自己的工作方式，不需要群项目、Git 基线或集成流程。成员不能写别人的私有目录，也不能把共享区当任意写入目录。文件或图片要传给全群时，由宿主校验来源并发布为带内容 revision 的不可变公开成果；同名但内容不同的成果不会互相覆盖。只读本地成员可以直接回复完整报告，由宿主保存到它自己的目录并发布；要求实际写文件而成员没有权限时，会在执行前说明并停止。你可以读取群工作区和公开成果，但私信不会因此公开。

外部 Claude Code / Codex 不能强制遵守这套本地目录边界时，会按只读或串行能力降级，不会只在提示词里声称已经隔离。

### 五种发法

输入框下方的「发给 ▾」选这条消息怎么发。输入 @ 只列群成员，选中的名字在输入框里高亮；**Enter 发出，Shift+Enter 换行**，⌘/Ctrl+Enter 也可以发。输入法组词时按 Enter 不会误发。@ 了不在群里的名字时不发送，下面一行说明原因。

| 发给                  | 谁能看到                   | 谁回答                                                  |
| --------------------- | -------------------------- | ------------------------------------------------------- |
| 所有人 · 有关的人举手 | 全体成员                   | 和职责有关的成员自主举手；文字里 @ 了成员，就按点名发   |
| 所有人 · 各自独立回答 | 全体成员，作答时彼此看不到 | 被问到的人并行回答，全部答完一起显示                    |
| @ 指定成员            | 全体成员                   | 只有被 @ 的人；多人时按顺序接力，后一位能看到前一位回答 |
| 私信…                 | 只有对方和你               | 对方                                                    |
| 交办…                 | 全体成员                   | 被交办的人完成一件有交付物的任务，接单、检查并发布成果  |

交办填写任务、交付和必要依据。常规群任务只需要自己的成员目录和群共享区，不需要配置项目或 Git；既有只读、隔离副本等高级任务兼容选项不会把私有目录变成共享工作区。

成员之间也会互相点名、私信和交办。有效任务由 Core 记录负责人、attempt、依赖、执行权、成果 revision 和检查；界面只是同一份任务事实的投影，不另建第二套进度。重派会撤销旧执行权，旧结果迟到不能覆盖新成果。

成员点名最好写全名，也可以写唯一能对上的名字开头，例如「@反方」可对上「反方（红队）」。名字有歧义或不存在时不会猜，会提示那位成员和你。

### 回答成员的提问与安全审批

成员在发言中问你问题，或请求需要批准的操作时，仍按普通对话的安全边界处理：可以回答、拒绝、不回答，或到该成员的本群执行详情里处理计划授权和电脑操作授权。提问卡固定在触发它的来源发言之后；后续发言不会把它挤到上方。

这些安全提问和权限审批不是人工 Agent 任务操控；0.3 不再提供「确认验收 / 确认完成 / 同意任务 / 不同意任务」这类按钮。回答后群里会留一行只有你能看到的小字，记录你回答了谁的问题；它不会发给其他成员，重开群后仍保留。

### 什么时候停

群聊不设本轮固定发言额度，一轮会在这些时候停下：

| 情况                     | 结果                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------ |
| 没有人要说了，排队也空了 | 本轮自然结束；开启「每轮结束时群聊出结论」时，由群聊内置协调给出结论                 |
| 两位成员来回、没有新内容 | 防打转开启时，内置协调换人或收尾；按有没有新内容判断，不按虚构进度                   |
| 同一位成员连续重复交办   | 防打转会暂停失控链路，群里写明真实原因；不会用另一张任务卡伪造第二套状态             |
| 大家都说「没有补充」     | 被点到的人都表示没有补充后，本轮结束                                                 |
| 你在一轮进行中又发消息   | 当前发言按调度规则收尾，排队的人按新消息重新安排                                     |
| 你点「停止」或按 ⌘.      | 所有成员立即停下，未说完的发言丢弃；后台任务按执行权规则取消，不允许迟到交付继续写入 |

- 「设置 › 用量与费用」里的防失控限制和费用上限按每位成员的每一次发言单独计算；一位成员失败不会让别人伪装成功。
- 应用重启时，进行中的一轮会停下；重启前未完成任务标为未知，不会盲目重派或重跑。
- 停止、重启和旧结果迟到都以 Core 任务日志为准，不只看界面文字。

### Claude Code、Codex 在群里

- 它们可以被拉进群，默认只在被点名时发言，在群里只读。
- **它们的发言仍是一次性出现**，没有本地成员那样的逐字流式草稿；不会伪造增量。
- 它们不接管 Emperor 宿主 Skill / MCP，也没有本地成员目录那样的硬隔离保证；需要目录边界时按只读或串行能力降级。
- 工具和最终答复以普通消息及右侧本群执行详情呈现，不显示旧式外部结果卡，也不提供「应用到项目 / 丢弃」的群任务按钮。
- 没登录、版本不兼容或运行失败时，群里写明原因和下一步，不由本地模型代答。

### 群设置

群聊页右上角的设置按钮打开群设置，左上角「‹」回到群里：

- **群名**：改完保存。
- **群公告**：每位成员发言前都会读到，适合写目标和约束。
- **每轮结束时群聊出结论**：由固定的 Emperor 以普通消息给出结论，不新增另一位主持人。
- **防打转**：两人来回、观点不再变化时，内置协调换人或收尾。
- **安静模式**：只回应 @；没人被 @ 就没人说话。
- **成员**：移出或邀请；移出的成员说过的话仍保留。Emperor 是固定成员，不能移出。
- **群文件**：查看群里的公开成果名称。
- **删除群聊**：确认后，先停止进行中的一轮，再把群聊和成员会话移到「设置 › 常规 › 已归档对话 › 最近删除」。

群设置没有协作方式、主持人、项目或 Git 绑定；新旧群都统一自主协作。旧日志中的主持人字段只用于兼容回放，不会重新变成配置入口。

### 恢复删除的群聊

删除的群聊在「设置 › 常规 › 已归档对话 › 最近删除」里占一行，写着「群聊 · 删除的日期」。30 天内可以恢复；「永久删除」（需要确认）或 30 天到期后，群聊记录、成员会话和群文件才真正删除，不能恢复。

### 新群的默认设置

「设置 › 群聊」（在「智能」一组）只保留新群的**防打转**默认值。它只影响以后新建的群；已有群在自己的群设置里修改。所有群始终自主协作，没有全局协作方式、项目或 Git 选项。
