先进入「设置 › 高级 › 诊断」。页面顶部是一张概览卡：一句结论（一切正常时是「运行正常」，否则是「n 项需要关注」「n 项异常」加「其余都正常」），下面只列需要关注的项目（异常在前），点一项会展开它所在的分组并滚到那里。读取诊断或探测环境失败时，概览上方出现一张提醒卡写明原因。右上角「导出诊断包」生成一个 zip（见下文[日志与诊断包](#日志与诊断包)），「复制报告」把整页复制成纯文本，便于反馈问题；刷新会重新读取诊断并重新探测环境。

概览下方是五个默认折叠的分组，标题下写着项数；只有含需要关注项目的分组，标题旁才显示「n 项需要关注」或「n 项异常」。展开后，正常的项目只显示值（鼠标停在名称上可以看到详情），需要关注的项目用颜色标出，并在名称下写明原因：

- **运行时**：定时任务存储、运行事件、工作区范围、命令沙箱、进程托管、进程隔离回执（最近 20 次启动的 MCP server 与插件 Hook 是已隔离、被拒绝还是经你同意在沙箱外运行，附策略哈希的前 12 位；有被拒绝或在沙箱外运行的就标为需要关注）、子智能体、提示词缓存和运行中任务；Core 没有返回数据的项不显示，标题下注明“另有 n 项未返回数据”；
- **环境工具**：基础工具、当前项目（包括可选的 GitHub CLI `gh`）、Skill 依赖和大型依赖的探测结果，已就绪的工具显示检测到的版本，只读显示，不在应用内安装；
- **桌面**：桌宠与 Node.js 运行时、桌面渲染层、桌宠模块等依赖；
- **存储路径**：运行根目录（通常也是内置技能、模板等只读资源所在的目录，这时只占一行）、Emperor Home、当前项目、会话、附件、模型配置、MCP 配置和日志的位置，每项直接显示路径（Emperor Home、当前项目与日志目录可以在文件管理器中打开），以及旧数据提示；用户主目录显示为 `~`；
- **配置**：模型配置与本地配置的状态、有效配置摘要和斜杠命令目录。

当前会话的上下文解释在「设置 › 记忆」顶部的「上下文概览」中查看。

不要先手工删除 `stateRoot`。

## 日志与诊断包

Emperor 把运行日志写在本机，不上传：

| 文件                                     | 内容                                                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| `~/Library/Logs/Emperor Agent/main.log`  | 主进程：启动与退出、启动失败的完整原因和调用栈、没接住的错误、崩溃的子进程、各模块的提示 |
| `~/Library/Logs/Emperor Agent/core.log`  | Core（会话、模型、MCP、定时任务等）的日志                                                |
| `~/Library/Logs/Emperor Agent/Crashpad/` | 进程崩溃时的转储（minidump），只在本机，不上传                                           |

- 两份日志各写到 5 MB 后轮转为 `main.log.1`、`main.log.2`…，最多保留 5 份；默认记录 info 及以上级别（环境变量 `EMPEROR_LOG_LEVEL=debug` 可以多记一些）。
- 写入前脱敏：`sk-` 开头的密钥写成 `sk-***`，网址里的 `token`、`key`、签名等参数，以及 Authorization、Cookie 头写成 `***`。
- 主进程里没接住的错误只写进日志，应用继续运行，不会弹出错误框或退出。
- 设置了 `EMPEROR_CONFIG_DIR` 时（测试、第二份资料），日志和转储放在那个目录的 `logs/` 下，不写 `~/Library/Logs`。
- 「设置 › 高级 › 诊断 › 存储路径」的「日志」一行可以直接打开这个文件夹。

**启动失败时**，恢复页只显示错误代码和日志位置，完整原因（含调用栈和底层原因）在 `main.log` 里；点「打开日志」查看，或直接导出诊断包。

**导出诊断包**：在「设置 › 高级 › 诊断」右上角，或恢复页上，点「导出诊断包」。Emperor 先整理好内容并列出 zip 里的每个文件、用途和大小，以及不包含的内容；确认后点「导出…」选择保存位置（默认在桌面），导出后可以「在访达中显示」。诊断包包含：

- `diagnostics.json`：诊断页背后的数据（Core `diagnostics.get`）；启动失败、Core 没有运行时写明不可用；
- `app.json`：应用、Electron、Chromium、Node 版本，Electron fuse 状态，电脑操作 Helper、听写 Helper、Chrome 扩展和浏览器连接的状态；
- `model-config.json`：模型配置的结构，所有 Key、令牌和请求头都换成 `[已移除]`；
- `system.json`：macOS 版本、芯片、内存、语言和时区；
- `logs/`：`main.log`、`core.log` 及上一份各自最近 2 MB，再脱敏一次；
- `crashes.json`：崩溃转储的文件名、大小和时间（转储本身含进程内存，不放进诊断包）；
- `README.txt`：以上清单和不包含的内容。

诊断包不包含会话与消息内容、记忆、API Key 等密钥；用户主目录显示为 `~`。

| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 页面白屏或窗口打开后无内容                        | `npm --prefix desktop run build`，再检查 `desktop/out/renderer/index.html`                                                                                                                                                                                                                                                                                           |
| 显示“必须在 Electron 中使用”                      | 当前页面没有 preload Core bridge；完整产品不能在普通浏览器运行                                                                                                                                                                                                                                                                                                       |

| 凭据代填提示 `credential-field-type`              | 目标输入框的类型与要填的字段不符（例如把密码填进普通文本框）；先观察，选对字段后再试                                                                                                                                                                                                                                                                                 |
| 电脑操作提示 `STALE_TARGET` 或 `STALE_ELEMENT`    | 页面导航、窗口变化或扩展重载会使旧目标与元素引用失效；重新列出目标、观察后再操作。原因为 `released-at-task-end` 表示上一个任务结束时已释放：窗口或页面仍在，Agent 重新绑定窗口或选回标签页即可                                                                                                                                                                       |
| Finder 完整观察反复提示 `STALE_TARGET`            | 当前版本已处理 Finder 图像加载引起的重复变更通知。若某个窗口仍持续报错，请重新列窗、绑定一次；仍报同一错误时停止该目标的自动操作，先手动完成并保留会话诊断，不要循环重试或改用坐标点击。                                                                                                                                                                             |
| 桌面 App 仍运行，但 `desktop_list_windows` 返回 0 | macOS 可能没有把其他桌面空间或已最小化的窗口列入当前可访问窗口；这不能证明 App 已退出。把目标窗口恢复到当前桌面后重新列窗；已绑定目标在其他空间截图可能返回 `TARGET_NOT_VISIBLE`                                                                                                                                                                                     |
| 桌面输入提示 `TARGET_NOT_VISIBLE`                 | Helper 已尝试将目标窗口置前，但目标 App、焦点窗口或模态窗口仍不符合绑定目标。`reason=target-app-not-frontmost` 表示目标 App 未在最前；`target-window-not-focused` 表示绑定窗口没有焦点；`frontmost-app-unverified` 表示无法确认当前最前的 App（例如刚启动的应用），为安全起见未派发。检查当前桌面和模态窗口，恢复后重新观察；输入尚未派发，不应盲目重试。            |
| 桌面按键或鼠标动作返回 `observed`，但画面未达预期 | `observed` 只表示派发后检测到目标版本变化；其他界面变化也可能触发。重新观察并核对具体控件或文件结果；若预期效果未出现，停止该动作流程并报告，不能仅凭 `observed` 宣称成功。                                                                                                                                                                                          |
| 动作提示 `OUTCOME_UNKNOWN`                        | 操作可能已经发生；先直接检查目标页面或窗口，不要重放发送、删除、付款或凭据填写                                                                                                                                                                                                                                                                                       |
| Hooks 不生效                                      | 「设置 › 高级 › Hooks」的「配置」校验结果、「测试」标签的 matcher 匹配与运行结果、handler 是否为 `command` 类型                                                                                                                                                                                                                                                      |

Finder 的内联重命名框有时不提供所属窗口。Helper 只有在辅助功能命中、前台焦点及当前可见的物理窗口都指向已绑定 Finder 窗口时才允许输入；任一条件不能确认，就会在派发前返回 `TARGET_NOT_VISIBLE`。本机曾出现 Finder 编辑框可见、但系统命中测试落在通知层的情况；把测试窗口移到无遮挡的桌面空间后，同一签名 Helper 完成了新建和命名。此时 `reason=target-input-point-unverified` 表示 Finder 编辑框虽已获焦点，但系统无法确认输入点仍属于该窗口。遇到这种拒绝时，先移开目标窗口或等待遮挡消失，再重新观察，不要放宽身份检查或反复点同一位置。每步动作后仍须重新观察：按下新建快捷键或输入名称的 `observed` 不等于文件名已经提交。若提交键收到 `STALE_TARGET`，先确认没有派发，再重新观察并核对当前编辑状态；无法确认时停止，不要盲目重复按键或改用坐标点击。

`desktop_type` 现在只向焦点明确落在可编辑文本控件的窗口派发文字。`reason=focused-text-editor-unavailable` 表示焦点仍在图标视图、只读字段或其他非编辑控件；先让目标文本框取得焦点，再重新观察。Finder 图标视图可能把误投的字符用于按名称选中，因此不能把选中项变化当作名称输入成功。

## 常用状态入口

Composer 中与当前任务相关的命令：

```text
/model
/reasoning
/permissions status
/goal
```

Token 用量和记忆在设置的对应分区中查看，Hooks 在「高级」里；插件、Skills、MCP 和工具在侧栏的「能力」页查看。「设置 › 用量」按全部、30 天或 7 天统计总 Token、输入、输出（含思考）和缓存命中率（缓存命中 ÷ 全部输入，与服务商返回的一致），主页显示这些指标和趋势（按模型或按类型）；「详细」里是活跃度（近一年热力图）、模型（可排序的排名）和缓存三个视图。

Diagnostics payload 中与内核相关的字段：

- `kernel`：打开诊断页时正在看的会话（`activeSessionId`）、正在运行的会话、当前模型 route、该会话可用的工具名单（含其项目的 MCP 工具）、各项目 MCP 实例（`projectMcp`），以及 `archivedLegacySessions`。
- `workspacePolicy`：该会话的 workspace 根和沙箱模式。
- `subagents`：子智能体记录。
- `mcp`：每个 server 的连接状态、generation 与工具数。
- `optionalCapabilities`：可选能力登记（当前包括 `watchlist` 和 `computer_use`）。

## 有效配置与来源

「设置 › 高级 › 诊断」的「配置」分组列出从现有事实源即时计算的配置项：模型执行策略、沙箱策略和 MCP 配置各一行，显示是否生效、最终来源和覆盖层数；当前可见的 `skills.<name>` 合并为一行「Skills 配置」，有来源不受信任或被拒绝的 Skill 时列出名称。Build 会话的项目 Skill 来源为 project；切回 Chat 后回到 user 或 builtin。「复制报告」中包含这些行。

MCP 的 args、env、headers 和 URL 在有效配置里统一显示为 `[REDACTED]`。有效配置是只读解释面，不是新配置文件；修改仍回到原入口（`settings.json`、能力页的 MCP 标签、Skill 目录）。

## 会话与恢复

会话的全部事实在 `stateRoot/sessions/<id>/log.jsonl`，这份 log 是 append-only 的：

- 应用在 turn 进行中退出或崩溃后，下次打开会话时会自动修复：未完成的工具调用被标记为未开始或结果未知，turn 以中断结束，待回答的审批与问题关闭为不可用。修复不会重新执行任何工具。
- 断电或强退可能让 log 末尾留下半行。下次打开会话时，这半行被移到同目录的 `log.jsonl.tail-<时间戳>`，会话照常打开；中间某行损坏时，保留损坏处之前的内容，原文件另存为 `log.jsonl.corrupt-<时间戳>`。两种情况界面都会提示一次。
- 只有记录头（第一行）损坏时会话打不开，原文件不会被改动，可以备份后提交问题。
- 磁盘写满时会话暂停保存，内容先留在内存里；腾出空间后自动补写。期间不要退出应用。
- 刷新或重启后，界面时间线从 log 重新投影，与实时显示一致。
- 会话记录读取失败时，时间线显示原因和「重试」，点一下重新读取；不会显示成空白的新对话。切到别的会话再回来也会重新读取。
- 只有应用刚启动时连不上本地服务，才会整屏显示「桌面端启动失败」和「重新连接」；使用中某次刷新失败只弹出提示，界面保持原样。要打开的会话已在别处归档或删除时，会回到最近的会话并提示。

出现恢复问题时，先完整备份该 session 目录，再提交问题；不要手工编辑 `log.jsonl`。

`/new` 会创建一个新会话并切换过去，旧会话保留；若只想减少上下文占用，使用 `/compact`。转换中断时检查 `stateRoot/control/session-transitions.json`，不要手工伪造 `applied` 状态。

## 后台任务与子智能体

CoreApi 的 `tasks.*` 把后台 job（`bash` 的后台命令）、子智能体会话和工作流运行（`workflow` / `ralph`）汇总在一起。界面中：

- 环境信息卡的「子智能体」一行点开后列出本会话委派的子智能体，点击打开子会话；子智能体仍在运行时，可以在子会话里点「停止」。
- 「后台任务」行显示后台命令和工作流运行的数量；点击展开后，每个任务有「输出」（只读查看命令输出或工作流记录）和运行中才有的「停止」。停止工作流前会先确认，它正在运行的子智能体会一起停止。
- 工作流在前台运行，停止当前 turn 会同时取消它；应用在运行中退出后，该运行记为已中断。
- 后台命令由 Agent 通过 `job_output`、`job_list`、`job_kill` 读取和停止，你也可以在「后台任务」中查看输出或停止它，Agent 下一步会知道是你停止的；后台命令只存在于当前进程，应用退出时会被终止。子智能体启动的后台命令在它被停止或会话停止时一起终止。
- 永久删除会话（「最近删除」里的「永久删除」或 30 天到期）时，它的子智能体会话和保存的大结果（`spill`，包括过长的命令输出）一起删除。
- fork 模式的子智能体会话不再复制主会话的历史，而是引用它；主会话永久删除后这些子会话也随之删除。

## 存储与清理

「设置 › 高级 › 存储」列出 Emperor Home 里会话、附件、溢出文件、记忆版本、用量账本、委派和其他各占多少磁盘空间（与 `du` 的统计一致）。「清理」先确认，然后删除：

- 30 天没有变化、且不属于任何会话的溢出文件（例如旧版本留下的命令输出 `shell-*.log`）；
- 「最近删除」里已超过 30 天的会话；
- 记忆版本索引之外的快照文件；
- 会话已删除的委派（Claude Code、Codex 子智能体的任务）留下的隔离目录和临时文件。

对话、附件与设置不会被清理。完成后页面写明释放了多少空间、各删除了几项，并重新统计占用。每次启动后 Emperor 也会在后台自动清理一次，不影响启动。

## 备份与恢复

「设置 › 高级 › 存储 › 备份与恢复」把 Emperor Home 打包成一个 `.emperor-backup.zip`，或从这样的文件恢复。

**导出备份**：点「导出…」，对话框先列出备份会包含的内容和大小，确认后选择保存位置（默认「文稿」），完成后可以「在访达中显示」。备份只保存在你选的位置，Emperor 不会上传。

| 部分                 | 内容                                                                                                                    |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 设置与配置           | `settings.json`、`model_config.json`、`mcp_config.json`、`hooks.json`、首次使用记录、子智能体设置与「以后都允许」的选择 |
| 记忆                 | 长期记忆、用户档案、情景记忆与版本历史                                                                                  |
| Skills、插件与智能体 | 你安装和编写的 Skills、已安装的插件、自定义智能体                                                                       |
| 项目与定时任务       | 项目设置、项目记忆和定时任务                                                                                            |
| 会话（可选）         | 会话记录、附件和用量记录；默认包含，可以在对话框里取消「包含会话」                                                      |
| 密码管理器（可选）   | 只有勾选「包含密码管理器」并设置备份口令（至少 12 个字符，输入两次）时才放进去，见下文                                  |

备份不包含：Agent 浏览器的登录资料与缓存（`browser/profiles`）、Agent 下载的文件、日志、受管环境工具、运行时与临时文件（`run/`、`spill/`、锁文件）、子智能体的运行目录，以及 `installation.json`。

**密码管理器与密钥**：不设备份口令时，备份里既没有凭据库（`computer-use/vault.json`），也没有 Emperor 的本地密钥（`computer-use/secrets/local.key`）。设了口令时，凭据库连同本地密钥用口令加密成一个文件放进备份（与密码管理器里「导出凭据备份」相同的方式），子智能体设置里粘贴的 Claude Code 令牌（`delegations/credentials.json`，用本地密钥加密）也一起放进去；忘记口令就无法恢复它们。恢复时填了口令才会恢复这些凭据，文件权限保持 0600。凭据库加了主密码时，先在「设置 › 浏览器 › 密码管理器」解锁。

**模型 Key 与 MCP 令牌**：它们在备份里仍是用本地密钥加密的形式；还没加密过的明文 Key 在备份里也会先加密（加密不可用时不放进备份）。在同一台 Mac 上恢复照常可用；恢复到另一台 Mac 时，只有备份里带了密码管理器（也就带了本地密钥）、而那台 Mac 上还没有 Emperor 本地密钥，Key 才能直接使用，否则需要在「设置 › 模型」重新填写。

**从备份恢复**：点「选择备份…」，选一个 `.emperor-backup.zip`。Emperor 先检查文件（不是 Emperor 备份、含有不该恢复的路径或符号链接、来自格式更新的备份都会拒绝，并说明原因），再显示备份时间、写入它的 Emperor 版本和会替换的部分。备份由更新版本的 Emperor 写入时会提示「这个备份来自更新版本的 Emperor」：可以恢复，但那些文件在当前版本里只读。备份带有密码管理器时可以填写备份口令一起恢复；口令错误时什么都不会改动，可以重新输入；留空则不恢复凭据。

点「恢复并重新启动」后，Emperor 重新启动，并在打开数据之前完成恢复：

1. 先把当前数据中会被替换的部分移到 Emperor Home 的 `migrations/backup-<日期时间>/`（保持原来的相对路径），这就是恢复前的自动备份；
2. 再把备份里的文件放到原位。备份没有的部分（例如没有包含会话的备份）保持当前内容不变；浏览器登录资料、日志和本地密钥不会改动；
3. 结果记在 `migrations/log.jsonl`。中途失败时，已经移动的文件全部移回，Emperor 照常用原来的数据启动，未完成的恢复留在 `migrations/restore-failed-<日期时间>/`。

启动后会提示「已从备份恢复」。确认恢复无误后，可以手动删除 `migrations/backup-*` 释放空间；需要撤销时，退出 Emperor，把其中的文件移回 Emperor Home 原处。

## 用较旧的 Emperor 打开数据

Emperor 自己的主要持久文件（设置、模型配置、定时任务、凭据库、会话索引、插件与浏览器记录、子智能体设置等）都写明它的版本（`version` 或 `schemaVersion`）；你自己的 `mcp_config.json` 和 `hooks.json` 不带 Emperor 的版本号，Emperor 也不会为此改写它们。较旧的 Emperor 读到更新版本写入的文件时：

- 照常读取它能理解的内容，但不会改写这个文件，也不会把它当作损坏文件移走；
- 修改这类文件的操作会失败，并提示「这个文件来自更新版本的 Emperor，当前版本只读」；
- 「设置 › 高级 › 存储」顶部列出这些文件；
- 比上次打开的版本旧时，启动后顶部会出现提示，点「查看」打开「存储」。

定时任务文件来自更新版本时，定时任务服务不启动（不会出现「运行了却记不下来」的重复运行）；会话索引来自更新版本时，会话照常使用，索引只在内存中更新。回到更新版本的 Emperor 后一切恢复正常。整个 Emperor Home 的布局版本更高时（`installation.json` 的 `stateLayoutVersion`），仍然直接显示恢复页，不会打开数据。

升级时，数据迁移（`migrations/<from>-<to>`）先把会改动的文件复制到 `migrations/backup-<日期时间>/`，结果写入 `migrations/log.jsonl`；某一步失败时从这份复制恢复原文件，下次启动再试。

## Time Machine 与凭据文件

- Agent 浏览器的登录档案文件夹（`~/.emperor/browser/profiles/<profile-id>/`，网站数据、缓存与登录状态）由 Emperor 自动排除出 Time Machine（`tmutil addexclusion`）。
- 建议再手动排除可以重新生成、体积大的目录：`~/.emperor/browser/profiles`（整个文件夹）、`~/.emperor/browser/downloads`、`~/.emperor/environment/downloads`、`~/.emperor/spill`、`~/.emperor/logs`（使用 `EMPEROR_CONFIG_DIR` 时）。在「系统设置 › 通用 › 时间机器 › 选项」里添加，或执行 `tmutil addexclusion <路径>`。
- 不要排除整个 `~/.emperor`：会话、记忆和配置都在里面。需要单独、可携带的副本时用上面的「导出备份」。
- 凭据文件的保护方式：凭据库 `computer-use/vault.json` 的每个字段、模型 Key 和 MCP 令牌都用 Emperor 本地密钥加密（AES-256-GCM），可以再加主密码；本地密钥 `computer-use/secrets/local.key` 只属于当前用户（0600，目录 0700），不使用钥匙串，Agent 的 Shell 与文件工具也读不到 `computer-use/`。Time Machine 备份里同时有本地密钥和凭据库，因此要像保护这台 Mac 一样保护备份磁盘（建议开启 Time Machine 的备份加密）。

## 资源详情

网页卡片先显示消息或工具已提供的信息；只有点详情后才联网。离线、超时、限流、网站拒绝或 GitHub 插件停用会显示原因，原链接保留，恢复后可手动重试。详情不使用浏览器登录 Cookie，浏览器里能看见的私密页面不一定可预览。预览图加载失败时仍可查看文字与地址。

文件标为不存在时，检查完整路径和当前 Build 项目；外部文件只在 Finder 中显示，已删除附件无法恢复。「输出内容」和「来源」只覆盖已加载历史，继续加载较早消息后会补齐。电脑操作截图在来源中标为观察记录。

## 更新与 Electron 版本

「设置 › 高级 › 诊断 › 桌面」有三行与更新有关：

- **检查更新**：已开启 / 已关闭 / 开发版不检查；上次检查没连上 GitHub 时写明原因并说明稍后自动重试（不算异常）。
- **测试更新源**：只在设置了环境变量 `EMPEROR_UPDATE_FEED_URL` 时出现，标为需要关注，写明地址。正常使用时不应看到这一行；看到了就检查启动 Emperor 的环境（例如 `launchctl getenv EMPEROR_UPDATE_FEED_URL`），去掉它后重启。
- **Electron 版本**：内置浏览器内核的版本，与最新发布内置的版本比较；落后 2 个以上主版本时标为需要关注，更新 Emperor 即可。

下载更新失败时，「设置 › 常规」最上方写明原因：SHA-256 与 `SHA256SUMS.txt` 不符或 GitHub 来源证明核验失败时，下载的文件已经删除，可以「重新下载」；反复失败说明下载的内容被改动过，请到 [GitHub Releases](https://github.com/TheSyart/emperor-agent/releases) 手动下载并用 `shasum -a 256 -c SHA256SUMS.txt` 核对。完整说明见[更新](getting-started.md#6-更新)。

## GitHub CLI（gh）

「Pull Request」页（包括 GitHub 插件的「议题」「CI」标签）和「审查」里当前分支的 PR 一行都依赖本机的 GitHub CLI。`gh` 是签名工具目录中的可选工具，要求 2.40.0 或更高版本；Emperor 只探测它，不会替你安装或登录。

1. 在「设置 › 高级 › 诊断」的「环境工具」分组里，看「当前项目」中 `gh` 的状态和版本。
2. 未安装时用 Homebrew 安装（`brew install gh`），或按 [GitHub CLI 官方说明](https://github.com/cli/cli#installation) 安装。
3. 在终端运行 `gh auth login` 完成登录。Build 会话可以直接使用右侧工作台的「终端」。
4. 回到 Pull Request 页点「重新检测」，或刷新诊断页。

Pull Request 页的三种不可用状态：

| 页面标题              | 含义                                                                  |
| --------------------- | --------------------------------------------------------------------- |
| 需要 GitHub CLI（gh） | 没有探测到可用的 `gh`，或版本低于要求；页面给出安装命令和「前往诊断」 |
| GitHub CLI 尚未登录   | `gh` 可用但没有登录，运行 `gh auth login` 后重新检测                  |
| 无法连接 GitHub CLI   | `gh` 调用失败，页面显示脱敏后的错误信息，可以「重试」                 |

`gh` 可用时，单次读取还可能遇到：

| 提示                               | 含义                                                                |
| ---------------------------------- | ------------------------------------------------------------------- |
| GitHub 暂时限流，请稍后再试        | GitHub 对当前账户限流（包括二级限流），过一会儿再刷新               |
| 当前账户没有读取这个仓库的权限     | 仓库存在，但 `gh` 登录的账户或其令牌权限不够读取                    |
| 找不到……，或当前账户无权访问该仓库 | 仓库、Issue 或运行记录不存在；GitHub 对无权查看的私有仓库也这样回应 |
| GitHub 插件已停用                  | 「议题」「CI」标签属于 GitHub 插件，在「能力 › 插件」里重新启用     |

Emperor 运行 `gh` 时不传递 `GH_TOKEN`、`GITHUB_TOKEN` 等 token 类环境变量，只使用 `gh` 自己保存的登录状态（会保留 `GH_CONFIG_DIR`、`XDG_CONFIG_HOME` 等定位 `gh` 配置目录的变量）。只在 shell 里设置了 token 环境变量、没有执行 `gh auth login` 时，页面会显示未登录。

## 受管进程

进程最小账本位于 `stateRoot/processes/receipts.v1.json`，只保存 owner、lease、脱敏摘要、PID 与启动身份和终态，不保存命令、环境变量或输出。应用重启后，Core 只在启动身份精确匹配时回收遗留进程，无法证明时标记为 `orphan_unverified` 且不盲杀。不要根据账本中的 PID 自行批量 kill。

## 配置损坏

Model、MCP、settings 和 Hooks 配置使用原子写或损坏保留策略。无法解析时，Core 会尽量保留带后缀的 corrupt backup，并使用安全默认值启动。

处理顺序：

1. 在诊断页确认文件路径和状态；
2. 退出应用；
3. 备份整个 `stateRoot`；
4. 对照 example 修复配置，或通过设置页重新保存；
5. 重启并确认 diagnostics 不再报告 corrupt。

不要把包含 API Key 的原文件贴到公开 issue。

## 提交问题

普通问题应包含：应用来源、平台与架构、复现步骤、期望结果、实际结果，以及「导出诊断包」生成的 zip（日志已脱敏，不含会话内容和密钥）。不要上传 API Key、环境变量、用户文档、崩溃转储原文件或完整 `stateRoot`。
