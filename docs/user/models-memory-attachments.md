## 模型配置

Emperor Agent 可以保存多条模型配置，但全局同时只激活一个模型：

- 文件：`stateRoot/model_config.json`
- schema：`schemaVersion: 2`
- 激活项：`activeModelId`
- 模型数组：`models[]`

每条模型至少包含 Provider、协议、模型 ID、API Base、上下文窗口、最大输出 Token 和稳定的 `entryId`。API Key 可以为空，例如连接本地兼容服务时。

此外还有几个可选字段（示例见 [`config/examples/model_config.example.json`](../../config/examples/model_config.example.json)）：

- `connectionId`：同一个连接（同一 Provider、协议、地址和 Key）的模型共用；换 Key 或地址时，这个连接下的所有模型一起更新。没有这个字段的旧条目按 Provider、协议和规范化后的地址归为同一连接。
- `limits`：输入、输出 Token 上限。
- `detected`：从厂商模型列表或内置目录得知的能力（工具、识图、思考与可选档位、是否接受温度、模态、类型）。能力的判断顺序是：你的能力覆盖 > `detected` > 按模型 ID 推断 > 默认值；思考强度的可选档位优先用 `detected.reasoningEfforts`。
- `metadata`：这些数据的来源（厂商接口、内置目录、家族规则、兜底或手动）、核对时间、生命周期，以及你锁定、不让刷新覆盖的字段（`userLocked`）。没有这个字段的旧条目视为手动填写、全部锁定。
- `sampling`：温度等采样参数。模型已知不接受温度时，请求里不会带温度。

文件里某一条模型格式不对时，只跳过这一条，其余模型照常可用；「设置 › 模型」顶部会列出无法读取的条目和原因，可以删除，或重新添加这个模型。正在使用的模型不能删除，要先在输入框切换到其他模型。保存模型设置时，所有改动在进程内依次写入，同时进行的两次保存不会互相覆盖。

旧版本 Emperor 能读取带这些字段的文件，但它保存时会丢掉这些字段（必填字段不受影响）；降级后再升级，需要在设置里刷新一次模型资料。

API Key 加密后写入文件（`"apiKey": "el1:…"`），使用与凭据库相同的 Emperor 本地密钥（`computer-use/secrets/local.key`），不使用 macOS 钥匙串；每个 Key 只能在它所属的那条模型里解开。旧版本留下的明文 Key 照常可用，下一次保存模型设置时自动加密，加密前的原文件保留为 `model_config.json.pre-seal-<时间>`（含明文，确认一切正常后可以自行删除）。设置页只显示已保存 Key 的末 4 位。本地密钥丢失或被替换时（例如只复制了 `model_config.json` 到另一台电脑），受影响的模型显示「凭据需要重新输入」，其余模型和设置照常可用，重新填写 Key 并保存即可；以同一用户运行的程序仍可能读到本地密钥，这是基础保护。

Provider 描述的是访问方式，不是固定模型清单。部分 Provider 支持模型发现；发现失败时仍可以手工填写模型 ID。`custom` 需要明确选择 `openai` 或 `anthropic` 协议。Provider 为 `deepseek` 时使用内置的 DeepSeek 适配器：官方地址默认走 Anthropic Messages，其他地址走 OpenAI Chat Completions（见下文「DeepSeek 的接口」）。其他 Provider 按所选协议走 OpenAI Chat Completions 或 Anthropic Messages。

“显示名称”只保存你明确设置的自定义别名；未设置时用目录或厂商给出的名称（`metadata.name`），再没有时用模型 ID。

「设置 › 模型」负责新增、编辑、连接测试和删除配置。配置按供应商分组，每个供应商一张卡片：卡片头是 logo、名称和连接状态（「已连接」「Key 无效 · N 天前测试」「连接失败 · …」「未测试」；缺 Key 时写「缺少 API Key」，本地密钥换过、Key 解不开时写「凭据需要重新输入」，Ollama 等本机服务写「本地 · 无需 Key」），下面一行是服务地址和已保存 Key 的末 4 位。卡片内逐行列出模型：显示名、「当前」、模型 ID、能力标签（工具 / 识图 / 思考）、「上下文 / 每次输出」和思考强度；鼠标停在行上时出现「测试」「编辑」和「⋯」：

- 右上角「添加模型」打开三步对话框（没有任何模型时会自动打开；输入框模型菜单底部的「添加模型…」也能打开）：
  1. **连接**：在搜索框输入供应商名称，或直接粘贴 API 地址（按主机名识别供应商，认不出的按「自定义」兼容接口处理）。供应商按国内、海外、本地、其他分组，其余的在「更多」里；Ollama、LM Studio 显示「未运行」或「运行中 · N 个模型」。填写 API Key（「获取 Key ↗」打开供应商的 Key 页面；粘贴的 Key 看起来属于其他供应商时会提示切换），已经保存过这个连接时默认勾选「沿用已保存的 Key」。供应商支持两种协议时直接显示「OpenAI 兼容 / Anthropic 协议」的选择；API 地址在「高级」里。点「连接并获取模型」先测试连接，再读取模型列表；Key 不对、地址不像兼容接口、连不上或被限流时会写明原因，能修正的地址可以一键改。
  2. **选择模型**：默认按「推荐」排序、按家族分组列出这个连接的对话模型，也可以按最新或名称排序；筛选有全部、识图、工具、思考、新（6 个月内）、非对话。供应商没有模型列表接口时，列表上方写明「下面是内置目录推荐」。每行显示确定具备的能力、上下文与输出上限、数据来源（官方接口、内置目录、推断、未知），以及「已添加」「将下线」「已退役」。列表不超过 3 个时全部预选，否则每个家族预选最新的一个；找不到时可以手动输入模型 ID，会按内置目录给出默认值。
  3. **确认参数**：每个模型可以调上下文、每次输出（旁注上限）、能力（自动 / 开 / 关）和思考强度（不能关闭思考的模型不提供「关闭」）；「高级」里有显示名、温度（模型不接受温度时不可填）和单价。来源为「未知」的数值需要勾选「我已核对这些数值」才能保存。可以统一设置每次输出，并选择把哪个模型设为当前模型。「添加 N 个模型」一次保存全部，保存后新行会高亮，并在后台对第一个新模型做一次文本测试。
- 供应商卡片上的「管理模型」直接打开这个供应商的第 2 步：已保存的模型是勾选状态，勾选新的会加入，取消勾选会删除（正在使用的模型和被备用模型引用的模型不能取消）。
- 卡片的「⋯」：**更换 Key**（这个连接下的所有模型一起改用新 Key，确认框会写明「将同时更新 N 个模型」）、**编辑地址**（同样作用于整个连接，Key 不变）、**刷新模型资料**（先列出内置目录与当前值的差异，如上下文、输出上限、能力、单价，点「应用」才写入；你改过的值不会动）、**删除供应商**（删除它的全部模型和 Key；有正在使用的模型时要先在输入框换掉）。
- 「测试」用已保存的配置发送一次最小请求，结果写在这一行，卡片头的连接状态随之更新（测试结果记在 `model_tests.json`，重启后仍在）。
- 「编辑」在该行下方展开编辑器，只放常改的：显示名、上下文、每次输出（各有 32K–1M、8K–128K 的预设，旁注数值来源：手动、官方接口、内置目录、推断，以及上限）、思考强度和三项能力。连接信息只读，旁边的「编辑地址」打开卡片的同名对话框；温度和单价在「高级」里（模型不接受温度时不可填；单价留空表示未知），DeepSeek 官方地址的模型在「高级」里还有「接口」。你改过的数值会被锁定，之后刷新模型资料不会覆盖。
- 厂商已退役或即将下线的模型在行下方显示琥珀色提示；内置目录知道替代模型时有「替换为 X」：新模型占用原来的位置，沿用你设置过的值、能力覆盖、温度和 Key，正在使用它或把它当备用模型的地方一起改过去。
- 「⋯ › 删除」先确认再删除这一个模型。

模型切换在聊天输入框完成，切换从下一次请求开始生效。输入框的模型菜单分两层：「模型」按供应商分组列出已保存的模型，模型较多时可以搜索；「思考强度」列出当前模型支持的档位。

能力覆盖包含 `toolCall`、`vision` 和 `reasoning`，用于修正无法自动判断的模型能力，不会让本来不支持该能力的服务端获得能力。

### DeepSeek 的接口

Provider 为 `deepseek`、API 地址是官方的 `https://api.deepseek.com`（带 `/v1`、`/anthropic` 等路径也算）时，请求默认走 Anthropic Messages 接口（`https://api.deepseek.com/anthropic/v1/messages`），与保存时选的协议是 OpenAI 还是 Anthropic 无关。编辑器的连接信息里会写「Anthropic Messages」。

- 思考内容连同签名原样带回下一轮，只回给产生它的同一个模型；换了模型之后，之前的思考不再发送。
- 思考强度按 DeepSeek 的三档发送：low、high、max。Emperor 的 medium 按 high 发送，「关闭」就是不开思考。编辑器、添加模型对话框和输入框的思考强度处都有这句提示。会话标题和压缩摘要不开思考。
- 图片先上传到 DeepSeek 的 Files API，请求里只引用文件，同一张图只传一次。缓存按「地址 + Key」分开，只在内存里，重启后同一张图会再传一次。上传的文件名以 `emperor-` 开头，24 小时后在 DeepSeek 端自动删除；超过约 1300×1300 像素的图片先缩小并转成 JPEG（质量 85，还太大就试 75、60）。账号的文件存储满了时，Emperor 只删除自己上传的最旧文件，再重试一次；上传失败时这张图改为直接内嵌在请求里（单次请求的内嵌图片最多 20 MiB），之后 10 分钟内同一个地址和 Key 不再尝试上传。
- 以前走 Chat Completions 的旧会话可以直接继续：其中的思考内容作为不带签名的思考发给同一个模型。

自定义网关或代理地址仍走 OpenAI Chat Completions（`/chat/completions`），图片直接内嵌在请求里。官方地址也想回到 Chat Completions 时（例如 Messages 接口出问题），任选一种：

- 在「设置 › 模型」点这个模型的「编辑」，在「高级 › 接口」选「OpenAI Chat Completions（回退）」并保存；改回「Anthropic Messages（默认）」即恢复。
- 编辑 `model_config.json`，给这条模型加 `"transport": "chat-completions"`。把 `"protocol"` 写成 `"chat-completions"` 也可以，读取时会换算成 `"protocol": "openai"` 加 `"transport": "chat-completions"`。删掉 `transport` 即恢复默认。

旧条目里的 `extraBody` 在两种接口下都会合并进请求，写的是 Chat Completions 的参数时，记得一起切回 Chat Completions。

### 重试

模型请求遇到空响应、限流、服务端错误、超时或网络错误时，最多自动重试 5 次，间隔从 0.5 秒指数增长到 10 秒；服务商返回的 Retry-After 在上限内时优先采用。认证、请求格式等错误不重试。

### 备用模型与成本上限

执行策略保存在 `model_config.json` 中，在「设置 › 模型」列表下方的「执行与成本策略」中编辑，改动立即保存（开关和选择改了就生效，成本上限在离开输入框或按回车时保存；打开备用模型后要选好目标才生效）：

- **备用模型**：开启且指定了可用条目后，主模型在自动重试用尽、且错误类型命中触发条件（限流，或服务端错误、超时、网络错误、空响应）时，本轮剩余请求改用备用模型；每轮最多切换一次，下一轮回到主模型。切换会在对话中显示一条提示。
- **成本上限**（设置里的「每个任务的费用上限」）：按整个任务计算。一个任务从你发出一条消息开始，到下一条消息为止，主对话、它启动的全部子智能体、失败后重试的请求都计入，按条目的 `pricing` 在每次请求返回后累计。达到上限后，正在做的这一步做完就停止，不再启动新的子智能体，对话里显示「已达到任务费用上限」；发出下一条消息后重新计算。没有单价的模型无法计算费用，上限对它不生效（它的用量不计入，也不会因此停止），设置页会写明「「X」没有单价，成本上限对它不生效」；账本里它的费用记为未知。单个请求本身可能略超上限。

## 模型请求会发送什么

每次请求可能包含：系统提示词、工作区说明（`AGENTS.md` / `CLAUDE.md`）、用户档案、长期记忆、Skill 目录与被调用的 Skill 说明、会话历史（含压缩摘要）、附件文本或图片，以及工具结果。

API Key 不会出现在模型上下文中。MCP 返回的内容按不可信输入处理，但其中与任务相关的文本仍会发给模型。

## 记忆层

| 数据         | 默认位置                                | 用途                       |
| ------------ | --------------------------------------- | -------------------------- |
| 用户档案     | `memory/profile/USER.local.md`          | 稳定偏好和个人上下文       |
| 全局长期记忆 | `memory/MEMORY.local.md`                | 跨会话的长期事实           |
| 项目私有记忆 | `projects/<project-id>/AGENTS.local.md` | 绑定项目的 Build 上下文    |
| 按日情景记忆 | `memory/YYYY-MM-DD.md`                  | 在设置的“记忆”中查看和编辑 |
| 记忆版本     | `memory/versions/`                      | 查看和恢复历史快照         |
| 会话记录     | `sessions/<session-id>/log.jsonl`       | 当前会话的全部内容         |

表中路径都相对 Emperor Home（`stateRoot`），默认 `~/.emperor`。

用户档案、全局长期记忆和（Build 会话中的）项目私有记忆会作为背景信息进入每个会话，内容变化后的下一轮会重新注入。每一节最多 32 KiB。Agent 可以用 `memory_edit` 工具修改这三份记忆（精确替换或追加），修改会生成版本快照；你也可以要求它“记住”某件事。在 `danger-full-access` 以外的权限预设下，每个会话第一次写入记忆前会请你批准一次。看起来像 API Key、令牌或私钥的内容，以及“忽略之前的指令”一类的文字会被拒绝写入。项目源码中的 `AGENTS.md` 不属于这个写入链路。

「设置 › 记忆」顶部是可展开的「上下文概览」，汇总上下文、历史 log、压缩和维护状态，需要处理时显示“需关注”。下方在「长期记忆」「用户档案」之间切换，直接编辑对应文件（右上角「保存」或 ⌘S）；“用户档案”上方显示档案访谈状态，可以开始或重新开始访谈（访谈还没做时，第一个空会话的输入框下方也会提示一次）。编辑器上的「历史」打开版本列表：列出记忆快照，可以查看差异并「恢复」。按日的情景记忆和 Watchlist 在右上角「更多」里，情景记忆按日期选择。两个编辑器各自保留未保存的修改，切换时不会丢；关闭设置或离开「记忆」前会先确认。

## 会话压缩

- 自动：上下文估算达到触发线时，Agent 会先截短较早的超长工具结果（刚产生、模型还没看过的结果不截），仍不够时把较早的对话压缩成一份摘要，保留最近的一段。触发线是上下文窗口的 80%，并且至少给模型的单次输出和摘要留出 64K 的余量：例如 128K 窗口、每次输出 8K 的模型约在 54K 时压缩，1M 窗口、每次输出 64K 的模型在 800K 时压缩；“每次输出”设得越大，压缩越早。
- 估算按中文、英文分别计算，并在每次请求后用服务商返回的真实用量校准，中文对话不会再被低估；图片按所用模型的计价方式估算。
- 自动压缩失败后会暂停 3 步再试；连续失败 3 次时对话里会提示「上下文接近上限」，这时可以输入 `/compact` 或新开一个会话。
- 溢出：服务商报告上下文超限时，会先压缩再重试一次；历史太长时摘要分段生成再合并，不会因为摘要请求本身超限而失败。
- 手动：输入 `/compact` 立即压缩当前会话。
- 一次请求里的图片超过模型的大小上限时，最早的图片改为一段说明文字发送；之后换模型、改用备用模型或重新打开会话，这些图片仍按说明文字发送。

摘要固定分为 8 个部分：主要请求与意图、关键技术概念、文件与代码、错误与修复、未完成的后台任务、当前工作、下一步和关键上下文。压缩只改变发给模型的会话内容，不会改写长期记忆，也不会删除 `log.jsonl` 中的原始记录。

## 附件

Composer 一次最多保留 5 个待发送附件：

- 图片：PNG、JPEG/JPG、WebP、GIF，单个最多 10 MiB；
- 文档和文本：PDF、JSON、CSV、纯文本、Markdown，单个最多 25 MiB。

非图片附件会提取文本并随消息发送。图片作为图像内容发送；当前模型不支持视觉时，请求中的图片会替换为一段说明文字。

附件原文件保存在 `stateRoot/memory/attachments/<month>/`，通过 `app://attachments/{id}/raw` 读取。Renderer 不能用该协议读取任意本地路径。

## 备份与迁移

用「设置 › 高级 › 存储 › 备份与恢复」备份：「导出备份」把 Emperor Home 打包成一个 `.emperor-backup.zip`（可选包含会话；密码管理器要另设备份口令才会包含），「从备份恢复」先把当前数据移到一边保留，再恢复并重新启动。包含什么、不包含什么见[备份与恢复](diagnostics-troubleshooting.md#备份与恢复)。

手工复制时先完全退出应用，再复制整个 Emperor Home。只复制 `memory/` 会遗漏会话、定时任务、MCP、用户 Skills、受管工具环境和模型配置；模型 Key 和 MCP 令牌用 `computer-use/secrets/local.key` 加密，单独复制 `model_config.json` 或 `mcp_config.json` 时这些值无法解开，需要重新填写。

从更早的旧内核版本第一次升级时，旧的 `sessions/` 目录会整体移到 `sessions.legacy-<时间戳>/` 保留，会话列表从空开始；旧会话不会被删除，但也不会在界面中显示。从 0.1.0-preview.2 或更新的预览版升级到 0.2 不会移动会话。不要在应用运行时手工修改 `log.jsonl`。

完整目录和迁移规则见[全局私有存储根架构](../architecture/global-state-store.md)。
