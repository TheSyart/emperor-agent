## 定时任务

点击侧栏的「定时任务」打开定时任务页（`/scheduler`），可以创建、编辑、暂停、恢复、立即运行和删除任务。Agent 也可以通过 `scheduler` 工具管理任务。

- **列表**：顶部是搜索框和「全部 / 已开启 / 已暂停 / 已完成」四个标签。每行显示任务名称、调度规则与下次运行时间（例如「星期五（时间：18:00） · 下次运行 3天后」），运行中、排队中或上次失败时带状态标记。已运行过、已停用的一次性任务归入「已完成」。
- **创建**：右上角「创建 ▾」提供「新建任务」和两个预填模板：「每日摘要」（工作日 09:00）和「每周回顾」（星期五 18:00）。模板只填好表单，保存前可以修改。
- **编辑**：点击一行打开任务对话框，查看状态、启用开关、任务详情、最近错误和运行历史，底部提供「删除」（需再次确认）、「立即运行」和「保存」。
- **行菜单**：每行右侧的 `⋯` 提供「立即运行」、「暂停」（已停用的任务显示「恢复」）和「删除」（删除前确认，任务和运行历史一并删除）。
- 受保护的系统任务可以暂停、恢复或立即运行，但不能编辑或删除。
- 列表下方显示服务状态（运行、并发和排队情况）以及关闭应用和错过触发点的处理规则。
- 「指定时间」必须选好日期和时间，并且晚于现在，否则不能保存；编辑一个已经过期的一次性任务时，不改时间就可以照常保存其他内容。
- 定时任务服务没有启动时（例如另一个 Emperor 进程正在使用同一个数据目录运行定时任务），列表上方会写明原因；「设置 › 高级 › 诊断」的「定时任务存储」一行也会显示。
- `jobs.json` 里某个任务读不出来时，只有它被移到数据目录的 `scheduler/jobs.rejected.json`，其他任务照常加载和运行；列表上方会提示一次，诊断里列出被移走任务的名称和原因。

定时任务运行完成或失败时，侧栏的通知铃铛会收到一条通知；此时正在查看定时任务页的话，这条通知直接记为已读。

任务支持：

- `at`：指定时间运行一次；
- `every`：按固定间隔运行；
- `cron`：按 cron 表达式和时区运行；
- `misfirePolicy`：应用停机期间错过触发点后的处理方式；
- `deleteAfterRun`：运行后删除一次性任务；
- `deliver`：把结果投递到会话界面。

任务类型：

- `agent_turn`：把任务消息作为一条用户消息提交到任务绑定的会话，并等待这一轮结束。在定时任务页新建任务时，任务绑定到你当时正在看的会话；旧版本留下的、没有绑定会话的任务在最近使用的会话里运行。定时任务在后台运行：不会把界面切到它的会话，你正在看的会话保持不变。目标会话有待回答的问题或审批时，本次运行会报错而不是跳过交互。
- 定时运行中遇到需要审批或回答的操作时，因为没有人在场，这些请求会被直接拒绝，模型照常收尾；这次运行记为「需要审批，已拒绝」，记录里写明被拒绝的操作。需要这类操作的任务，请先在会话里把权限预设调到允许它的级别，或改为手动执行。
- 一次定时运行最长 30 分钟，超时后停止，记为「已取消」（原因为超时），之后的触发照常进行。模型请求失败的运行记为「失败」并带错误码（例如 Key 失效为 `AUTH`）；你在会话里点停止的运行记为「已取消」。
- `system_event`：系统任务。`watchlist-check` 会检查 Watchlist，需要时再发起一轮 `agent_turn`。

旧版本创建的 `team_wake` 任务已不再支持，运行时会报错，请删除或改为 `agent_turn`。

`misfirePolicy` 有三种：`skip`（默认）只记录错过并移到下一个未来触发点；`latest` 只补跑最后一个错过的触发点；`catch-up-one` 只补跑最早一个错过的触发点。无论错过多少次，每个任务每次启动最多补跑一次。电脑睡眠期间错过的触发点按同样的规则处理：醒来时比触发点晚 1 分钟以上，就当作错过，`skip` 的任务记一条「已跳过」，其余两种补跑一次。启动时补跑的任务在插件同步之后才开始，插件提供的 Hook 对它照常生效。

同一个数据目录同时只有一个进程运行定时任务（`scheduler/scheduler.lock`）：例如编辑器里的 ACP 会话先占用了它，桌面端就不运行定时任务并说明原因；占用的进程退出后，桌面端会在 5 分钟内自动接手。

定时任务最多同时运行 2 个、同一目标最多 1 个，最多排队 100 个，这些上限不能从界面或任务放宽。应用退出时定时任务服务停止接收新任务并取消进行中的工作，它不会作为系统后台服务继续运行。重启后已经开始运行的任务不会自动重放，无法确认结果时记为 `interrupted`。

## Hooks

入口是「设置 › 高级 › Hooks」。Hooks 在指定事件发生时自动运行命令，配置写在 `hooks.json` 中，只支持 `command` 类型的 handler。

- 配置文件：`stateRoot/hooks.json`，按“事件 → matcher 分组 → hooks”组织，可以在“配置”标签编辑；保存时会校验并立即重新加载。
- 支持的事件：`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop`、`SubagentStart`、`SubagentStop`。其他事件和非 `command` 类型的 handler 会被忽略，页面会列出被跳过的项。
- Hook 在会话工作目录中按配置顺序串行运行，多个结果取最严格的决定。环境变量 `CLAUDE_PROJECT_DIR` 指向当前项目目录，单个 Hook 默认超时 10 分钟。这里说的是你自己写在 `hooks.json` 里的 Hook；插件带来的 Hook 在进程沙箱里运行，只拿到系统变量与插件清单声明的变量，默认 30 秒、最多 120 秒超时，见[工具、Skill 与 MCP › Plugins](tools-skills-mcp.md#plugins)。

| 事件               | 可以做什么                                   |
| ------------------ | -------------------------------------------- |
| `SessionStart`     | 追加上下文                                   |
| `UserPromptSubmit` | 拒绝本次提交，或追加上下文                   |
| `PreToolUse`       | 拒绝工具调用，或要求先询问你                 |
| `PostToolUse`      | 阻止结果并返回反馈，或追加上下文             |
| `Stop`             | 阻止本轮结束、让 Agent 继续（每轮最多 3 次） |
| `SubagentStart`    | 为子智能体追加上下文                         |
| `SubagentStop`     | 仅观察                                       |

Hook 输出中的 `updatedInput`、`systemMessage` 和 `continue: false` 会被解析并记录警告，但不会生效。Hook 不能放宽权限预设或沙箱。

「设置 › 高级 › Hooks」分为三个标签：

- **配置**：查看已加载的配置文件、加载错误和各事件的命令数，编辑 `hooks.json`，支持「还原」「校验」「保存」（⌘S 保存）。
- **测试**：选择事件并输入 matcher 查询，查看会匹配到的命令；对某条命令点击「执行」后还需「确认执行」才会真正运行，结果显示决定、退出码和耗时。编辑器中尚未保存的内容也按当前内容匹配和运行。
- **审计**：按事件和结果筛选当前会话的 Hook 运行记录，展开查看 matcher、退出码、耗时和 stderr。审计记录来自当前会话 log 中的 Hook 调用与结果事件。

项目目录中的 `.claude/settings.json` 当前不会被加载，项目信任设置接口也已下线。

## Watchlist

Watchlist 由 `memory/watchlist.md` 定义，在「设置 › 记忆」右上角「更多 › Watchlist」中编辑。可以在该页点击右上角的「手动检查」，也可以由定时任务中的 `watchlist-check` 系统任务定期检查；判断需要处理时会发起一轮普通 Agent turn。它不提供 Slack、邮件或社交平台连接器。

## 桌宠 companion

「设置 › 常规 › 外观 › 桌宠」可以启用或关闭 companion，默认关闭；窗口出错时开关下方显示最近的错误。窗口由主 Electron 进程托管。桌宠只投影空闲、工作等状态，不能代替真实的任务状态，也不能直接修改 Core 状态。

## 子智能体

主会话的 Agent 可以把一部分工作交给子智能体，自己继续统筹。子智能体有三种：

- **本地子智能体**：Emperor 自己的 Agent，用你在「设置 › 模型」里配置的模型，始终可用。
- **Claude Code**、**Codex**：你电脑上的 Claude Code 和 Codex，在 Emperor 的权限和工作区规则下运行。它们使用你自己的订阅额度（Claude 订阅、ChatGPT 账号）或 API 计费，所以默认关闭。

是否交出任务、交给谁由主会话的 Agent 决定；你可以在消息里直接要求，例如「让 Codex 审查这次改动」。主任务、权限和验证始终由 Emperor 负责。子智能体的页面怎样查看和发消息，见 [Chat 与 Build › 子智能体](chat-build.md#子智能体)。

### 打开 Claude Code 与 Codex

在「设置 › 子智能体」打开 Claude Code 或 Codex 的开关。Emperor 第一次把任务交给它时，对话里会弹出确认卡，写明会用哪份额度：

- 「本次允许」：这一轮对话里都允许；
- 「以后都允许」：以后不再询问（在设置里关掉再打开会恢复询问）；
- 「不允许」：这个任务改由本地子智能体完成。确认卡 15 分钟没有回答、或被关掉，也按不允许处理，且不会记住。

定时任务等无人值守的运行没法询问：除非你选过「以后都允许」，否则不会使用 Claude Code / Codex。升级前没有改过这项设置的，Claude Code 与 Codex 会被关闭，设置页顶部说明一次（「知道了」关掉）。计划模式下它们只能做只读审查。

### 设置页

「设置 › 子智能体」一屏放下全部常用设置，改动立即保存，没有「保存」按钮；右上角「重新检测」重新检查命令行程序、版本和登录。

- **可用的子智能体**：
  - 「本地子智能体」右侧选它用哪个模型：默认「跟随对话」，也可以固定为「设置 › 模型」里的某一条（例如让子任务用便宜一些的模型）。那条模型删除后暂时按对话的模型运行，行内写明「（已删除）」。
  - Claude Code、Codex 每行有状态（「子智能体就绪」「已关闭」「未登录」「未安装」「可能不兼容」「版本不兼容」「未找到命令行程序」等）和一句说明，右侧是启用开关和进入详情页的箭头。两者用各自的标志标出。打开并就绪后，行内可以选默认模型；Claude Code 打开了但还没有登录时，这个位置换成「登录 Claude Code」；没有安装时，这一行写出官方安装命令。
- **子任务**：「同时运行」（Claude Code 和 Codex 合计 1–4 个，默认 2 个，超过后排队）、「改代码的位置」（见下面「工作区与成果」）、「单个任务的费用上限」（$1 / $2 / $5 / $10，默认 $10），以及「高级」。
- **高级**：「运行」组有每次运行最多轮数、单次运行时长上限；「开发环境」组；「排查」组的「验证后再应用」「诊断模式」。各项见下文。
- **详情页**（Claude Code、Codex 各一页）：版本（见下面「版本与升级」）、状态（找不到程序时有安装命令或「安装说明」，以及「更正路径」）、登录（只有 Claude Code）、默认模型（「刷新模型」重新读取列表；下拉里还有「跟随本机 CLI」和「新增自定义模型…」）、擅长的任务（「编辑专长」或「恢复默认」，主会话据此决定交给谁）和能力与运行情况。
- **Codex 的模型**：在这里选了模型，交给 Codex 的任务就用它，即使它不在列表里。选「跟随本机 CLI」时用 Codex 自己的默认模型（`~/.codex/config.toml` 里的 `model`，Codex 桌面版也会改它）。Codex 用 ChatGPT 账号登录、而这个默认模型不在这个账号可用的模型里时（例如 Codex 桌面版换上了更新的模型，命令行版本还用不了），「默认模型」下面写一行「你的 Codex 默认模型 … 这个账号用不了，交给 Codex 的任务会改用 …；也可以在上面选一个模型。」，交给 Codex 的任务改用账号列表里的默认模型（「能力与运行」的「使用的模型」写「…（代替 …）」），任务详情写明「你的 Codex 默认模型 … 这个账号用不了，本次改用 …。」。Emperor 不修改你的 `~/.codex`。读不到账号的模型列表时不会擅自换模型；如果这一轮因为模型不可用被拒绝，Emperor 重新读一次列表，换一个可用的模型在同一个对话里重跑一次，并在任务详情里写明。

### 版本与升级

打开「设置 › 子智能体」时，Emperor 向 npm 的公开仓库查 Claude Code 和 Codex 的最新版本号，每天第一次启动时也查一次。只读取公开的版本号，不发送账号、令牌或这台 Mac 的任何信息；连不上时最新版本显示为未知，不影响使用。

- **发现新版本**：打开着的 Claude Code 或 Codex 有新版本时，页面顶部提示「Claude Code 和 Codex 有新版本」，写明从哪个版本升到哪个版本，可以「全部升级」或「稍后」（这些版本不再提示，出了更新的版本再提示）。对应那一行写「本机 x · 可升级到 y」并多一个「升级」，左侧导航的「子智能体」带一个小点。
- **升级到哪个版本**：Claude Code 升到最新版。Codex 只升到 Emperor 验证过的次版本里最新的发布版（目前验证过 0.153 和 0.163，所以 0.153.4 升到 0.163.0）；更新、但 Emperor 还没验证的版本显示「尚未验证」，不提供升级。
- **怎么升级**：按你当初安装它的方式。npm 全局安装的，用装它的那个 npm 运行 `npm install -g <包>@<版本>`；Homebrew 安装的运行 `brew upgrade <名字>`（Homebrew 提供的正是这个版本时）；用 Claude 官方安装命令装的运行 `claude install <版本>`。点「升级」后先确认：弹窗写明要运行的命令和不会改动的东西，确认后才运行。Emperor 从不自动升级，也不用管理员权限。Codex 桌面版自带的 Codex 随桌面版更新；认不出安装方式时，只给出一条命令让你复制到终端运行。
- **升级中**：那一行显示「升级中」、进度条和已用的时间，「查看过程」显示命令的输出（令牌和你的用户目录已去掉），可以「取消」。升级期间不把新的子任务交给它；正在运行的子任务先跑完，然后才开始升级。
- **完成与失败**：完成后 Emperor 重新检测，那一行写出新版本，并提示「Codex 已升级到 0.163.0」。失败时页面顶部写明原因，例如「Codex 升级失败：没有写入 /opt/homebrew/lib/node_modules 的权限」，并给出同一条命令：「复制命令」后在终端里自己运行，完成后点「重新检测」；那一行的「重试」再试一次，「查看过程」看命令输出。
- **详情页的「版本」**：本机版本、安装方式和位置、最新版本、Emperor 已验证的版本（Codex），以及「升级到 …」「检查更新」和上次检查的时间。
- 升级不改动 `~/.codex`、`~/.claude` 里的登录和设置，Emperor 为 Claude Code 准备的专用登录也保留。

### 登录

**安装 Claude Code**：Emperor 运行你在这台 Mac 上安装的、未经修改的 Claude Code（`claude` 命令），应用本身不附带 Claude Code。它会在 `PATH`、常见的安装位置（`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin` 等）和登录 shell 的 `PATH` 里找 `claude`。还没安装时，设置页那一行显示「未安装」和官方安装命令：在终端运行

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

装好后点「重新检测」（也可以用 Homebrew：`brew install --cask claude-code`）。需要 2.1.79 或更高版本；更旧的显示「版本不兼容」，点那一行的「升级」，或在终端运行 `claude update` 升级。装在别处时，在详情页点「更正路径」填写它的完整路径。

**登录 Claude Code**：Claude Code 用它自己的登录，第一次使用前登录一次：

1. 在「设置 › 子智能体」Claude Code 那一行，或详情页的「登录」里，点「登录 Claude Code」。
2. Emperor 运行 Claude Code 自己的登录（`claude auth login`），浏览器打开 Claude 的登录页，设置页显示「正在浏览器中登录 Claude Code…」。在浏览器里登录你的 Claude 账号（Pro、Max、Team 或 Enterprise）并授权。
3. 浏览器里完成后，设置页自己显示「已登录 Claude 账号 · 你的邮箱」，不用再点什么。中途不想登录了，点「取消」。

同一时间只有一个登录在进行。10 分钟内没有完成，或者 Claude Code 中途出错时，设置页写明原因，并给出一行命令作为备用：点「复制命令」，粘贴到 macOS 的「终端」里运行，按提示在浏览器里登录，完成后回到 Emperor 点「重新检测」。这行命令用同一个专用目录，登录的结果和上面一样。

用 Anthropic Console 账号按用量计费时，点详情页的「用 Console 账号登录（按用量计费）」，同样在浏览器里完成（`claude auth login --console`）。「退出登录」运行 `claude auth logout`。

这份登录由 Claude Code 自己保存在专用目录里的文件中，和 Codex 一样不放进 macOS 钥匙串。原因是 Emperor 运行它时用的是专用的主目录，那里没有你的登录钥匙串；Emperor 替它回答「钥匙串不可用」，所以不会弹出「找不到钥匙串」的系统提示。如果以前遇到这个提示时点过「还原」，子智能体页可能显示未登录，重新登录一次即可。Emperor 为它准备了一个专用目录（`~/.emperor/delegations/claude-code/`），每个子任务、每次检测和每次登录都用这个目录，所以登录一次之后一直有效；它和你平时在终端里用的 `claude` 的登录互不影响。**Emperor 不读取、不保存、也不转交你的 Claude 登录**：登录时浏览器直接把结果交回 Claude Code，Emperor 不读 Claude Code 打印的登录链接或代码；之后它只运行 `claude auth status`，问 Claude Code 是否已登录、用的是哪种方式和哪个账号，再把这些显示出来；Emperor 自己的工具也读不到那份登录文件。

**使用 API Key**：也可以不登录 Claude 账号，改用你在 Anthropic Console 创建的 API Key（按用量计费）：在详情页的「登录」里点「使用 API Key」，粘贴 `ANTHROPIC_API_KEY`（以 `sk-ant-api` 开头）。它只保存在这台 Mac 上，用 Emperor 的本地密钥加密（与模型 Key、密码管理器用同一把），保存后立即生效，页面只显示「末 4 位」；「更换 API Key」「移除」在同一处。Claude 账号的登录令牌（以 `sk-ant-oat` 开头）不能填在这里。

**第三方端点**：如果你的 `~/.claude/settings.json` 在 `env` 里配置了兼容 Anthropic 接口的第三方端点（`ANTHROPIC_BASE_URL`，加上它的 `ANTHROPIC_AUTH_TOKEN` 或 `ANTHROPIC_API_KEY`，例如 DeepSeek 的 Anthropic 兼容接口），Claude Code 子任务照样使用它，详情页写「使用第三方端点 …」。启动 Emperor 时的环境变量、登录 shell（例如 `~/.zshrc`）里导出的 `ANTHROPIC_API_KEY` 也照样交给它；从程序坞或访达启动时，Emperor 会在需要时运行一次登录 shell 读取这几个变量，最多等 3 秒。

**哪一个生效**：API Key 和第三方端点的令牌优先于 Claude Code 自己的登录（这是 Claude Code 自己的规则）。Emperor 依次取 ① 你在 Emperor 里设置的 API Key；② `~/.claude/settings.json` 的 `env`；③ 启动 Emperor 时的环境变量；④ 登录 shell 里导出的变量，用第一个找到的；都没有时用 Claude Code 自己的登录。详情页的「登录」按 `claude auth status` 写明实际在用哪一个，并说明要改用 Claude 账号需要去掉哪一处。没有任何登录时，设置页显示「未登录」（详情页写「尚未登录」），主会话也会被告知它不可用，不会把任务交给它。

**从旧版本升级**：以前粘贴进 Emperor 的 Claude 令牌会在升级后第一次启动时删除，「设置 › 子智能体」顶部提示一次「Claude Code 现在用它自己的登录」，点「登录 Claude Code」登录一次即可（「知道了」关掉提示）。之前的子任务仍然可以继续对话。

**Codex**：在终端运行 `codex login` 登录，然后在设置页点「重新检测」。Codex 子智能体与你自己的 Codex 共用 `~/.codex/auth.json` 这一份登录，不复制令牌：子任务刷新登录后你自己的 Codex 也拿到新令牌，不会被登出。同一时间只有一个 Codex 子任务在运行，另一个排队等待。使用 API Key 的 Codex 只把密钥作为环境变量传给子任务。Emperor 从程序坞或访达启动时，也会读取你在 `~/.zshrc` 里导出的自定义提供方密钥（例如 Azure 的 `AZURE_OPENAI_API_KEY`），Azure 的 `api-version` 等查询参数也会保留。

Claude Code 子任务里执行的命令（Bash）拿不到 Emperor 交给它的 API Key 或端点令牌，任务里的提示注入无法用 `printenv` 读走这些凭据。

### 工作区与成果

要改文件的子任务在独立的工作区里工作，不碰你正在改的项目。它从项目「现在的样子」开始：最近一次提交，加上还没提交的改动和新建的文件（`.gitignore` 里的文件和 `.env` 之类的密钥文件不带过去）；改动超过 1 万个文件时，请让它从最近一次提交开始。「设置 › 子智能体 › 改代码的位置」决定 Claude Code、Codex 要改文件时默认在哪里改：「独立工作树」（默认）如上；「当前工作区」直接改项目，它改完之前主会话不能同时修改文件（见下面「等待工作区」）。主会话为某个任务明确指定了位置时，按它指定的来。不在 Git 里的文件夹，子任务默认只读审查；要它改文件时，它在这个文件夹的一份副本里改，主会话照常写自己的文件。

子任务完成后，会话里出现它的成果卡，样子和「已编辑 N 个文件」一样，例如「Codex 改了 6 个文件 +120 −8」，下面列出文件：

- 「查看差异」逐个文件看它改了什么。
- 「应用到项目」把这些改动合并进项目现在的样子：你在它工作期间改过的其他文件保持不变，同一个文件两边都改过时按内容合并。合并不了的文件列为冲突，这时一个文件也不写，成果保留；改好这些文件后可以「再次应用」。应用之后卡片显示「已应用到项目」和「撤销」，撤销会把这些文件恢复到应用之前（之后又改过的文件会跳过），先确认一次。
- 「丢弃」删除这个成果，项目不变，先确认一次。
- 主会话的 Agent 也可以请求应用成果，每次都会弹出审批卡让你决定。
- 成果在应用、丢弃或会话被彻底删除（「最近删除」里清除）时一起清理；放了 14 天还没处理的成果，卡片上写「这个成果已保留 N 天，还没有处理。」并提供「清理」。

「设置 › 子智能体 › 高级 › 验证后再应用」默认关闭。打开后成果卡的主按钮变成「验证后再应用」，点开任务详情按顺序完成：「收集成果」→「独立验证当前成果」（运行你指定的验证命令，或勾选「我已检查上面的成果」）→「生成整合预览」→「应用此预览到原工作区」。

**等待工作区**：直接在项目里改文件的子任务（「当前工作区」）工作时，主会话要写同一个项目会等它。等了 10 秒以上，等待的那一步下面会显示「正在等待子智能体释放工作区 · 停止它」，点「停止它」停下那个子任务，主会话随即继续；停止主会话本身也会结束等待。

### 停止、重启与「标记为已结束」

**停止**：在子智能体的页面点「停止」，或在主会话里停止，都会先请它中断当前这一轮，5 秒内没停下就结束它的整组进程，再过 5 秒强制结束，最多约 10 秒；排在它后面、还没送达的消息一并取消。停止主会话会停下这个会话里所有正在运行的子任务（包括只读的），目标转为「已暂停」。按 Cmd+Q 退出 Emperor 最多等 10 秒。

**退出或重启后**：Emperor 退出（包括强制退出）或电脑重启时还在运行的子任务，下次启动显示为「已中断」，不会自动重新执行；它占用的并发名额会释放，已经写出的文件保留，可以在主会话里继续安排任务。还没送出的消息记为送达情况未知，没回答的提问作废。

**标记为已结束**：两种情况下任务会停在那里等你处理——无法确认它已经停下（显示「结果待确认」，它的工作区暂时锁住），或者排着队、还没开始就遇到了重启。确认不再需要后，在主会话的环境信息卡、子智能体的页面或任务详情里点「标记为已结束」（不再二次确认）：工作区解锁，排队的消息取消，目标继续往下走，已保留的文件不受影响；它的工作区已经不在时，子智能体的页面随之关闭。主会话的 Agent 也可以请求标记为已结束，但每次都要你在审批卡上同意。

**诊断模式**：「设置 › 子智能体 › 高级 › 诊断模式」默认关闭。打开后，停止子智能体时会额外扫描并停止离开了它进程组的进程，用于排查问题；平时不需要打开。

### 费用与额度

用订阅登录（Claude 账号、ChatGPT 账号）的子任务只占用你的订阅额度，任务详情写「订阅额度，不计费用」，不会因为子智能体报告的名义费用被拦下，只受每次运行的轮数和运行时长限制。用 API Key（包括 Console 账号登录）的子任务按估算费用计入「单个任务的费用上限」（默认 10 美元）：Claude Code 把剩余额度交给它自己控制，超出时子任务停止并写明「已达到单任务费用上限」；Codex 按模型目录的单价估算，模型没有公开单价时改按 token 计，一个任务最多 200 万 token（「已达到单任务 token 上限」）。同一个任务里继续安排任务、或重启 Emperor 之后，已用的额度都不会清零；你发出下一条消息时开始新的任务。子任务用掉的 API 费用也计入主对话的「每个任务的费用上限」。

### 运行规则

- **谁能安排**：主会话的 Agent 和工作流都可以把任务交给已启用的 Claude Code / Codex。目标在等这些任务结束时不会为了等待反复调用模型，你的消息优先。定时任务和主会话共用同样的并发与权限边界；定时任务里子任务提问时没有人回答，问题会退回给主会话的 Agent，说明需要你来回答。停止主会话后，晚到的子任务通知不会让它自己重新开始。
- **每次运行最多轮数**：Claude Code 一次运行默认最多调用模型 200 轮，可在「设置 › 子智能体 › 高级 › 每次运行最多轮数」改为 50–1000。用完时这次运行结束，主会话可以发消息让它接着做。
- **长时间等待**：Codex 子智能体向你提问后，过几分钟再回答也不会超时；长时间没有输出的命令（例如构建）也不会被中途停止。只有超过「设置 › 子智能体 › 高级 › 单次运行时长上限」（默认 30 分钟，可选 10、30、60、120 分钟）时才会停止，结果里写明原因是超时。多轮对话、输出很长的 Codex 子智能体也可以继续安排任务。
- **开发环境**：子智能体在自己隔离的主目录里运行（Claude Code 用 Emperor 为它准备的专用目录），读不到你的 `~/.gitconfig`、SSH 密钥、nvm 等工具链和 gh 登录。「设置 › 子智能体 › 高级 › 开发环境」逐项决定带上哪些：「Git 身份」（提交时用你 git 配置里的姓名和邮箱）和「网络代理」默认打开；「SSH 代理」（经你的 SSH agent 访问远端仓库，不复制密钥）、「开发工具链」（nvm 的默认 node、volta、rustup / cargo、pyenv）和「允许子智能体使用 GitHub 登录」（把 `gh auth token` 的令牌交给子任务，并在它私有的 gh 配置里写一份，Claude Code 的 Bash 也能用 gh）默认关闭，按需打开。从程序坞启动 Emperor 时，这些变量从你的登录 shell 读取。仓库里的 `CLAUDE.md`、`AGENTS.md` 会作为说明交给 Claude Code，`AGENTS.md` 的摘要会附在 Codex 的任务简报里；仓库的 `.claude/settings.json` 不会被加载（其中的权限放行规则可能绕过 Emperor 的审批）。
- **失败原因**：Claude Code 子任务失败时，任务详情写明原因和下一步：「Claude Code 的登录已失效或过期」（401，点「登录 Claude Code」重新登录，或换一个新的 API Key）、「被限流了」（429 或订阅额度用尽，稍后再试）、「账户余额或计费状态不允许继续调用」（检查 Anthropic Console 的余额与付款方式）、「达到了这次运行的最多轮数」、「对话超出了模型的上下文长度」（把任务拆小或新开子智能体），其他情况为「子智能体这一轮执行失败」并附子智能体报告。子智能体这一轮失败时，子智能体那一行、任务详情和主会话的 Agent 收到的结果都以一句原因开头：服务返回的错误读成一句话，例如「Codex 这一轮失败：被限流了（HTTP 429，rate_limit_error）：…」；模型不可用时写明是哪个模型、去哪里换，例如「Codex 不支持模型 gpt-6.1-sol（ChatGPT 账号登录）。请在「设置 › 子智能体 › Codex › 默认模型」里换一个可用的模型。」，任务详情有「打开子智能体设置」。Codex 或 Claude Code 还没开始工作就失败时（准备工作区、准备运行环境、启动进程），子智能体那一行、任务详情（「原因：…」）和主会话的 Agent 收到的结果都写明哪一步、为什么，例如「准备工作区失败：当前签名执行环境中没有可用 Git（探测失败：timeout）。」；任务详情另给下一步，`~/Library/Logs/Emperor Agent/core.log` 里同时记一行 `external run failed`（不含密钥和你的任务内容）。
- **版本**：Claude Code 使用你本机安装的 `claude`，需要 2.1.79 或更高（它支持 `claude auth status` 与 `claude auth login --console`）；用官方命令安装的 Claude Code 会自己在后台更新，Homebrew 安装的用 `brew upgrade claude-code` 升级；两者有新版本时也可以在设置页升级（见上面「版本与升级」）。Codex 使用本机安装的 CLI，需要与 Emperor 验证过的版本同属一个次版本（目前是 0.153.x 与 0.163.x）；同一次版本但协议有变化时显示「可能不兼容」，仍然可以运行，失败时结果里会注明可能是版本原因；其他版本显示「版本不兼容」和需要的版本范围。
