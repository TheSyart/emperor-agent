## 定时任务

点击侧栏的「定时任务」打开定时任务页（`/scheduler`），可以创建、编辑、暂停、恢复、立即运行和删除任务。Agent 也可以通过 `scheduler` 工具管理任务。

- **列表**：顶部是搜索框和“全部 / 已开启 / 已暂停 / 已完成”四个标签。每行显示任务名称、调度规则与下次运行时间（例如「星期五（时间：18:00） · 下次运行 3天后」），运行中、排队中或上次失败时带状态标记。已运行过、已停用的一次性任务归入“已完成”。
- **创建**：右上角「创建 ▾」提供「新建任务」和两个预填模板：「每日摘要」（工作日 09:00）和「每周回顾」（星期五 18:00）。模板只填好表单，保存前可以修改。
- **编辑**：点击一行打开任务对话框，查看状态、启用开关、任务详情、最近错误和运行历史，底部提供「删除」（需再次确认）、「立即运行」和「保存」。
- **行菜单**：每行右侧的 `⋯` 提供「立即运行」、「暂停」（已停用的任务显示「恢复」）和「删除」（删除前确认，任务和运行历史一并删除）。
- 受保护的系统任务可以暂停、恢复或立即运行，但不能编辑或删除。
- 列表下方显示服务状态（运行、并发和排队情况）以及关闭应用和错过触发点的处理规则。
- 「指定时间」必须选好日期和时间，并且晚于现在，否则不能保存；编辑一个已经过期的一次性任务时，不改时间就可以照常保存其他内容。
- 定时任务服务没有启动时（例如另一个 Emperor 进程正在使用同一个数据目录运行定时任务），列表上方会写明原因；「设置 › 高级 › 诊断」的「定时任务存储」一行也会显示。
- `jobs.json` 里某个任务读不出来时，只有它被移到数据目录的 `scheduler/jobs.rejected.json`，其他任务照常加载和运行；列表上方会提示一次，诊断里列出被移走任务的名称和原因。

定时任务运行完成或失败时，侧栏的通知铃铛会收到一条通知；此时正在查看定时任务页的话，这条通知直接记为已读。

任务支持：

- `at`：指定时间运行一次；
- `every`：按固定间隔运行；
- `cron`：按 cron 表达式和时区运行；
- `misfirePolicy`：应用停机期间错过触发点后的处理方式；
- `deleteAfterRun`：运行后删除一次性任务；
- `deliver`：把结果投递到会话界面。

任务类型：

- `agent_turn`：把任务消息作为一条用户消息提交到任务绑定的会话，并等待这一轮结束。在定时任务页新建任务时，任务绑定到你当时正在看的会话；旧版本留下的、没有绑定会话的任务在最近使用的会话里运行。定时任务在后台运行：不会把界面切到它的会话，你正在看的会话保持不变。目标会话有待回答的问题或审批时，本次运行会报错而不是跳过交互。
- 定时运行中遇到需要审批或回答的操作时，因为没有人在场，这些请求会被直接拒绝，模型照常收尾；这次运行记为「需要审批，已拒绝」，记录里写明被拒绝的操作。需要这类操作的任务，请先在会话里把权限预设调到允许它的级别，或改为手动执行。
- 一次定时运行最长 30 分钟，超时后停止，记为「已取消」（原因为超时），之后的触发照常进行。模型请求失败的运行记为「失败」并带错误码（例如 Key 失效为 `AUTH`）；你在会话里点停止的运行记为「已取消」。
- `system_event`：系统任务。`watchlist-check` 会检查 Watchlist，需要时再发起一轮 `agent_turn`。

旧版本创建的 `team_wake` 任务已不再支持，运行时会报错，请删除或改为 `agent_turn`。

`misfirePolicy` 有三种：`skip`（默认）只记录错过并移到下一个未来触发点；`latest` 只补跑最后一个错过的触发点；`catch-up-one` 只补跑最早一个错过的触发点。无论错过多少次，每个任务每次启动最多补跑一次。电脑睡眠期间错过的触发点按同样的规则处理：醒来时比触发点晚 1 分钟以上，就当作错过，`skip` 的任务记一条「已跳过」，其余两种补跑一次。启动时补跑的任务在插件同步之后才开始，插件提供的 Hook 对它照常生效。

同一个数据目录同时只有一个进程运行定时任务（`scheduler/scheduler.lock`）：例如编辑器里的 ACP 会话先占用了它，桌面端就不运行定时任务并说明原因；占用的进程退出后，桌面端会在 5 分钟内自动接手。

定时任务最多同时运行 2 个、同一目标最多 1 个，最多排队 100 个，这些上限不能从界面或任务放宽。应用退出时定时任务服务停止接收新任务并取消进行中的工作，它不会作为系统后台服务继续运行。重启后已经开始运行的任务不会自动重放，无法确认结果时记为 `interrupted`。

## Hooks

入口是“设置 → 高级 → Hooks”。Hooks 在指定事件发生时自动运行命令，配置写在 `hooks.json` 中，只支持 `command` 类型的 handler。

- 配置文件：`stateRoot/hooks.json`，按“事件 → matcher 分组 → hooks”组织，可以在“配置”标签编辑；保存时会校验并立即重新加载。
- 支持的事件：`SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop`、`SubagentStart`、`SubagentStop`。其他事件和非 `command` 类型的 handler 会被忽略，页面会列出被跳过的项。
- Hook 在会话工作目录中按配置顺序串行运行，多个结果取最严格的决定。环境变量 `CLAUDE_PROJECT_DIR` 指向当前项目目录，单个 Hook 默认超时 10 分钟。这里说的是你自己写在 `hooks.json` 里的 Hook；插件带来的 Hook 在进程沙箱里运行，只拿到系统变量与插件清单声明的变量，默认 30 秒、最多 120 秒超时，见[工具、Skill 与 MCP › Plugins](tools-skills-mcp.md#plugins)。

| 事件               | 可以做什么                                   |
| ------------------ | -------------------------------------------- |
| `SessionStart`     | 追加上下文                                   |
| `UserPromptSubmit` | 拒绝本次提交，或追加上下文                   |
| `PreToolUse`       | 拒绝工具调用，或要求先询问你                 |
| `PostToolUse`      | 阻止结果并返回反馈，或追加上下文             |
| `Stop`             | 阻止本轮结束、让 Agent 继续（每轮最多 3 次） |
| `SubagentStart`    | 为子智能体追加上下文                         |
| `SubagentStop`     | 仅观察                                       |

Hook 输出中的 `updatedInput`、`systemMessage` 和 `continue: false` 会被解析并记录警告，但不会生效。Hook 不能放宽权限预设或沙箱。

“设置 → 高级 → Hooks”分为三个标签：

- **配置**：查看已加载的配置文件、加载错误和各事件的命令数，编辑 `hooks.json`，支持「还原」「校验」「保存」（⌘S 保存）。
- **测试**：选择事件并输入 matcher 查询，查看会匹配到的命令；对某条命令点击「执行」后还需「确认执行」才会真正运行，结果显示决定、退出码和耗时。编辑器中尚未保存的内容也按当前内容匹配和运行。
- **审计**：按事件和结果筛选当前会话的 Hook 运行记录，展开查看 matcher、退出码、耗时和 stderr。审计记录来自当前会话 log 中的 Hook 调用与结果事件。

项目目录中的 `.claude/settings.json` 当前不会被加载，项目信任设置接口也已下线。

## Watchlist

Watchlist 由 `memory/watchlist.md` 定义，在“设置 → 记忆”右上角「更多 › Watchlist」中编辑。可以在该页点击右上角的「手动检查」，也可以由定时任务中的 `watchlist-check` 系统任务定期检查；判断需要处理时会发起一轮普通 Agent turn。它不提供 Slack、邮件或社交平台连接器。

## 桌宠 companion

“设置 → 常规 → 外观 → 桌宠”可以启用或关闭 companion，默认关闭；窗口出错时开关下方显示最近的错误。窗口由主 Electron 进程托管。桌宠只投影空闲、工作等状态，不能代替真实的任务状态，也不能直接修改 Core 状态。

## Claude Code / Codex 子智能体与长任务

Claude Code 和 Codex 子智能体默认关闭，因为它们会使用你自己的订阅额度（ChatGPT、Claude 订阅）或 API 计费。在「设置 › 子智能体」打开后，Emperor 第一次把任务交给 Claude Code 或 Codex 时，会在对话里弹出确认卡：「本次允许」只对这一轮对话有效；「以后都允许」以后不再询问（在设置里关闭再打开会恢复询问）；「不允许」时这个任务改由 Emperor 的本地子智能体完成。定时任务等无人值守的运行无法询问，除非你选过「以后都允许」，否则不会使用 Claude Code / Codex。升级前没有改过这项设置的用户，Claude Code 与 Codex 子智能体会被关闭，第一次打开设置页时会看到说明。计划模式下子智能体只能做只读审查。

已启用的 Claude Code/Codex 可被父 Agent 和工作流调度。目标等待未结束的外部任务，不为轮询而反复调用模型；用户消息优先。定时任务共享同一并发/权限边界，无法人工回答的子任务问题返回 needs_user。停止根任务后不会被晚到子任务通知自动复活。

费用与额度：用订阅登录（Claude 订阅、ChatGPT 账号）的子任务只占用你的订阅额度，任务详情写「订阅额度，不计费用」，不会因为子智能体报告的名义费用被拦下，只受每个任务的轮数和运行时长限制。用 API Key 的子任务按实际估算费用计入「单任务费用上限」（默认 10 美元）：Claude 把剩余额度交给它自己控制，超出时子任务停止并写明「已达到单任务费用上限」；Codex 按模型目录的单价估算，模型没有公开单价时改按 token 计，一个任务最多 200 万 token（「已达到单任务 token 上限」）。同一个任务里继续安排任务、或重启 Emperor 之后，已用的额度都不会清零；你发出下一条消息时开始新的任务。子任务用掉的 API 费用也计入主对话的「每个任务的费用上限」。

工作区与成果：要改文件的子任务在独立的工作区里工作，不碰你正在改的项目。它从项目「现在的样子」开始：最近一次提交，加上还没提交的改动和新建的文件（`.gitignore` 里的文件和 `.env` 之类的密钥文件不带过去）；改动超过 1 万个文件时，请让它从最近一次提交开始。不在 Git 里的文件夹，子任务默认只读审查；要它改文件时，它在这个文件夹的一份副本里改，主会话照常写自己的文件。

子任务完成后，会话里出现它的成果卡，样子和「已编辑 N 个文件」一样，例如「Codex 改了 6 个文件 +120 −8」，下面列出文件：

- 「查看差异」逐个文件看它改了什么。
- 「应用到项目」把这些改动合并进项目现在的样子：你在它工作期间改过的其他文件保持不变，同一个文件两边都改过时，按内容合并。合并不了的文件会列为「冲突」，这时一个文件也不写，成果保留；改好这些文件后可以「再次应用」。应用之后成果卡上有「撤销」，把这些文件恢复到应用之前（之后又改过的文件会跳过）。
- 「丢弃」删除这个成果，项目不变。
- 父 Agent 也可以请求应用成果，每次都会弹出审批卡让你决定。
- 成果在应用、丢弃或会话被彻底删除（「最近删除」里清除）时一起清理；放了 14 天还没处理的成果，卡片上会提示「清理」。

「设置 › 子智能体 › 高级 › 验证后再应用」默认关闭。打开后成果不能直接应用：要在任务详情里先收集回执、运行你指定的验证命令、生成整合预览，再应用。

等待工作区：直接在项目里改文件的子任务（`shared-exclusive`）工作时，主会话要写同一个项目会等它。等了 10 秒以上，等待的那一步下面会显示「正在等待子智能体释放工作区 · 停止它」，点「停止它」停下那个子任务，主会话随即继续；停止主会话本身也会结束等待。

停止子智能体：先请它中断当前这一轮，5 秒内没停下就结束它的整组进程，再过 5 秒强制结束，最多约 10 秒。按 Cmd+Q 退出 Emperor 最多等 10 秒。

退出或重启后：Emperor 退出（包括强制退出）或电脑重启时还在运行的子任务，下次启动显示为「已中断」，不会自动重新执行；它占用的并发名额会释放，已经写出的文件保留，可以在主会话里继续安排任务。少数情况下无法确认它已经停下（显示「结果待确认」），这时它的工作区会暂时锁住。确认不再需要后，在主会话的环境信息卡、子智能体对话页或任务详情里点「标记为已结束」：工作区解锁，目标继续往下走，保留的文件不受影响。父 Agent 也可以请求标记为已结束，但每次都要你同意。

诊断模式：「设置 › 子智能体 › 高级 › 诊断模式」默认关闭。打开后，停止子智能体时会额外扫描并停止离开了它进程组的进程，用于排查问题；平时不需要打开。

Codex 登录：Codex 子智能体与你自己的 Codex 共用 `~/.codex/auth.json` 这一份登录，不再复制令牌，子任务刷新登录后你自己的 Codex 也拿到新令牌，不会被登出。同一时间只有一个 Codex 子任务在运行，另一个会排队等待。使用 API Key 的 Codex 只把密钥作为环境变量传给子任务。Emperor 从程序坞或访达启动时，也会读取你在 `~/.zshrc` 里导出的自定义提供方密钥（例如 Azure 的 `AZURE_OPENAI_API_KEY`），Azure 的 `api-version` 等查询参数也会保留。

Claude Code 登录：在「设置 › 子智能体 › Claude Code」的「登录」一栏点「设置令牌」。

- 订阅账号（Pro、Max 等）：在终端运行 `claude setup-token`，按提示在浏览器里登录，把它打印出的长期令牌（以 `sk-ant-oat` 开头）粘贴进来。
- API Key：选「API Key」，粘贴 `ANTHROPIC_API_KEY`（以 `sk-ant-api` 开头，在 Anthropic Console 创建）。
- 令牌只保存在这台 Mac 上，用 Emperor 自己的本地密钥加密（与模型 Key、密码管理器用同一把），保存后立即生效；页面只显示「已设置 · 末 4 位」，不会再显示令牌本身。「更换令牌」「移除令牌」在同一栏。

Emperor 按这个顺序找 Claude Code 的登录，用第一个找到的，不把几处的密钥混在一起：① 你在 Emperor 里设置的令牌；② `~/.claude/settings.json` 里 `env` 的 `CLAUDE_CODE_OAUTH_TOKEN` 或 `ANTHROPIC_API_KEY`；③ `~/.claude/.credentials.json`（只用其中的访问令牌）；④ 启动 Emperor 时的环境变量，以及登录 shell（例如 `~/.zshrc`）里导出的这几个变量——从程序坞或访达启动时，Emperor 会在需要时运行一次登录 shell 读取它们，最多等 3 秒。Emperor 不读取 macOS 钥匙串，所以在终端里用 `/login` 登录、只存在钥匙串里的账号，需要按上面的方法设置令牌。「登录」一栏写明当前用的是哪一处。

`.credentials.json` 里的访问令牌有效期很短：过期后显示「令牌已过期」，过期前 10 分钟显示「令牌即将过期」（长任务可能中途失败）；改用 `claude setup-token` 的长期令牌可以避免。没有任何可用登录时，Claude Code 显示「需要登录配置」，主会话也会被告知它不可用，不会再把任务交给它。

Claude Code 子任务失败时，任务详情写明原因和下一步：「登录令牌已失效或过期」（401，重新设置令牌）、「被限流了」（429 或订阅额度用尽，稍后再试）、「账户余额或计费状态不允许继续调用」（检查 Anthropic Console 的余额与付款方式）、「达到了这次运行的最多轮数」、「对话超出了模型的上下文长度」（把任务拆小或新开子智能体），其他情况为「子智能体这一轮执行失败」并附子智能体报告。

开发环境：子智能体在自己隔离的主目录里运行，读不到你的 `~/.gitconfig`、SSH 密钥、nvm 等工具链和 gh 登录。「设置 › 子智能体 › 高级 › 开发环境」逐项决定带上哪些：「Git 身份」（提交时用你 git 配置里的姓名和邮箱）和「网络代理」默认打开；「SSH 代理」（经你的 SSH agent 访问远端仓库，不复制密钥）、「开发工具链」（nvm 的默认 node、volta、rustup / cargo、pyenv）和「允许子智能体使用 GitHub 登录」（把 `gh auth token` 的令牌交给子任务，并在它私有的 gh 配置里写一份，Claude Code 的 Bash 也能用 gh）默认关闭，按需打开。从程序坞启动 Emperor 时，这些变量从你的登录 shell 读取。仓库里的 `CLAUDE.md`、`AGENTS.md` 会作为说明交给 Claude Code，`AGENTS.md` 的摘要会附在 Codex 的任务简报里；仓库的 `.claude/settings.json` 不会被加载（其中的权限放行规则可能绕过 Emperor 的审批）。

每次运行最多轮数：Claude Code 一次运行默认最多调用模型 200 轮，可在「设置 › 子智能体 › 高级 › 每次运行最多轮数」改为 50–1000。用完时这次运行结束，主会话可以发消息让它接着做。

Claude Code 子任务里执行的命令（Bash）拿不到它自己的登录令牌或 API Key，任务里的提示注入无法用 `printenv` 读走这些凭据。

长时间等待：Codex 子智能体向你提问后，过几分钟再回答也不会超时；长时间没有输出的命令（例如构建）也不会被中途停止。只有超过运行上限（默认 30 分钟）时才会停止，结果里写明原因是超时。多轮对话、输出很长的 Codex 子智能体也可以继续安排任务。

版本：Claude Code 默认使用随 Emperor 发布的版本，本机 claude 自动更新不会影响它；在「设置 › 子智能体 › Claude Code › 查看详情」打开「使用本机安装的 claude」后改用本机版本，需要 2.1 或更高。Codex 使用本机安装的 CLI，需要与 Emperor 验证过的版本同属一个次版本（目前是 0.153.x）；同一次版本但协议有变化时显示「可能不兼容」，仍然可以运行，失败时结果里会注明可能是版本原因；其他版本显示「版本不兼容」和需要的版本范围。
