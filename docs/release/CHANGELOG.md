# 更新日志

本文件记录 Emperor Agent 的用户可感知变化，格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。每个版本按「新增 / 改进 / 修复 / 安全 / 移除」分组；安全修复只写影响，不写利用细节。

## [0.2.0] - 未发布

0.2.0 是 Emperor Agent 的第一个正式版（Stable），与 `v0.1.0-preview.4` 相比的变化如下。只支持 macOS（Apple 芯片与 Intel）；安装包和预览版一样不签名、不经 Apple 公证，首次打开的步骤写在 Release 正文的第一段。更新到这一版后，电脑操作的辅助功能与屏幕录制、听写的麦克风与语音识别需要重新允许一次。

### 新增

- Claude Code 与 Codex 子智能体：主会话的 Agent 可以把子任务交给你电脑上的 Claude Code 或 Codex，与本地子智能体一起在「子智能体」里管理。它们使用你自己的订阅额度或 API 计费，所以默认关闭，在「设置 › 子智能体」打开；第一次把任务交给它们时，对话里会弹出确认卡（本次允许 / 以后都允许 / 不允许），选「不允许」时任务改由本地子智能体完成，定时任务等无人值守的运行除非选过「以后都允许」否则不使用它们。计划模式下它们只能做只读审查。Claude Code 使用你本机安装的 `claude`（需要 2.1.79 或更高，没装时设置页给出官方安装命令）；Codex 使用本机 CLI，0.153.x 与 0.163.x 都可用，同一次版本里协议有变化时提示「可能不兼容」但仍可运行。
- 「设置 › 子智能体」一屏：本地子智能体、Claude Code、Codex 各一行，写着是否就绪和默认模型，右侧是启用开关和详情页；改动立即保存。本地子智能体可以固定用某一条模型（默认跟随对话）。「子任务」一组有同时运行（最多 4 个）、改代码的位置（独立工作树 / 当前工作区）和单个任务的费用上限；每次运行最多轮数（默认 200）、单次运行时长上限（默认 30 分钟）、开发环境、验证后再应用、诊断模式在「高级」里。
- 子智能体的版本检测与一键升级：打开「设置 › 子智能体」时（以及每天第一次启动时）向 npm 的公开仓库查 Claude Code 和 Codex 的最新版本号，不发送任何账号或设备信息。有新版本时页面顶部提示（「全部升级」「稍后」），那一行写「本机 x · 可升级到 y」并多一个「升级」，导航里的「子智能体」带一个小点。确认后按你当初的安装方式升级（npm 全局安装、Homebrew、Claude 官方安装器），不用管理员权限，可以查看过程和取消；升级期间不把新的子任务交给它，正在运行的先跑完；完成后重新检测并提示，失败时写明原因（例如没有写入权限）并给出可复制的命令。Codex 只升到 Emperor 验证过的版本，更新的显示「尚未验证」。详情页新增「版本」：本机版本、安装方式、最新版本、已验证的版本和「检查更新」。升级不改动 `~/.codex`、`~/.claude` 里的登录和设置。
- Claude Code 登录：用 Claude Code 自己的登录。点「登录 Claude Code」，Emperor 运行 `claude auth login` 并打开浏览器，在浏览器里登录一次，设置页自己显示已登录（可以「取消」；10 分钟内没有完成或出错时写明原因，并给出一行命令供你在「终端」里自己登录）；Console 账号用「用 Console 账号登录（按用量计费）」；「退出登录」运行 `claude auth logout`。登录由 Claude Code 保存在 Emperor 为它准备的专用目录里，Emperor 不读取、不保存、不转交；设置页用 `claude auth status` 显示登录方式和账号。也可以用你自己的 Anthropic Console API Key（「使用 API Key」，本地密钥加密保存，只显示末 4 位），`~/.claude/settings.json` 里配置的第三方端点和环境变量里的 `ANTHROPIC_API_KEY` 照常可用，设置页写明哪一个在生效。没有登录时主会话不会把任务交给它；失败时任务详情写明原因（登录失效、限流、余额、最多轮数、上下文过长）和下一步。Codex 与你自己的 Codex 共用 `~/.codex/auth.json` 这一份登录（不复制令牌，刷新后你自己的 Codex 不会被登出），支持 Azure 等自定义提供方的查询参数，从程序坞启动时也能读到 `~/.zshrc` 里导出的提供方密钥；提问后几分钟再回答、长时间没有输出的命令都不会被中途停止。
- 子智能体的成果回到会话：要改文件的子任务从项目现在的样子开始（包括没提交的改动和新文件，遵守 `.gitignore`），在独立的工作区里改；完成后会话里出现成果卡「Codex 改了 N 个文件 +A −D」，可以查看差异、「应用到项目」（与项目当前改动三方合并，有冲突时一个文件也不写并列出冲突文件，应用后可撤销）或丢弃，主会话的 Agent 请求应用时会弹出审批卡。不在 Git 里的文件夹默认只读审查，要写时在副本里改。主会话等子智能体释放工作区超过 10 秒会显示「停止它」。成果在应用、丢弃或会话彻底删除时清理，放了 14 天的会提示清理。回执、独立验证和整合预览的流程在「设置 › 子智能体 › 高级 › 验证后再应用」，默认关闭。
- 子智能体的页面可以直接发消息：本地子智能体在下一轮读到，Codex 运行中直接插话，其余在这一轮结束后送达；它向你提问时问题卡出现在输入框的位置。下面是「返回父智能体」「返回主会话」，标题旁有返回箭头。环境信息卡里每个子智能体显示运行了多久；子智能体使用 36 个角色头像，按身份固定分配，侧栏和委派记录里一致。
- 子智能体停下与恢复：停止最多约 10 秒（先中断，5 秒后结束整组进程，再 5 秒强制结束）；Emperor 退出、崩溃或电脑重启时还在运行的子任务，下次启动显示「已中断」，不会自动重新执行，释放并发名额，已经写出的文件保留。无法确认已经停下的任务（「结果待确认」）或重启前排队未开始的任务，可以在环境信息卡、子智能体页面或任务详情里「标记为已结束」，工作区解锁、目标继续往下走；主会话的 Agent 也可以请求标记，但要你同意。
- 子智能体的费用如实计算：用订阅登录时只显示「订阅额度，不计费用」，只受轮数和运行时长限制；用 API Key 时按估算费用计入单个任务的费用上限（Codex 按模型目录单价估算，单价未知时一个任务最多 200 万 token），运行中越过上限就停止，重启后已用额度不清零，并计入主对话的任务费用上限。
- 子智能体可以用你的开发环境：提交时使用你的 git 身份，沿用网络代理；在「设置 › 子智能体 › 高级 › 开发环境」可以另外打开 SSH 代理、nvm / volta / cargo / pyenv 工具链和 GitHub 登录（默认关闭）。Claude Code 子任务会读到仓库的 `CLAUDE.md`，Codex 的任务简报附上 `AGENTS.md` 摘要。
- 添加模型改为三步对话框：选供应商或粘贴地址并填 Key → 自动测试连接、拉取模型列表，按家族分组、按能力筛选、多选 → 按厂商接口与内置目录预填上下文、每次输出和思考强度并标出来源，一次保存全部。默认只发送确定支持的参数（不接受温度的模型不发温度）；Ollama、LM Studio 在本机运行时直接显示。供应商卡片的「管理模型」可以勾选增删同一连接下的模型；输入框模型菜单底部新增「添加模型…」。
- 首次启动的接入引导：还没有任何模型时，打开 Emperor 先看到铺满窗口的引导。
  - 有两种方式：「使用本机模型」（Ollama、LM Studio 在运行时排在前面，标「推荐」，不需要 Key）和「使用 API Key」。
  - 之后用添加模型的同一套步骤连接、选择模型；数值都已知时选完就保存。
  - 「准备好了」页在后台测试一次，「开始使用」回到对话。
  - 「稍后配置」以后不再弹出，空会话的输入框下方会留着「开始接入」。已有模型但用不了时，那里写明原因并给出「去处理」。
- 空会话的标题会叫你的称呼：档案里写了称呼后显示「小周，今天想推进什么？」。在设置里或让 Agent 改了称呼，标题立即更新。
- Agent 可以用 `web_fetch` 读取公开网页（默认开启）：网页转成 Markdown，返回标题、跳转后的地址和正文，长页面分段读取；不带 Cookie 和登录状态，地址或跳转指向本机、内网地址时直接拒绝，单页最多读取 10 MB；网页内容按不可信的外部内容交给模型。模型使用 DeepSeek 官方 API 时，Agent 还可以用 `web_search` 通过 DeepSeek Search API 搜索网页（使用该模型的 API Key，按次计费）。
- 新增「设置 › 高级」：「网络工具」可以分别关闭网页读取和网页搜索，关闭后工具从 Agent 的工具列表和「能力 › 工具」里消失（插件 Hook 里的 `WebFetch` 匹配现在对应 `web_fetch`）；「任务预算」限制一个任务（你发出的一条消息和它引出的全部工作）能用多少：每轮最多 400 步（定时任务与目标每轮 120 步）、同时最多运行 8 个子智能体（多出的排队）、最多启动 64 个子智能体、子智能体的结果最多唤醒对话 32 次，达到步数上限时本轮停止并在对话里说明原因；Hooks 与诊断也在这里的二级页。
- 「设置 › 高级 › 存储」：列出会话、附件、溢出文件、记忆版本、用量账本、委派和其他各占多少磁盘空间；「清理」先确认，再删除 30 天没有变化且不属于任何会话的溢出文件、到期的「最近删除」会话、记忆版本索引之外的快照，以及会话已删除的委派留下的隔离目录和临时文件（对话、附件与设置不受影响），完成后写明释放了多少；每次启动后也会在后台清理一次。
- 备份与恢复：「设置 › 高级 › 存储 › 备份与恢复」可以把设置、记忆、Skills、插件、项目、定时任务和会话（可选）导出为一个 `.emperor-backup.zip`；密码管理器、本地密钥和子智能体的登录令牌只在设了备份口令时才加密放进去，明文模型 Key 在备份里也会先加密。「从备份恢复」先把当前数据移到 Emperor Home 的 `migrations/backup-<时间>/`，然后重新启动并完成恢复，失败时自动还原。
- 数据版本与降级保护：Emperor 自己的配置文件都写明版本（你自己的 `mcp_config.json`、`hooks.json` 不会被加上版本号，升级迁移也不碰它们）；用较旧的 Emperor 打开更新版本写入的文件时只读取、不改写也不当作损坏文件移走，「存储」里提示「这个文件来自更新版本的 Emperor，当前版本只读」，比上次打开的版本旧时启动后也会提示。升级时的数据迁移先备份要改动的文件，结果记在 `migrations/log.jsonl`，失败时从备份还原。
- 检查更新：启动 30 秒后和之后每 24 小时向 GitHub 查看有没有同一渠道的新版本（Preview 版看 Preview 与 Stable，Stable 版只看 Stable），请求不带账号、令牌或设备标识，连不上时静默重试、每天最多 3 次，可在「设置 › 常规 › 更新」关闭（关闭后不发任何请求）。有新版本时「设置 › 常规」最上方和侧栏通知显示「Emperor 0.2.1 可用 · 查看更新说明 · 下载」；Emperor 下载这台 Mac 的 DMG 并显示进度，用 `SHA256SUMS.txt` 核对 SHA-256（不符即拒绝并删除），装有并登录了 GitHub CLI 时再用 `gh attestation verify` 核对来源（不能时只核对 SHA-256 并写明），通过后放进「下载」文件夹、在访达中显示，并写出替换步骤（拖进「应用程序」、首次打开在「系统设置 › 隐私与安全性」允许、重新授予辅助功能、屏幕录制、麦克风与语音识别）。未签名的安装包不能自动替换，Emperor 也不会打开或运行它。「设置 › 高级 › 诊断」显示内置 Electron 的版本，落后最新发布 2 个以上主版本时提醒更新。
- 日志、崩溃转储与诊断包：主进程和 Core 的日志写进 `~/Library/Logs/Emperor Agent`（`main.log`、`core.log`，各按 5 MB 轮转、保留 5 份，密钥与令牌写入前就换成 `***`），进程崩溃时在同一目录的 `Crashpad` 留下只在本机的转储；启动失败时日志里有完整原因，恢复页多了「打开日志」。「设置 › 高级 › 诊断」和恢复页可以「导出诊断包」：先列出 zip 里的每个文件，确认后再选位置保存，里面没有会话内容、记忆和密钥。不做遥测，也不上传崩溃报告。
- 删除会话可以撤销：删除后的提示条带「撤销」（10 秒），会话原样回来；删除的会话进入「设置 › 常规 › 已归档对话」里的「最近删除」，保留 30 天，可以恢复或永久删除（需要确认），到期自动清除。关闭还有程序在运行的终端标签时先确认。
- 侧栏搜索除了标题，稍停后还会找出聊天内容里提到这段文字的会话，并显示命中的那一句；焦点在会话行上时可用 ↑ / ↓ 切换会话；等你回答或审批的会话用橙色圆点标出。
- 输入框新增：「+」菜单的「截图」（macOS，用系统截图框选区域或窗口，图片直接成为附件）；输入框为空时发送键的位置换成麦克风；目标条的「编辑」把 `/goal edit <目标>` 放进输入框修改；发送前检测消息里疑似的 API Key、令牌和私钥，可以遮掩后发送。
- 「设置 › 常规 › 会话 › 新会话的权限」：选择新会话从哪个权限预设开始（选完全访问时先确认）。
- 对话资源统一展示：输入框保留可编辑的网址，消息里的网页与 GitHub 对象用网站标记、类型图标与摘要卡片显示，GitHub 区分仓库、PR、Issue、Commit、Release 和 CI；网页详情主动展开后才联网，失败可重试。环境信息卡逐条列出来源和出处。文件图标改为逐类绘制的图标，统一用于消息、附件、资源清单与文件面板，文件链接支持 `#L12`、`:12`、`:12:3` 定位行，缺失文件明确显示不可用。「设置 › 常规 › 会话 › 显示网站图标」（默认关闭）打开后网页引用显示真实网站图标，关闭时不访问链接网站。
- 文件统一在右侧「文件」面板打开，普通聊天和非 Git 项目也可以：回复、附件、来源与「已编辑 N 个文件」卡里的文件都能查看当前内容（Markdown／源码、文本、代码、常见图片）；图片使用全窗口灯箱，支持缩放、拖动、旋转与同组切换。

### 改进

- Claude Code 子智能体按 Anthropic 的条款接入：只运行你在本机安装、未经修改的 Claude Code，安装包不再附带它（小了约 220 MB）；登录走 Claude Code 自己的流程（「登录 Claude Code」运行它自己的 `claude auth login`，在浏览器里完成，Emperor 不经手登录链接或代码），每个子任务、每次检测和登录共用 Emperor 为它准备的一个专用目录，登录一次一直有效，之前的子任务也能在这里继续对话。
- 界面换上新的配色与质感，布局仍是 Emperor 原来的：深色主题从偏蓝的灰改为暖中性灰，浅色主题有了层次（暖白画布、白色面板），金色只留给发送、链接、焦点和选中的开关；状态色、细线与阴影重新调过，中英文之间自动留出间距，启动时窗口底色与主题一致。界面细节统一到同一套设计令牌：小圆角统一为 8px、粗体统一为半粗、图标统一为 12 / 14 / 16 / 20px，样式不再依赖 Tailwind，启动时加载的全局样式小了约 18%。
- 状态标签、圆点、头像、提示条、空状态、输入框、搜索框、勾选框和页签换成统一的一套：输入框与下拉框同为 32px 高、细线描边，聚焦时显示金色焦点环；运行中的状态是金色呼吸点，审批和计划用橙色点；各处的搜索框都能用 Esc 清空、用 × 清除。
- 新的品牌标：一枚现代印章，侧栏、窄轨、空会话首屏、网页图标和应用图标都换成同一份矢量图形，随明暗主题变色；首次打开时的接入引导用整幅插图作底；安装包（DMG）窗口有了背景，应用与「应用程序」文件夹对齐箭头。
- 侧栏重新设计：从上到下是收起与后退 / 前进、Emperor 标志与搜索、通知，「新对话」（侧栏里唯一抬起的一块，悬停显示 ⌘N）和整页入口（Pull Request 只在 GitHub 插件启用时出现），置顶 / 项目 / 对话三组会话，底部是设置与明暗切换；收起后是一列窄图标。所有行统一 32px，分组标题旁的 + 与 ⋯ 悬停才出现，会话行显示紧凑时间（「3 小时」「昨天」「9月10日」），悬停换成 ⋯。窗口使用系统标题栏，侧栏、对话和工作台平铺，之间只有一条细线。
- 会话流变简洁：一轮里的思考和工具步骤收成一行，运行中写着当前在做什么（「正在读取 SettingsView.vue · 第 4 步」），完成后变成「已处理 9 步 · 用时 1 分 12 秒」，点开才看每一步；可在「设置 › 常规 › 会话 › 处理过程」改为始终展开或始终收起。上下文注入和 Hook 行默认不再显示（「设置 › 常规 › 开发者 › 显示系统步骤」）。模型还在写工具参数时，工具行就带着文件名和「准备中」出现；你的消息与回答正文改为 15/26，复制和用时只在指针停在这一轮时出现；展开与收起统一为 200ms 的动画，减少动态效果时没有动画。

### 修复

- 不需要 Key 的本机模型（Ollama、LM Studio 等）可以对话了：之前每次请求都在发出前失败，测试显示「No API key for provider」。
- 对话在计划模式、或有提问和计划等你回复时，设置里的保存（模型、子智能体、MCP、Skills、Hooks、定时任务等）不再失败：设置是全局的，不受窗口背后那个对话的状态影响；停止任务和后台进程也随时可用。仍然要等那个对话处理完的操作（例如应用子智能体的成果）会写明原因，不再只显示「发生内部错误」。
- 输入框不再丢草稿：发送被拒绝时原文、芯片和附件都会放回；每个会话保留自己的草稿；切换会话的瞬间回车不会发到上一个会话；附件上传完前不能发送，同名文件互不干扰；可以直接粘贴截图；编辑排队消息会带回附件，且不覆盖已输入的内容。不是命令的 `/词`（如 `/tmp 下有什么`）会提示后作为普通消息发送。审批、提问和计划卡片上按 Esc 只收起卡片，不再直接取消。
- 新装 Emperor 或会话全部删掉后，起始页的新对话照样有斜杠命令和 Skill，「+ › 插入 Skill 或插件」不再是空的，输入 `/plan` 回车作为命令执行，不再当成普通消息发给模型；侧栏里有别的会话时，新对话也不再显示第一个会话那个项目的 Skill，Build 新对话列出的是它自己项目的 Skill。
- 打开不存在或已删除的会话（「没有找到这个会话」）时，输入框停用，计划、权限、目标和模型按钮不再作用到背后的另一个会话，那个会话的目标条、排队消息和审批卡也不再显示在这里。
- 在起始页（新对话还没发消息时）开计划模式、切执行权限不再报「请先打开一个会话再试（control.setMode 需要指明 sessionId）」：它们属于这个新对话，发出第一条消息时随会话一起生效，第一步就在计划模式里；从起始页启动目标时带上所选的权限。新对话也不再显示上一个对话的「计划 ×」和目标条。第一条消息刚发出时按停止会真的停下，再发一条不会多出一个新会话，接着输入的文字和听写不会丢；会话不存在或已删除时提示「会话不存在或已被删除。」，不再显示「发生内部错误」。
- 用户消息只有真正进入对话才算发出：压缩等准备步骤期间点停止、费用上限或 Hook 拦下这一步时，消息回到队首，不再丢失；一轮出错后排在后面的消息显示「待发送 · 上一轮失败」，可以「发送」或「丢弃」；停止后排队的消息保留为「待发送 · 上一轮已停止」，不会自动接着运行；应用在消息发出前退出或崩溃时，重新打开会话后显示「待发送 · 应用重启前未发出」。ACP 的 `session/cancel` 与定时任务取消只作用于自己的消息。
- 写会话记录时断电、强退或磁盘写满，不再让会话永久打不开：末尾的半行在下次打开时移出另存，中间损坏的行之前的内容会保留，原文件另存备份；回合结束、提问和审批会立即写入磁盘，磁盘写满时暂停保存、腾出空间后自动补写。
- 应用在压缩上下文、运行工作流、后台任务或子智能体途中崩溃后，重新打开会话会把它们标成「已中断」，不再一直显示运行中，`/compact` 也不再永远提示正在压缩。一步内部出错（例如工具结果无法写入会话记录）后，会话可以继续，严格校验调用与结果配对的模型服务不再拒绝之后的请求。
- 个别模型网关在流式工具调用里重复发送空的 id 或名称时，工具调用不再丢失名称；模型请求中途失败并重试后，失败那次的半段文字不再重复出现在回复和子智能体摘要里；点「停止」后，不理会取消的工具（例如部分 MCP 工具）不再让这一轮停不下来。
- 中文会话的上下文估算不再低估三四倍，估算按服务商返回的真实用量逐步校准，不会再因为低估而每一步都重新压缩；上下文超限后的恢复在历史很长时分段生成摘要，不会因为摘要请求本身也超限而失败；刚执行完、模型还没看到的工具结果不再被截短。
- 「设置 › 用量」的缓存命中率不再一直是 0：账本如实记录缓存命中与写入、思考 token、服务商和每次调用的费用（没有填写单价时用内置目录的单价），输入不再把缓存命中重复计算，压缩摘要的调用也记入用量。
- `model_config.json` 里有一条模型格式不对时，不再整个文件被隔离、所有模型消失：只跳过这一条，「设置 › 模型」顶部列出原因并可以删除；正在使用的模型不能删除；同时保存两次模型设置不再互相覆盖。用到没有单价的模型时，成本上限不再让整轮停下，保存成本上限也不再要求先填好所有单价。
- 设置里没保存的编辑不再被悄悄丢掉：长期记忆、用户档案、`hooks.json`、模型编辑和能力页的 MCP JSON 有改动时，关闭设置、按 Esc、点遮罩、切换分区或页签都会先问「放弃未保存的修改？」；后台刷新只更新没改过的草稿。
- 定时任务、ACP 客户端与资料访谈在后台运行时不再把界面跳到它们的会话；停止按钮、新建定时任务的默认会话和设置页的拦截判断都跟着你正在看的会话走；需要会话的操作没有指明会话时直接报 `SESSION_REQUIRED`，不再落到某个默认会话上。
- 定时任务如实记录结果：模型请求失败记为「失败」并带错误码（例如 Key 失效为 `AUTH`），被停止记为「已取消」，遇到审批或提问时直接拒绝并记为「需要审批，已拒绝」，不再一直等待或误报「成功」；单次运行最长 30 分钟。
- 项目插件只在本项目的会话里生效：它的 MCP 工具和 Hook 不再出现在普通 Chat 或其他项目的会话里，也不再随你切到哪个会话而开关；同一项目的多个会话共用一组项目 MCP 服务。
- 在还没发过消息的新对话里直接启动目标不再报 `unknown session`；新建构建项目时在选择文件夹窗口点「取消」不再弹出报错；侧栏归档、重命名失败会弹出原因，不再悄无声息；侧栏布局没读取成功时，不会再用默认布局覆盖你保存的置顶、排序和折叠。
- 「设置 › 电脑操作」的总开关随时可用：「重新连接」或请求系统权限还在等待时，也能立即关闭电脑操作；这些操作超过 30 秒没有完成就停止等待并说明原因。
- 再次打开已在运行的 Emperor 只会把它的窗口带到前台；数据目录被另一个 Emperor 占用时，恢复页写明对方的版本和 pid，并可一键切换过去；恢复页「重试」不再重复创建电脑操作驱动。退出时先写完会话记录，关闭卡住超过 5 秒时强制结束子进程和终端后退出，不再残留后台进程。
- Codex、Claude Code 子任务不再在「正在准备」时无声失败：更新后第一次打开桌面、文稿里的项目，macOS 授权窗口晚于 5 秒才点「允许」时，Git 会在这个项目里一直「不可用」、每个外部子任务都失败，直到重启 Emperor；现在允许后半分钟左右（最长 5 分钟）自动恢复。还没开始工作就失败的子任务，子智能体那一行、任务详情和主会话的 Agent 收到的结果都写明哪一步、为什么（例如「准备工作区失败：当前签名执行环境中没有可用 Git（探测失败：timeout）。」），`core.log` 同时记一行，不再只有 `EXECUTOR_ERROR`。
- Codex 子任务不再全部「失败」又什么都不说：Codex 桌面版把它的默认模型（`~/.codex/config.toml` 的 `model`）换成这个 Codex 命令行的 ChatGPT 账号用不了的模型（例如 `gpt-6.1-sol`）后，每个 Codex 子任务都立刻失败，原因还被空回复挡住，界面只写「失败」，主会话的 Agent 以为没有任何回报。现在没在 Emperor 里选模型时，Codex 子任务改用这个账号可用的默认模型，任务详情写明「你的 Codex 默认模型 … 这个账号用不了，本次改用 …。」，「设置 › 子智能体 › Codex」的「默认模型」下面也提示一行；读不到账号的模型列表时不擅自换，被拒绝后重新读一次列表、换一个可用的模型重跑一次。在设置里选了的模型照用，Emperor 不修改你的 `~/.codex`。子任务这一轮失败时，子智能体那一行、任务详情和主会话的 Agent 收到的结果都以一句原因开头：服务返回的错误读成一句话，模型不可用时写明哪个模型、去哪里换。
- 子智能体和工作流里的子任务结束后不再一直占用内存；子智能体启动的后台命令在它被停止或会话停止时一起终止；永久删除会话时，它的子智能体会话目录和保存的大结果一并删除。
- 凭据库：文件损坏或由更新版本的 Emperor 写入时应用照常启动，只是暂时不能代填，原文件保持不变，可以「从备份恢复」或「重新开始（先备份）」；本地密钥文件被 `chmod -R 700` 之类收紧权限后照常可用，其他用户也能读取时先提供「修复权限」；新建本地密钥后会同步目录，断电后不会丢失；解锁不再让界面卡住半秒。从浏览器导入密码不再冻结界面，等待钥匙串授权时应用仍可操作。
- 桌宠开着时关掉主窗口，点 Dock 图标或桌宠右键「打开主窗口」都能重新打开；拔掉外接显示器后窗口与桌宠回到可见的屏幕上；临时浏览任务复用最多 4 个清空过的会话分区，不再每个任务留下一个无法释放的会话；电脑操作 Helper 的 socket 跟随自定义 `EMPEROR_CONFIG_DIR`。

### 安全

- Emperor 自己运行的 git（回合快照、「审查」、worktree、子智能体的快照与成果）不再信任仓库里的 git 配置：打开不受信任的仓库时，仓库配置不能借 Emperor 的 git 在沙箱外运行程序。
- 安装包仍不签名，但做了加固：打包时关闭 Electron 的 Node 运行与调试入口，应用只从封签过的 `app.asar` 加载，改动一个字节就无法启动；应用和每个 Helper 的 ad-hoc 封签都带 hardened runtime，entitlements 只保留必需的几项。其他程序不能借 Emperor 或 Helper 的身份和你已经授予的权限运行自己的代码。打包版不再接受改写界面来源或打开远程调试的启动参数与环境变量；内部的打包冒烟入口只接受系统临时目录下的数据目录；查验签名、复制 Helper 等系统命令一律按绝对路径执行。
- 主窗口有了严格的内容安全策略：只运行应用自带的脚本，不能向任何网络地址发请求或嵌入框架。Emperor 自己的窗口不再授予网页权限（麦克风、摄像头、屏幕、通知、设备与下载一律拒绝）；打包版没有「重新载入」和「开发者工具」。回复里的任何链接都不会让主窗口跳转或重新加载，远程图片不再自动加载（可被用作追踪像素），点击后由 Emperor 代为下载；渲染层不能再让主进程打开任意文件夹。
- 模型 API Key 与 MCP 配置里 key、token、secret、authorization、password 类的值不再明文写入配置文件，改用 Emperor 本地密钥加密（不用钥匙串），设置页只显示末 4 位；旧的明文 Key 在下一次保存时加密，加密前的原文件保留为 `*.pre-seal-<时间>`（含明文，确认无误后可删除）。
- Agent 的文件、搜索与 Shell 工具在任何权限模式下都读写不到 `~/.emperor` 的 `model_config.json`、`mcp_config.json`、`settings.json`、`hooks.json` 与电脑操作、浏览器数据；`~/.ssh`、`~/.aws`、`~/.config/gcloud`、`~/.docker/config.json`、`~/.netrc`、`~/.codex/auth.json`、`~/.claude/.credentials.json` 不能写，读取需要你批准一次（审批卡写明文件和理由）。默认预设下经 SSH 的 `git push`、`aws`、`gcloud` 等命令因此需要批准一次。`danger-full-access` 的 Shell 在 macOS 上也受这张表约束，守护起不来时不再执行命令。
- MCP stdio server、插件 Hook 与 Shell 共用同一套进程沙箱：读取默认关闭，只开放系统与工具链目录、workspace 和各自需要的目录，Emperor 的设置文件和你的凭据始终读不到；`npx`、`uvx` 类 server 在沙箱里能正常启动（每个 server 有自己的缓存目录，第一次启动会重新下载一次）。沙箱不可用时插件的 server 与 Hook 不运行，你自己的 server 先在对话里问你一次，不再悄悄在沙箱外运行；每次启动的结果在「设置 › 高级 › 诊断」的「进程隔离回执」。插件 Hook 的 workspace 只读，只能写自己的数据目录。
- 工作流脚本改在受限的独立进程里运行：读不到项目文件和 Emperor 数据、不能联网、内存上限 512 MB、最长 30 分钟；`workflow` 支持后台运行，结束后通知模型。
- 插件的边界收紧：插件带来的 Hook 只拿到 `PATH`、`HOME` 等少数系统环境变量和插件清单 `env` 里声明的变量，看不到你的 API Key 之类的凭据，默认 30 秒、最多 120 秒超时；项目插件的启用状态改记在 Emperor 里，仓库 `.emperor/settings.json` 的 `enabledPlugins` 只会在「能力 › 插件」显示建议，你确认后才启用（升级前已在项目里启用的插件保持启用）。你自己 `hooks.json` 里的 Hook 不变。
- Claude Code 子任务里执行的命令拿不到 Claude Code 自己的登录令牌或 API Key；子智能体在自己隔离的主目录里运行，不加载仓库的 `.claude/settings.json`（其中的放行规则可能绕过 Emperor 的审批）。
- 记忆写入：`memory_edit` 原样写入替换文本，不再意外把文件其余内容复制进记忆；疑似密钥和提示词注入的内容拒绝写入；非 `danger-full-access` 下每个会话第一次写记忆前请你批准。审批回答没有选项 id 时一律按拒绝处理，「不允许」不再被当成允许。定时任务运行中不能再修改、恢复、立即运行或删除任何定时任务。
- 凭据库升级为版本 3：主密码设置时要输入两次，更改或移除都要先输入当前主密码，连续输错 5 次后每次重试要等待（最长 5 分钟）；每个条目的绑定与代填方式参与加密校验，被改动的条目无法解密，其他条目不受影响。新增「导出凭据备份」与「导入凭据备份」，用你设的口令加密成 `.emperor-vault` 文件。
- 电脑操作 Helper 与 Emperor 的连接改为双向认证：一次性密钥不再出现在启动参数里，抢先连上的其他程序拿不到任何凭据。
- 从 Chrome/Edge 导入的 Cookie 不再以只有固定口令保护的方式存进 Chromium 的 Cookie 数据库，改用 Emperor 本地密钥加密，使用时只放进浏览器内存；登录档案文件夹排除出 Time Machine。升级前已经导入的 Cookie 不会自动迁移，需要时清空那个登录档案再重新导入。
- 网页在你要输入的字段上把焦点挪进跨源 iframe 时，Agent 的输入与凭据代填会被拒绝，不再让 Emperor 卡死或崩溃。
- 下载：Agent 下载收件箱里的文件带 macOS 来源标记，第一次打开时由系统检查；下载黑名单补上磁盘映像、描述文件、快捷指令、可加载的包和脚本等类型（对 Agent 下载和你自己的下载都生效）。
- Chrome/Edge 扩展：启动时重新核对扩展文件夹里的实际文件，被改动就整个重装；文件夹只有你能访问；连接通道在扩展完成认证前限制消息大小与配对请求的频率。

### 移除

- 「设置令牌」：Emperor 不再接收、保存或转交 Claude 账号的令牌，也不再读取 `~/.claude/.credentials.json` 或转交 `CLAUDE_CODE_OAUTH_TOKEN`。升级后第一次启动时删除之前保存的令牌，「设置 › 子智能体」提示一次改用「登录 Claude Code」。「使用本机安装的 claude」开关一并移除：现在总是使用本机安装的。
- 不再支持 Windows 与 Linux：只构建、发布和测试 macOS（Apple 芯片与 Intel）安装包。
- 侧栏的「探索」页：精选的 Skills 与 MCP server 移到「能力」每个标签顶部的「推荐」，旧链接打开推荐。
- 右侧工作台的「首页」：打开工作台直接回到上次用的面板。
- 「审查」里合并、关闭 PR 等操作：在 GitHub 网页上完成；环境信息卡里的切换分支、worktree、提交推送和比较分支移到「审查」。
- 设置里独立的「Hooks」「诊断」「桌宠」分区：分别移进「高级」的二级页和「常规 › 外观」，旧链接（`?settings=hooks`、`?settings=diagnostics`、`/pet` 等）打开新位置。
- 旧的文本输入框与 `@skill()` 标记：输入框只用芯片引用 Skill 和插件。

`v0.1.0-preview.1` 至 `v0.1.0-preview.4` 的变化，没有逐个版本拆分。

### 新增

- 「设置 › 电脑操作 › Chrome 和 Edge › 浏览器权限」的「启用站点工具」（WebMCP）标为不可用；当前未接入站点工具，开关不能打开，模型也没有对应工具可调用。

- Chat 移除顶部“对话 / 正在办差 · 模型”标题栏；右侧工作台可在 360–960px 之间拖动，窗口变窄时先缩窄、再自动收起，侧栏、工作台、环境信息卡和「详情」列的布局在重启后恢复。
- 删除已退役的桥接接入模块及其 API、运行事件、诊断和界面投影；旧安装私有文件不会被读取、迁移或自动删除。
- 模型配置统一为 schema v2：可保存多个标准接口模型，全局只激活一个。
- Renderer 的映射 Core API 调用统一通过 `api/http.ts` 的桌面 Core bridge；普通浏览器不是受支持运行模式。
- Core runtime event 类型与 renderer 投影共用明确契约。
- Composer 的模型 / 模式菜单逻辑收敛到共享 helper。
- Chat 消息列表滚动监听改为跟踪最新可见消息签名，避免深度监听完整时间线。
- README 改为面向普通用户的产品入口，并把详细操作、架构、发布与维护内容分层到文档中心。
- 设置弹窗的全部分区改用统一的设置组件重写：记忆按“长期 / 用户档案 / 情景 / Watchlist / 版本”切换，用量提供活跃度、趋势、模型和缓存视图，Hooks 分为配置 / 测试 / 审计，常规外观支持跟随系统。
- Skill 校验放宽为只检查 `SKILL.md` 及其引用的文件，名称以 frontmatter 为准；项目 Skills 在对应 Build 会话中可以写入，每个项目使用独立的 Skill 目录。`skills.previewInstall`、`skills.confirmInstall` 与 `skills.package` 已移除，Skill 安装统一使用 `skills.import`。
- 对话中工具行的 Inspect 改为跳到「轨迹」并在轨迹右侧的「详情」列中定位该调用；「详情」列可拖宽、收起并记住宽度。原右侧详情栏及其 Inspect / Environment 标签移除：子智能体在子会话中查看和停止；后台命令和工作流的输出查看与停止移到「环境信息」卡的「后台任务」中（展开后每个任务有「输出」和「停止」，停止工作流前会确认）。
- `computer-use` Skill 不再是内置 Skill，改由 Computer Use 插件提供：电脑操作关闭时它不再出现在 Skill 列表里。电脑操作设置中，未配对的 Chrome/Edge 连接显示为“实验性”并写明需要配对；macOS 上缺少 Helper 时写明“没有找到 Emperor Computer Helper”。
- 定时任务、插件、Skills 和 MCP 从设置弹窗移到整页，设置弹窗保留常规、模型、Hooks、工具、记忆、用量、桌宠、配置和诊断；旧的 `?settings=scheduler|plugins|skills|mcp`、`/skills/<名称>` 与 `/mcp` 链接会跳到对应页面。
- 能力 › 工具只列 Emperor 内建的工具，按用途分为基础工具、网络、任务与规划、子智能体与工作流，以及技能、记忆与配置五组，每组标题带数量，保留搜索；每行是工具名和一句说明，展开后仍可查看参数和 JSON schema。MCP server 的工具在「MCP」标签按 server 列出，插件带来的工具改在插件详情里列出，页首有这两处的链接。
- 电脑操作可以操作除系统保护应用（授权弹窗、钥匙串访问、「密码」、系统设置、登录窗口和 Emperor 自身）以外的所有应用：去掉「不让 Emperor 操作的应用」、高风险应用与不截图的应用三份名单，终端也不再带额外提示。去掉紧急停止（⌃⌥⌘.、程序坞菜单、菜单栏图标和设置里的「立即停止」）：要让 Agent 停下，停止回合或关掉总开关。从预览版升级时设置自动迁移，以前不让 Emperor 操作的应用会在「设置 › 电脑操作」顶部提示一次。
- 「设置 › 浏览器」按卡片重排：去掉页首说明，「导入…」移到「自动填充和密码」标题右侧；「清除浏览数据」的结果改为这一行里的「已清除」或「清除失败」标记，失败原因写在行内；主页和密码管理器、登录状态、下载历史记录、网站设置出错时，页面顶部出现一张提醒卡，二级页的说明压到一句。
- 「设置 › 语音」先放「听写」的麦克风、识别语言和快捷键，系统权限放到最后，两项状态相同时合成一行；权限被拒绝或受限、听写组件不可用时，改为页面顶部的一张提醒卡，带「打开系统设置」或「重新检测」，散放的听写组件行去掉。
- 「设置 › 诊断」顶部改为一张概览卡：一句结论加需要关注的项目，点一项展开对应分组，去掉四个计数小块；运行根目录移到「存储路径」，路径直接显示；五个分组样式统一，正常的项目只显示值、不再带彩色标签，只有含需要关注项目的分组在标题旁显示状态；请求失败时页面顶部出现提醒卡。
- 听写时，输入框底部一行换成录音条（参照 Codex）：× 取消并丢弃这段听写；波形随麦克风的真实音量起伏，最新的在右边，安静时是一排点，显示大约最近 3 秒；■ 停止听写并把文字放进输入框，悬停时显示「停止听写」和快捷键（默认 ⇧⌘D）；发送键结束听写，等最终文字放进输入框后再发送。这是你按下的发送，听写本身仍不会发送消息。系统开启「减少动态效果」时波形不滚动，只显示当前音量。
- 密码管理器和 Chrome/Edge 配对不再使用 macOS 钥匙串，启动和使用时不会再弹出「emperor-agent-desktop Safe Storage」授权框：凭据与配对改用 Emperor 本地密钥加密，密钥保存在这台 Mac 的 Emperor 目录（`~/.emperor/computer-use/secrets/local.key`）。以前用钥匙串加密的密码和 Chrome 配对在升级后清除，需要重新添加或导入密码、重新配对扩展；登录状态 profile 的 Cookie 不受影响。本地密钥只算基础保护（以你身份运行的程序也能读到），密码管理器如实标注并建议设置主密码；密钥丢失或文件权限不对时顶部提示，确认后可「清空」重新开始。去掉密码管理器的「Touch ID 解锁」，查看密码前仍用 Touch ID 或登录密码确认身份。只有「从 Chrome/Edge 导入」读取那个浏览器自己的钥匙串项目时，macOS 才会询问。

### 安全

- Git、Files 和 Terminal 由 Core 按 Build session 所有权授权；Renderer 不获得 Node/fs/shell，Git mutation 使用 revision/确认，Files 拒绝 traversal/symlink escape，Terminal 高频字节流不进入聊天或持久事件。
- Electron 主界面与桌宠现在显式运行在 renderer sandbox 中；preload 改为受构建/打包审计的最小 CommonJS，桌宠不再直接读取文件系统，packaged smoke 会真实验证 Core bridge 与受管附件协议。
- 明确 MCP、Web 与外部消息是不可信输入，目标完成态只能由 Core Completion Gate 提交。
- 网络调研回复只有在逐项引用本轮 verified source 并通过隔离复核后才发布；核验事件不包含 URL、正文、命令、本机路径或 reviewer prompt。
- 发布文档区分当前未签名 Preview 与尚未启用的受信 Stable 流程。
- 右侧工作台的内置浏览器运行在独立的 sandboxed `WebContentsView` 与不落盘的内存分区中，只加载你在地址栏提交的 `http(s)` 地址，拒绝权限请求、下载和应用内弹窗，关闭后清空浏览数据；旧的内嵌预览通道与 `previewId` 授权路径已删除。
- 电脑操作：页面改成明文的密码框、普通输入框里的验证码，以及代填凭据后整页的输入值都不再出现在 Agent 的观察结果中；跨源 iframe 内的动作按 iframe 自己的网站授权；以点结尾的可执行文件名不再绕过下载拦截；受限 Shell 不能读取 `~/.emperor/browser/`；授权记录损坏时明确显示为已暂停。
- `gh` 只以固定参数调用，仓库、PR 编号和搜索文本先经校验再作为单个参数传入；Emperor 不向 `gh` 传递 `GH_TOKEN`、`GITHUB_TOKEN` 等 token 环境变量，Pull Request 页不执行任何写操作。
- Agent 的 `read`、`edit`、`write`、`grep`、`glob` 工具在任何权限模式下都不能读取或修改 `~/.emperor/computer-use/`（凭据库、本地密钥、浏览器配对、授权记录）与 `~/.emperor/browser/`（登录状态 profile、下载收件箱等）：按真实路径判断，从上级目录搜索时略过，与受限 Shell 的 Seatbelt 规则共用一份目录表；这两个目录启动时设为 0700。
