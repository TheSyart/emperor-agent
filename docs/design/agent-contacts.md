# 联系人与群聊

> 文档状态：Active<br>
> 面向读者：设计者、前端与 Core 开发者、维护者<br>
> 最后核验：2026-10-27（对照 `76a61ad1`）<br>
> 事实源：本文是 0.3 的设计稿，实现后以 `packages/core/src/contacts/`、`packages/core/src/groups/`、`desktop/src/renderer/src/components/contacts/`、`desktop/src/renderer/src/components/groups/` 及其测试为准

联系人是长期存在的 agent：有名字、头像、一份岗位说明书、自己的模型、工具和记忆。群聊把几位联系人拉进同一个会话，谁对谁说了什么、为什么交给谁、交出了什么，都摆在一条时间线上，用户随时能插话、点名、停止。它们都在 [Group 模式](modes.md)里。

## 联系人

### 岗位说明书

每个联系人是一份七节的岗位说明书，编译成固定结构的系统提示词（同样的输入，输出逐字节相同）：

| 节           | 内容                                                                            |
| ------------ | ------------------------------------------------------------------------------- |
| 1 身份       | 名字（1–24 字，不重名）、头像、一句话简介（≤ 60 字）、领域（最多 3 个）         |
| 2 职责与交付 | 负责什么、交出什么、什么格式                                                    |
| 3 工作方法   | 步骤与检查清单                                                                  |
| 4 知识       | 只读参考资料：文件、文件夹、网址、Skill；回答时注明出处；另有个人记忆           |
| 5 边界       | 不做什么、什么时候交还、不确定时怎么标                                          |
| 6 能力       | 模型、工具预设（只读 / 调研 / 写作 / 工程 / 自定义）、权限（不能高于全局权限）  |
| 7 群聊习惯   | 什么时候开口（只在被点名时 / 和职责相关时举手 / 总是发言）、篇幅（简明 / 详细） |

- 每次保存生成一个版本，保留最近 20 个，可以对比和退回；群里永远用最新版。
- 资料和网页内容当数据，不当指令：工具权限只由岗位说明书决定。
- 个人记忆只记用户的明确反馈（👍 / 👎 加一句话），只对这个联系人生效，可以改、可以删。

### 四种建法

在 Group 模式侧栏点「+」（新建联系人）打开编辑器。四种建法都只填编辑器，点「保存联系人」才保存：

1. **从岗位模板**：18 个模板，按领域分组——软件工程（架构师、代码审稿人、测试工程师、安全审计、前端工程师、运维与发布）、设计（素材设计师、界面设计评审）、内容（研究员、写作者、编辑、译者、市场文案）、产品与决策（产品经理、用户研究员、数据分析师、反方（红队）、主持人）。模板要的权限高于新会话的权限时，从只读开始。
2. **说说你要什么人**：用户写几句描述，点「起草」后 Emperor 用默认模型做一次结构化输出：信息不够时最多追问 3 个问题，回答后直接起草。起草的节标「AI 起草」，用户改过就去掉；起草失败时描述留着，可以再试。起草和试用台都是真实的模型调用，只在用户点按钮时发生。
3. **导入**：Claude Code 的 `agents/*.md` 或现成的提示词文件，只读用户选的那一个文件，不超过 64 KB。`name` 成为名字，`description` 成为简介（截到 60 字），`model` 只作提示，正文进「工作方法」；工具按表转换（Read、Grep、Glob、Bash、Edit、Write、WebSearch、WebFetch），其余列为「没有导入」；frontmatter 坏了时整个文件进「工作方法」并提示。导入的文字是资料，工具只按表来。
4. **复制已有联系人**：用户自己建的联系人，名字加「副本」。

编辑器右边有完整度检查（交付、≥ 2 步方法、边界、工具与权限一致、跑过试用台；只提示，不阻止保存）、试用台和生成的系统提示词预览（和运行时编译的完全一样）。试用台用还没保存的设置在隐藏会话里跑一次样例任务，显示结果、用量和花费；需要批准的操作和提问都会被拒绝，关掉编辑器就停止，隐藏会话 24 小时后清理，不出现在任何列表和搜索里。内置联系人只能改头像和简介；外部联系人的模型和权限跟随「设置 › 子智能体」。

### 头像

- 头像库：135 个 Q 版头像，15 个主题（工程、设计、内容、产品、文臣、武将、宫廷、混搭、动物、机器人、人物、奇想）。
- 新建时**先推荐**：从模板新建时先用模板的默认头像，别人在用就从模板对应主题里随机挑一个，跳过别的联系人已在用的（空白、起草、导入的从人物、动物、机器人里挑）。旁边有「换一个」（同主题再随机，这次编辑里推荐过的都不再出现，全都用过时才允许重复）和「从头像库选…」（按主题分组、可搜索；别人在用的标「在用」，仍然可以选，选了会提示谁也在用）。头像的名字和主题跟编辑器一起加载（编辑器本身是单独的一块，不进入口包），所以推荐行一开始就写「推荐：安全审计」；读不到时写主题（「推荐：工程主题」）。之后在联系人档案里也能换（「换头像」打开头像库）。
- 内置联系人：Emperor 用吉祥物小单戴冠的头像；Claude Code、Codex 用厂商标志。子智能体仍用原来的毛绒动物头像，和联系人区分开。

### 档案与单聊

- 档案页（`/contacts/:id`，GRP-05）：头像（「换头像」）、名字、领域和简介；「发消息」「拉进群」（列出群，选一个就把它加进去并打开那个群，GRP-08）「编辑」；四个数字（Core `contacts.stats`）：参与的群（现在是成员的群）、发言次数（群里的发言，不含「没有补充」和系统消息，加上它单聊里的回答）、你的评分（个人记忆里还留着的 👍 占全部 👍 / 👎 的比例，「83%」「你的评分（12 次）」；还没有时写「—」）、岗位说明书版本。标签页：职责与方法、知识、能力、记忆（每条可以改、可以删，个人记忆开关；内置联系人的开关不能动）、版本。新建联系人保存后进它的档案。
- 版本标签页：当前版本在最上面，然后是旧版本，新的在前。下面对比两个版本（默认上一个版本对当前版本，两个下拉框可以选任意两个，旧版本行上的「和当前对比」直接选它），逐项列出不同的地方（名字、简介、领域、职责、交付、工作方法、参考资料、边界、模型、工具、权限、群聊里发言、发言篇幅、个人记忆）。「退回到 vN」先确认，退回产生一个新版本，历史不变。
- 「发消息」打开和这个联系人最近的单聊，没有就新建（Core `contacts.openChat`：只看 `surface: 'contact'` 的会话，试用台、群成员会话不算，`/clear` 换掉的旧会话也不算）。单聊就是普通会话，日志、压缩、计划模式、目标、工作台都照常；`/clear` 之后新会话仍是这个联系人的单聊。它属于 Group 模式，侧栏里亮着的是这个联系人那一行。
- 单聊里每段回答上方是联系人的头像和名字；空的单聊首页写联系人的名字和简介，输入框提示「给「审稿人」发消息」。回答的底栏（指针移上去时出现）有 👍「有帮助」/ 👎「没帮助」，点了写一句为什么（可以不写），「记下」写进它的个人记忆（`contacts.feedback`，带上这段回答的消息 id）；个人记忆关着时没有这两个按钮。联系人被删除后单聊只读，输入框写「这个联系人已删除，这个会话只能查看」。
- Claude Code、Codex 的单聊（GRP-11）不跑本地回合：单聊里的消息交给它们自己，是一个以单聊会话为根、由用户开的委派（`owner.source: 'contact'`）。第一条消息开委派（`contacts.chatSend`），只读（`shared-readonly`，没有项目时在单聊自己的工作目录里），之后的消息续这个委派，每条消息各算一个任务，聊得再长也不会碰到「每个任务最多外部运行」。套了岗位说明书的外部联系人，说明书经委派的 `instructions` 追加。用户自己发的消息就是同意，不再弹「允许交给它」的卡片；它运行中的提问出现在它的对话页。
  - 打开：档案里「发消息」、Group 首页只 @ 它们，都打开它们的单聊。还没有消息时是单聊首页，输入框是简单的一行（「给 Codex 发消息」，下面写「单聊里它只读、不改文件」）；有了委派之后，单聊直接打开委派的对话页（复用子智能体对话页 `ExternalAgentConversation.vue`），路径写「联系人 / 单聊」，‹ 回到联系人档案。对话页里发消息、停止、回答它的提问都照常。
  - Core 守卫：`chat.submit` 发到它们的单聊报 `contact_chat_external`；主机在送达和每一步之前也拒绝（群成员会话、后台回合同样不会让本地模型代它们说话）。联系人删除后，它的单聊和委派对话页都只能查看（`contact_deleted`）。
  - 档案页写「单聊里它只读、不改文件；要它改代码，在 Build 对话里把任务交给它。」
- 外部联系人（Claude Code、Codex）也可以套一份岗位说明书，例如「Claude Code · 安全审计」：通过两个执行器各自的追加指令入口生效，模型和权限跟随「设置 › 子智能体」。

## 群聊

### 群设置

| 设置                   | 默认    | 说明                                                                                                                                                                                                                                   |
| ---------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 群公告                 | 空      | 每位成员发言前都会读到：目标、约束                                                                                                                                                                                                     |
| 协作方式               | 自主    | **自主**：没人被 @ 时，和职责有关的成员举手发言；成员之间可以直接点名、直接交办。**主持人审核**：没人被 @ 时由主持人安排；成员点名别人、交办别人，先交给主持人批准、改顺序或驳回。全局默认在设置里新增的「群聊」一节，每个群可以单独改 |
| 安静模式               | 关      | 只回应 @：没人被 @ 就没人说话                                                                                                                                                                                                          |
| 每轮结束时主持人出结论 | 开      | 结论用浅金底显示，可以一键交办                                                                                                                                                                                                         |
| 防打转                 | 开      | 见下文「停下来」                                                                                                                                                                                                                       |
| 主持人                 | Emperor | 可以换成别的成员，也可以没有                                                                                                                                                                                                           |

用户自己的 @ 和交办永远不需要审核；不论哪种协作方式，改项目代码都要用户确认，在隔离副本里改。

### 五种发法

每条群消息都带「受众」。受众决定谁的上下文里有这条消息，点名决定谁要回答。**用户能看到全部消息，包括成员之间的私信**；没有用户看不到的 agent 间通信。

| 发法     | 怎么发                            | 谁能看到                       | 谁要回答                                                                  | 界面上                                             |
| -------- | --------------------------------- | ------------------------------ | ------------------------------------------------------------------------- | -------------------------------------------------- |
| 广播     | 不 @ 人，或 @所有人               | 全体成员                       | 看协作方式：自主 = 有关的人举手；主持人审核 = 主持人安排；安静模式 = 没人 | 「→ 所有人」                                       |
| 点名     | @A，或 @A @B                      | 全体成员                       | 只有被 @ 的人；多人按 @ 的顺序接力，后一位能看到前一位的回答              | 「→ @A」，@ 高亮                                   |
| 独立作答 | 广播或点名时选「各自独立回答」    | 全体成员，但作答期间彼此看不到 | 被问到的人同时答（最多 3 位并行），都答完后一起显示                       | 并排的「独立作答」卡片                             |
| 私信     | 用户：发给 → 私信；成员：私信工具 | 只有对方（和发送者）           | 对方                                                                      | 紫色左边线和「🔒 私信 · 其他成员看不到，你能看到」 |
| 交办     | 用户：发给 → 交办；成员：交办工具 | 全体成员                       | 被交办的人去做一件有交付物的事                                            | 任务卡：交付、依据、权限、状态                     |

成员怎么说话：轮到它时，它在自己的成员会话里正常干活，最后的回答就是一条群消息。正文里写 `@名字` 就是点名下一位；不点名，这条线就说完了。成员另有工具：私信、交办、「我没有补充」；主持人另有「安排下一位」和「结束本轮、出结论」。Claude Code、Codex 只能用正文里的 @。交办链不能绕回：A 交给 B 的任务，B 不能再交回 A 或链上的任何人。

### 停下来

群聊**不设本轮额度**：不限发言次数、轮数和费用，也没有花费提醒，标题栏只实时显示「本轮 ¥… · 不设上限」。一轮会在这些时候停：

| 情况                             | 结果                                                                                                                                    |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 没人被点名，排队也空了           | 本轮自然结束；有主持人时，主持人出一段结论                                                                                              |
| 主持人认为问题答完了             | 主持人结束本轮，附结论                                                                                                                  |
| 两位成员来回没有新内容（防打转） | 按「有没有新内容」判断，不按次数：同一对成员连续来回 4 次以上且最近两次几乎没有新内容时，主持人介入换人或收尾；没有主持人就暂停并问用户 |
| 用户发了新消息                   | 正在说的人说完这一段，排队的人按新消息重排                                                                                              |
| 用户点「停止」或按 ⌘.            | 所有人立即停下，没发出的发言丢弃，进行中的交办一起停                                                                                    |

「设置 › 用量与费用」页（0.3 由原来的「用量」页扩成）里的防失控限制（一次回答最多调用工具 400 步）和费用上限（默认不限制）**按每位成员的每一次发言单独计算**，不累计成整轮的额度：一次发言被截停时，群里写明原因，其他人照常。

### 群聊页

点开一个群（侧栏、Group 首页、搜索、通知）进 `/groups/:groupId`（GRP-08）；群自己的会话从 `/chat/:id` 打开时也转到这里。

- 头部：群名、人数、协作方式标签（「自主」或「主持人审核」，安静模式时加「· 安静」），右侧「本轮 $… · 不设上限」、「停止 ⌘.」和群设置。花费用美元，和「设置 › 用量与费用」一致。
- 消息流：用户消息（右侧暖色气泡，上面写发给谁：「→ 所有人」「→ @架构师」「🔒 私信 → 写作者」）、成员发言（头像、名字、职责、受众标签，正文按 Markdown 显示，@ 高亮）、独立作答卡片（揭晓前写「N/3 已答，答完一起显示」，不显示内容）、私信（紫色左边线和「🔒 私信 → X · 其他成员看不到，你能看到」）、任务卡（交付、依据、权限、状态）、结果卡（交回的内容；Claude Code、Codex 在隔离副本里改的，附上和对话里一样的成果卡：查看差异、应用到项目、丢弃）、结论（浅金底）、系统消息（居中小字；写着「设置 › 子智能体」的带一个打开它的按钮）、「没有补充」（淡色一行）。超过 12 行的消息先折叠，「展开全文」；已删除的联系人显示灰色头像和「已删除的联系人」。
- 成员的工具步骤不进消息流。发言右上角「过程 ›」打开这位成员自己的会话：只能查看，标题栏是「群名 / 成员 · 工作过程」，点群名回到群里；输入框写「这是「架构师」在群「…」里的工作过程，只能查看；回到群里和它说话」。
- 成员发言时要用户回答的问题（`ask_user_question`）和要批准的操作，像群里的一条消息一样出现在那位成员名下（D29）：问题的选项是消息里的快捷回复，只有一个单选问题时点一下就回答；也可以自己写一句；「不回答」取消这个问题。审批写明要做什么，按钮和对话里的一样（拒绝、允许本次……；Claude Code、Codex 第一次用时是不允许 / 本次允许 / 以后都允许）。计划审阅和电脑操作授权写一句「等你处理」，「去处理 ›」打开它的工作过程。回答之后问题离开消息流，群日志里记一条只给你看的系统消息（GRP-12）：「你回答了 架构师 的提问：…」「你批准了 架构师 的请求：…」「你拒绝了 …」「你没有回答 …」（计划审阅是「你批准了 … 的计划」「你对 … 的计划提了意见」），居中小字，回答的是哪个问题悬停可见；重开群页面、重启后都还在。在成员的工作过程里回答的也记。它不是群消息：不投递给任何成员，不进群纪要，不算发言次数（提问的成员从自己的会话里拿到回答）；电脑操作授权不记，停止一轮时取消的提问也不记。成员交给 Claude Code、Codex 在隔离副本里改代码的任务，任务卡上有「同意 / 不同意」。
- 输入框：「发给 ▾」五种发法：所有人 · 举手（文字里 @ 了成员就按点名发）、所有人 · 各自独立回答（没有 @ 时问除主持人和「只在被点名时」发言的成员以外的每一位）、@ 指定成员、私信…（选一位成员）、交办…（选一位成员，填任务、交付、依据和权限：只写群文件 / 只读 / 在隔离副本里改代码；发出后回到「所有人 · 举手」）。@ 补全只列群成员（↑↓ 选择、Enter 或 Tab 确认、Esc 关闭）；⌘↵ 发出，Enter 换行；@ 了不在群里的名字时不发送，下面一行说明原因。
- 输入框上方一行：正在发言、排队（交办的标「（交办）」），右边「本轮 3 分 12 秒 · 7 次发言 · $0.86」。一轮结束后写它怎么结束的（已结束、已停止、已暂停：两位成员来回没有新进展、应用重启时停下，可以重发）。
- 右侧成员栏：「成员 N」和「+ 邀请」，每人一行：头像（状态小圆点，发言中有一圈蓝色）、名字、状态（空闲、发言中、执行中、排队、排队 · 交办任务、等你回答、等你批准、出错；主持人空闲时写「主持人 · 空闲」，外部成员写「外部 · 只读 · 只在被 @ 时」）。状态变化用 `aria-live="polite"` 读出「架构师 发言中」，不读正文。超过 8 人时列表滚动。最下面说明不设本轮额度。点一行打开联系人档案。
- ⌘. 在有进行中的一轮时停止它（有对话框打开时不响应）。

#### 群设置

`/groups/:groupId/settings`，标题栏「群设置 / 群名」，「‹」回到群里。依次是：群名（改完离开输入框保存）、群公告（「保存公告」）、协作方式（两张卡片，写明「默认值在「设置 › 群聊」，这里只改本群」）和主持人、「每轮结束时主持人出结论」「防打转」「安静模式」三个开关（改了立即保存）、成员（移出、邀请）、群文件（只列名字）。保存失败时提示，并回到原来的值。

#### 新建群聊

侧栏的「新建群聊」（Group 下的 ⌘N）、「群聊」标题旁的「+」和 Group 首页的「新建群聊」卡片打开同一个对话框：先选模板——评审（架构师、代码审稿人、测试工程师）、正反方（产品经理、反方（红队））、调研写作（研究员、写作者、编辑）——或空白。模板填好群名和群公告，勾上从对应岗位模板建的联系人（Emperor 默认加入并主持）；还没有这种联系人时写「还没有：测试工程师」和「去新建联系人」。成员、主持人、群公告和协作方式在「建群」前都能改；协作方式默认是「设置 › 群聊」里的值，只有改了才单独记到这个群。建好后打开新群。

#### 新群的默认设置

「设置 › 群聊」（和「子智能体」在同一组）有「新群的默认设置」：协作方式（自主（默认）/ 主持人审核）和防打转（默认开）。新建的群按它初始化，已有的群不变。

### 空状态与错误

- 没有群：「把几个联系人拉进一个群，让他们一起讨论；你随时可以插话」+「新建群聊」（模板：评审、正反方、调研写作）。
- 成员的模型不可用：那次发言失败，群里一条系统消息写明原因（「X 这次发言失败：…」），其他人照常。
- 外部成员没登录、版本不兼容：群里一条系统消息，带和「设置 › 子智能体」一致的按钮。
- 应用重启时进行中的一轮标记为已停止，用户可以重发。
