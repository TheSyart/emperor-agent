# 输入框

> 文档状态：Active<br>
> 面向读者：设计者、前端开发者、维护者<br>
> 最后核验：2026-10-20<br>
> 事实源：`desktop/src/renderer/src/components/composer/`（`ComposerCard.vue`、`PermissionChip.vue`、`ModelPicker.vue`、`ComposerStatusBar.vue`、`StatusGoalSection.vue`、`StatusQueueSection.vue`、`statusBarModel.ts`）、`components/chat/composerController.ts`、`composerPalette.ts`、`composerModelControl.ts`、`components/conversation/HeroProfilePrompt.vue`、`theme/components.css`（`--composer-*`）、`desktop/src/main/screenshot-ipc.ts`；测试 `ComposerBottomBar.test.ts`、`ComposerStatusBar.test.ts`、`statusBarModel.test.ts`、`composerArchitecture.test.ts`、`desktop/tests/visual/composer.spec.ts`

输入框在对话面板底部：上面一行状态条，下面一张卡片，卡片里是富文本编辑器和一排四个控件。一个信息只放一处：权限和 Plan 在同一个菜单里，模型、思考强度和上下文用量在同一个菜单里，改动、待办、目标和队列在同一条状态条里。

## 卡片

- 底色 `--composer-fill`（两套主题都是 `--surface-raised`），圆角 `--r-xl` 24，没有边框。边缘 `--composer-edge`：深色只靠 `--elev-1` 的阴影，浅色是 0.5px `--hairline` 描边加 `--elev-1`。
- 宽度跟对话内容列一致（`--composer-card-max`）；空会话的 Hero 居中显示同一张卡片。
- 编辑器在上，四个控件在下。一行草稿时，从卡片上沿到控件行上沿的输入区至少 56px（上内边距 16 + 一行 28 + 与控件行的间距 12）；草稿变长时编辑器长高，最多 336px 后滚动。
- 编辑器上方按需出现一行说明：附件托盘、留到别的对话的听写结果、像密钥的内容的提示、未知 `/词` 的提示、Goal 待输入（「Goal：描述要持续完成的目标，发送后开始」+「取消」）。这几行在卡片里，不算控件行。
- 拖入文件时卡片外圈加 2px 焦点色描边。

## 底栏的四个控件

控件行恰好四个可聚焦控件，左边两个，右边两个：

| 控件   | 外观                                                                            | 内容                                                                                           |
| ------ | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `+`    | 28px 圆形图标按钮                                                               | 菜单：上传图片或文件、插入 Skill 或插件（打开芯片列表）、截图（只在 macOS 桌面应用里出现）     |
| 权限   | 28px 芯片：盾牌图标 + 预设简称（只读 / 工作区 / 完全），Plan 打开时加「· Plan」 | 菜单：说明行、三个预设、底部「Plan 模式」开关（金色只在开关打开时出现）                        |
| 模型   | 28px 芯片：供应商 logo +「模型名 · 思考强度」+ 下拉箭头                         | 两层菜单（模型、思考强度），每层底部都是「添加模型…」和上下文用量                              |
| 发送位 | 32px 圆形                                                                       | 空草稿：麦克风（有听写时）；有草稿：金色发送键；运行中：停止键，有草稿时旁边多一个「加入队列」 |

- 运行中权限和模型芯片禁用（不可聚焦），编辑器照常可写，回车加入队列。
- 发送位是唯一的金色主操作；权限、模型、`+` 都是中性色。
- 截图由 main 运行系统的交互式截图（`screencapture -i`），窗口暂时隐藏，截下的 PNG 作为附件放进托盘；Esc 什么都不放。屏幕录制权限被拒绝时轻提示写明去哪里允许。
- 上下文用量：「上下文 12.0k / 128.0k · 已用 9%」加一条 4px 进度条，75% 起用 `--warn`，90% 起用 `--error`；不知道上下文窗口时不显示。
- 听写时整行换成录音条（取消、波形、停止）和发送键，行为见用户手册的[语音听写](../user/chat-build.md#语音听写)。

## 状态条

- 卡片上方一行，32px 高，`--surface-raised` 底、`--r-md` 圆角，13/20、`--text-2`；整行是一个按钮，末尾一个 `›`。
- 内容按固定顺序拼成一行，用「 · 」（`--text-4`）分隔，放不下时末尾省略：

| 部分 | 文案                                                                                    | 出现条件                                                 |
| ---- | --------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 改动 | 「3 个文件已更改 +18 −4」（增删用 `--state-ok-label` / `--state-error-label` 等宽数字） | Build 会话、工作区有未提交改动（整个工作区，不是某一轮） |
| 待办 | 「待办 2/4」                                                                            | 有待办清单                                               |
| 目标 | 「目标进行中」「目标已暂停」「目标已阻塞」                                              | 有未完成的 Goal                                          |
| 队列 | 「1 条排队中」，全部待发送时「1 条待发送」，插话中「1 条准备插入」                      | 队列不空                                                 |

- 四部分都没有内容时状态条不渲染。审批、提问等卡片接管输入框时只保留「目标」。
- 点击展开 `ui/Popover`（宽度等于状态条，在上方），每部分一个分区，分区之间 0.5px `--hairline`：
  - 改动：一行总计和「审查」（链接色），点击后打开工作台「审查」并收起。
  - 待办：完整清单，已完成划线、进行中转圈。
  - 目标：阶段、目标（最多 3 行）、轮数与用时、阻塞或暂停说明；「暂停 / 恢复」「编辑」「清除」。编辑把 `/goal edit <目标>` 放进输入框并收起；清除先用 `confirm()`（危险色）确认。
  - 队列：每条一行；普通排队「插入当前执行 / 编辑 / 删除」，待发送（上一轮失败、上一轮已停止、应用重启前未发出）「发送 / 编辑 / 丢弃」，标签写「待发送 · 上一轮失败」等。编辑会收起面板，其他操作不收起。
- Esc 或点别处收起，焦点回到状态条。

## 个人档案访谈提示

个人档案访谈待开始时，第一个空会话的 Hero 在卡片下方显示一行「补充个人偏好 · 用一个简短访谈设置称呼、沟通方式和工作偏好」和「开始访谈」「不再提醒」。只出现一次：这个对话在本次运行中一直显示到你作答，别的对话和以后的启动都不再显示（`localStorage` 的 `emperor.profilePrompt.v1`）。访谈始终在「设置 › 记忆 › 用户档案」里。

## 反例

- 不要在控件行加第五个常驻控件；新入口放进 `+` 或对应的菜单。
- 不要在状态条上方再叠 dock 或胶囊；新的进度信息作为状态条的一部分加入 `statusBarModel.ts`。
- 不要把上下文用量、Plan 状态做成独立的小控件（旧版的上下文环和 Plan 胶囊已经删除）。
