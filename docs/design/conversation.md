对话面板里从上到下是一条会话流：你的消息、Agent 处理这一轮的过程、回答、本轮改动卡和轮末操作。默认只显示结论，过程收成一行，细节按需展开。

## 过程组

一轮里从提示之后到最终回答之前的步骤组成一个「过程组」，在虚拟列表里是一行：

- **成员**：思考、工具调用（含子智能体派出、工作流）、重试、切换备用模型、上下文压缩；打开 设置 › 常规 › 开发者 › 显示系统步骤 后还有上下文注入（ContextRow）与 Hook（HookRow）。没打开时这两种行在任何地方都不显示。
- **边界**：用户消息（包括运行中插入的消息）、目标变更、错误与输出上限等提示、本轮改动卡和轮末都不进过程组；它们把一轮的过程切成前后两组。
- **回答**：最后一次工具调用之后、带正文（文字、图片）的模型步骤是回答，排在过程组之后。回答的思考块留在过程组里，正文在组外。
- **没有工具调用的一轮**不建过程组，思考仍是单独一行可折叠的「思考」。例外是运行中：还没有回答的思考也显示为运行中的过程行。
- **步数**：展开后列表里的每一行算一步——一个思考块、一次工具调用（含准备中的调用）、一条系统或提示行。步骤之间的叙述文字不算步数。

| 状态   | 显示                                                                                                                                                                             |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 运行中 | 一行：转圈 + 当前步骤的动作与对象（中性 shimmer）+「· 第 N 步」，例如「正在读取 SettingsView.vue · 第 4 步」；运行超过 15 秒后加用时。没有步骤在执行时是「正在思考 · 第 N+1 步」 |
| 完成后 | 一行「已处理 N 步 · 用时 X ›」，13/20，`--text-3`，悬停 `--text-2`                                                                                                               |

- 运行中的过程行就是这一轮的状态行，下面不再另显示一行状态；只有还没有过程（等第一个 token）或回答正在输出时，才显示原来的状态行。
- 用时：一轮的第一组从这一轮开始算起，以后的组从第一步算起；一轮已经结束且这是最后一组时到这一轮结束为止（与轮末的「用时」一致），否则到下一行开始时为止。
- 点击过程行展开或收起步骤列表。展开状态存在会话视图的展开记录里，滚出虚拟列表再滚回来不会丢；点击时这一行留在屏幕上的原位（运行中的过程行除外，它继续跟随底部）。
- 「处理过程」设置（设置 › 常规 › 会话）：

| 选项               | 运行中                 | 完成后                                 |
| ------------------ | ---------------------- | -------------------------------------- |
| 完成后收起（默认） | 一行，可点开看实时列表 | 收起；运行中点开的列表在完成时一并收起 |
| 始终展开           | 展开                   | 展开                                   |
| 始终收起           | 一行                   | 收起；是否展开只由你决定，不随完成而变 |

- 跳到过程组里的某一步（时间轴、环境信息卡的计划行、来源的「定位出处」）会先展开这一组。

## 工具行

- 行高 28：图标 14（`--text-3`）、动作名 13（`--text-2`）、摘要 13（`--text-3`），中间用「·」分隔。思考、上下文、Hook 等行同样是这个规格（`DisclosureRow`）。
- 展开后的内容与思考的正文一样左缩进 22px；工具的输入输出块用 `IoBlock`（`--surface-raised`、`--r-md`、无边框，IN / OUT 两段，过长时「展开全部」）。
- **三个阶段**（准备中 → 运行中 → 结果）：模型还在写工具参数时，这一行已经出现，显示已经解析出的参数（文件名、命令、关键词）和「准备中」，不能展开；参数写完、调用开始后换成运行中的工具行。草稿只保留前 4096 个字符（`TOOL_DRAFT_LIMIT`），模型消息落地后丢弃。
- 参数在传输中被截断时，展开后提示「参数过长，已截断显示」；只有打开了 设置 › 常规 › 开发者 › 显示轨迹，才接着写「在轨迹中查看完整内容」。

## 轨迹门控

轨迹（会话头部的「对话 | 轨迹」页签、工具行的 Inspect、轨迹的「详情」列）是开发者视图，只有打开 设置 › 常规 › 开发者 › 显示轨迹 才出现（`useUiPreferences().showTrajectory`，默认关；`components/conversation/trajectoryGate.ts`）。

- **关闭时**：会话头部只有 46px 的一行（路径与两个开关），没有页签；工具行展开后没有 Inspect；对话不加载轨迹分包，会话 store 也不注册 trajectory target，对话这条路径没有额外开销。
- **轨迹链接**：关闭时打开 `/chat/:id/trajectory`（深链、⌘[ 回到旧的轨迹页）会转到 `/chat/:id`，去掉 `call`、保留其他参数；带 `call` 时滚到对应的工具行并展开（先展开它所在的过程组，较早的调用先加载更早的记录，最多 5 页），同时提示「轨迹视图已关闭」，操作「在设置中开启」打开 设置 › 常规。
- **运行时切换**：在轨迹页关掉开关，立即回到对话页（打开的设置弹窗保留），「详情」列收起，宽度留到下次打开。
- **释放**：离开轨迹视图 30 秒后，trajectory target 从会话 store 注销（`LAZY_TARGET_IDLE_MS`），之后的事件不再为轨迹装配；30 秒内回来则继续使用。

## 消息与正文

- **用户气泡**：`--bubble-user` 底色、`--r-xl` 圆角、内边距 10/16、正文 15/26、最宽为内容列的 80%、无边框；附件用 Tag 显示在气泡上方。
- **回答正文**：不套容器，15/26，段落之间 12px。Markdown 标题用 `--md-h1` / `--md-h2` / `--md-h3`（20 / 18 / 16，都小于页面标题）；表格 14/22。
- **链接与行内引用**：文字用 `--text-link`，前面是 12px 的来源图标：本地文件用文件类型图标，网页用站点图标（打开 设置 › 常规 › 显示网站图标 时取网站自己的图标，否则是首字母）。
- 过程组里的叙述文字是 `--text-2`，比回答低一级。

## 轮末

复制回答、时间与「用时 · 首字 · tok/s」、token 数合成一行操作，只在指针停在这一轮（提示、过程、回答任一处）或键盘焦点进入这一行时出现，平时不占视觉；这一行的高度始终保留，出现时下面的内容不动。用时写作「8 秒」「1 分 12 秒」「1 小时 2 分」。

## 动效

- 过程组、工具行、思考行的展开与收起用同一个过渡（`CollapseTransition`）：200ms（`--motion-base`、`--ease-standard`），高度与透明度一起变化。
- 减少动态效果时没有过渡，直接展开或收起。
- 这里是有意让高度参与动画：下面的行要跟着移动。其他地方仍按样式审计的约定只对 transform 与 opacity 做过渡。

## 实现要点

- `processModel.ts` 是纯函数：输入快照的节点顺序、节点和 Turn/Step 时间线，输出虚拟列表的行；行不变时保持同一个对象，整张表不变时返回上一次的数组，流式输出时只有被改动的那一行重新渲染。
- 过程组的 id 是 `process:<turn>:<序号>`；时间轴的「当前可见行」把它换算成组里的第一步。
- 准备中的调用从当前步骤的模型节点里读取（即使那个节点只有工具调用、本身不显示），排在已开始的调用之后。
